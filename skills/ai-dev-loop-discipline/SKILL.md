# AI 迭代纪律 skill：把「我觉得」换成「我查过」

> **一句话**：AI 写新代码时错在**设计偏好**（见 `finagent-lessons`）；
> AI 改已有系统时错在**取证方式** —— 它拿代码阅读推断当结论，
> 而产线状态只能靠产线数据回答。
>
> 本 skill 不讲"怎么写"，只讲**"改之前查什么、改完验什么、交付前扫什么"**。

---

## §0 · 先分清三个 skill 的分工（别用错）

| 场景 | 用哪个 skill | 核心问题 |
|---|---|---|
| 从零写 Agent / LLM 编排 | `finagent-lessons` | 我的**设计**有没有系统性偏好？ |
| 判某段计算/接口/表该不该留 | `pipeline-redundancy-audit` | 它**该不该存在**？ |
| **改一个正在跑的系统** | **本 skill** | 我**凭什么**说它是这样？改完**怎么知道**没坏？ |

⚠️ **本 skill 的第一条纪律就藏在上表里**：先分清"这是设计问题还是取证问题"。
本项目 2026-09-27 那一轮，8 个事故里**只有 1 个**是设计问题（样本最大值偏差），
其余 7 个都是取证/流程问题。

## §2 · G1 取证闸门 —— 结论必须有出处，且出处要分级

### 2.1 证据分级（**高 → 低**）

| 级别 | 证据 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| **E1** | 产线数据库查询结果（贴原始行） | 系统**现在**是什么状态 | — |
| **E2** | 真实 HTTP 响应体 / 端到端实测计时 | 用户**实际**收到什么 | 内部为什么这样 |
| **E3** | 运行日志 / 任务台账 / 物化表 | 过去发生过什么 | 现在是否仍然 |
| **E4** | 测试输出 | 这条路径**能**跑通 | 产线**是否**在用这条路径 |
| **E5** | 读代码推断 | 代码**长什么样** | 业务**实际**需要什么 |
| **E6** | 上一轮对话里的结论 / 记忆 | 我说过什么 | 现在是否还成立 |

**规则**：
- **E5 及以下不得单独支撑结论。** 写"算 554 个"之前，必须有 E1 或 E2。
- 报结论时**标注级别**：`（E1：见下方 SQL 结果）`。没有级别标注的结论视为猜测。
- **E6 必须重新取证**。长会话里最容易犯的错：拿三轮前的查询结果回答现在的问题。

### 2.2 用户是 E1 级证据源

用户说「拥挤度清单只有 262 个，为什么计算 554 个」，这不是**假设**，是**观测报告**。
正确处理：`相信观测 → 去查为什么两处不一致`。
错误处理：`解释为什么 554 是对的`（= 拿 E5 反驳 E1）。

### 2.3 🔴 强制切换规则：**同一话题被纠正 ≥ 2 次**

```
第 1 次被纠正 → 重新取证，正常回答
第 2 次被纠正 → 停止输出结论，改为**只输出原始证据**：
                贴 SQL + 贴结果 + 贴响应体，让用户自己判读
第 3 次被纠正 → 说明取证方式本身错了，不是判断错了：
                换证据源（换表 / 换接口 / 直接问用户从哪看到的）
```

📌 本项目实例：262 ↔ 554 在四轮里翻了 **4 次**（262→554→262→554→262）。
每一次翻转都是"我找到了新证据"，但**每一次都还是 E5**。
真正定案靠 `source` 字段的分布查询（E1）：

```
visible=1 的 554 个拆开：
    source='default' + 概念    257   ← 系统种子
    source='manual'  + 非概念  292   ← 【用户手动加的】
    source='manual'  + 概念      5
```

> **教训**：`source` 这类**来源字段**才是"用户意图"的证据；
> 勾选框默认值、配置项默认值、代码注释都是 E5，反映的是**视图默认**不是**用户意图**。

## §3 · G2 口径闸门 —— 一个数字只能有一个权威来源

### 3.1 SSOT（单一事实来源）规则

任何"几个"的问题（几个板块 / 几个池 / 几个接口 / 几行数据），**必须有唯一权威产出口**。

| 做法 | 判定 |
|---|---|
| 复用权威清单，脚本**只做减法** | ✅ |
| 脚本**重新推导**一遍上游规则 | ❌ **禁止** |

**实例（本项目三次计数错误）**：

| 我算出的 | 权威值 | 错在哪 |
|---|---|---|
| 123 | 122 | 冻结脚本**重新推导**了胜率门槛，漏掉「已走满窗口 ≥ 3」条件 → 多剔 7 个 |
| 110 | 122 | 脚本只统计**有告警**的板块（118），漏掉 12 个"无告警但门槛保留"的 |
| 122 | 122 | ✅ 复用官方 16 条剔除清单，**双向差集验证 0/0** |

**规则**：
- 从上游清单**读**，不要从上游**规则**再算一遍。
- 产出后**双向差集**：`应有 − 实有 == 0` **且** `实有 − 应有 == 0`。单向差集等于没验。
- 两个数字不一致时，**先问"这两个数字分别是谁算的、从哪读的"**，再问"哪个对"。

### 3.2 静默失败三连（加黑名单必须同时设计白名单）

**任何"排除/隐藏/剔除"机制上线时，必须同时交付三件套**：

1. **撤销通路** —— 「恢复/新增」接口必须能撤掉排除标记
2. **立即补算** —— 恢复后立刻算该对象的数据，否则用户看到的是 `—`
3. **顺序正确** —— **先补算，再读列表**（反了就是"数据还没算完，列表已经返回"）

**本项目反例**（修复前）：

```python
# POST /config_list 与 /restore 只写 visible=1，不碰剔除清单
→ 接口回 {"restored": 1}
→ 板块不出现（还在剔除清单里）
→ **不抛任何异常，不报任何错**
```

📌 **静默失败比报错危险 10 倍**：报错你会去修，静默失败你会以为已经修好了。
**自检问法**：「如果这个操作完全没生效，我能从返回值里看出来吗？」答不出 → 加显式校验。

## §4 · G3 半径闸门 —— 改之前先算爆炸半径

### 4.1 强制动作：改配置/改范围前，列出**全部消费者**

```bash
# 1. 谁读这个函数 / 这个清单？
grep -rn "load_crowding_exclusions\|list_visible_codes\|load_frozen_pool" --include="*.py" src/ scripts/

# 2. 谁读这张表？（含外部消费者）
grep -rn "sector_crowding_daily" --include="*.py" src/ scripts/ tests/

# 3. 前端谁在调这个接口？
grep -rn "config_list\|crowding" web/src/
```

**实例**：收窄拥挤度范围时，只查了"前端看板"，
没查 `mainline/datastore.py` 也在读剔除清单 → **主线池被顺带砍掉 6 个合法板块**。

```
拥挤度剔除清单（2255 条）
   ├─→ sector_crowding/refresh.py     ✅ 预期消费者
   ├─→ sector_crowding/metrics.py     ✅ 预期消费者
   └─→ mainline/datastore.py          ❌ 隐式消费者（未预期）
```

**规则**：
- **隐式耦合** = 两个子系统共享一份**有语义的清单**（黑名单、白名单、剔除表）。
- 收窄共享清单前，必须做 §4.1 的三条 grep，并把消费者**逐条写进改动说明**。
- 若消费者不该被影响 → **解耦**，不要"调参数让它刚好不影响"。

### 4.2 解耦的正确形状：**快照 > 动态规则**

当需求是「从此固定下来，不要再变」时：

| 做法 | 结果 |
|---|---|
| 写一条**动态规则**（如"胜率 ≤ 40% 就排除"） | ❌ 新板块也会被这条规则排除 |
| 生成一份**冻结快照**（`mainline_frozen_pool.yaml`，122 条） | ✅ 新板块仍能加入，老名单不再抖动 |

本项目交付形状：
- `configs/mainline_frozen_pool.yaml` —— **122** 条（`base_pool: 138` − `gated_out: 16`）
- `load_frozen_pool()` 返回 `set | None`；**`None` = 无快照 = 退回旧行为**（可回退）
- 快照存在时跳过动态排除，但**仍然尊重 `sector_blacklist`**（安全类排除不因快照失效）

> **口诀**：要"停止变化"用**快照**，要"持续生效"用**规则**。混用必错。

### 4.3 废弃函数的墓碑模式

判某个方法死刑时，**不要直接删除**：

```python
def peer_max_median(conn, config):
    raise RuntimeError(
        "peer_max_median 已废弃：向同类中位数收缩在截断回测里一致变差"
    )
```

删除 → 旧调用点变 `ImportError`/`AttributeError`（还能发现）；
但如果有人**复制了旧逻辑**，删除救不了。**保留一个 raise 的墓碑**，
让任何残留调用**立刻炸**，而不是静默算出一个错数。

## §5 · G4 完成闸门 —— tests green ≠ done

### 5.1 「完成」的四级定义

| 级别 | 标准 | 足够吗 |
|---|---|---|
| L1 | 代码改完，能 import | ❌ |
| L2 | 单元测试全绿 | ❌ **本次 93 个测试全绿时，一键刷新路径是坏的** |
| L3 | **静态检查 + 真实路径 smoke** | ✅ 最低交付线 |
| L4 | 端到端实测，贴出计时/输出 | ✅✅ 修复类改动应到此 |

### 5.2 L3 的两个必做动作（缺一不可）

**① 静态检查 —— 专抓"编辑事故"**

```bash
ruff check --select F821,F811 src/ scripts/     # 未定义名 / 重复定义
python -m compileall -q src/                     # 语法
```

为什么必须有：本次我在一次 `edit` 里删代码块时，
把相邻的 `workers = max(1, min(int(config.performance.worker_threads), 16))`
一起删掉了 → 运行时报 `NameError: name 'workers' is not defined`，
**而 93 个测试全绿**（因为没有任何测试跑到那条分支）。

> **规则**：`F821` 是免费的事故探测器。任何 Python 改动后必跑。
> 并且**为"刚炸过的那条路径"补一个守护测试**（本次补了 `test_refresh_no_undefined_names`）。

**② 真实路径 smoke —— 专抓"出口异常"**

单元测试测的是**函数**，生产炸的是**渲染/序列化/传输**。本次实例：

```python
# Starlette 的 JSONResponse.render() 用 allow_nan=False
# → 响应体里只要有一个 NaN/Inf，就在**渲染期**抛异常
# → 这个阶段**在路由的 try/except 之外**
# → 用户看到：SYS_5000「服务器开了点小差」，日志里没有任何业务堆栈
```

修复形状（`src/api/main.py`）：

```python
class _SafeJSONResponse(JSONResponse):
    @staticmethod
    def _clean(value):
        if isinstance(value, Real) and not isinstance(value, Integral):
            f = float(value)
            if math.isnan(f) or math.isinf(f):
                return None          # → 出口统一转 null
        ...
    # 全局兜底：
    app = FastAPI(default_response_class=_SafeJSONResponse)
```

⚠️ **两个细节值得抄**：
1. 用 `numbers.Real` 而不是 `isinstance(value, float)` —— 否则 `np.float32` 漏网。
2. **测试必须"钉住"这个护栏**（本次 6 个测试里有一个专门断言
   "Starlette 默认实现确实会拒绝 NaN"）—— 否则将来换框架这层护栏会**静默失效**。

### 5.3 归因纪律：先排除环境，再怀疑代码

「8 个板块刷新失败」的排查顺序：

| 顺序 | 假设 | 证据 | 结论 |
|---|---|---|---|
| 1 | 代码 bug | 8 个全失败？不是，1845 个里 8 个 | ❌ 不是普遍性代码问题 |
| 2 | 数据问题 | 8 个 code 全是 `8612xx.TI` | ⚠️ 可疑，同一命名段 |
| 3 | **数据源限流** | 失败时间戳全在 `18:50:37`（同一秒） | ✅ **真因**：Tushare `ths_daily` 500 次/分钟 |

**规则**：
- 失败**时间戳是否聚集**、**代码是否有共同前缀**、**失败率是否 ≈ 1/N** ——
  这三条能在 30 秒内区分"代码 bug"与"外部限流"。
- **限流的正确修法是退避/串行/降并发**，不是 `try/except` 吞掉。

### 5.4 降噪必须配留痕（**不要只把失败藏起来**）

用户口径：「前端不要显示失败信息 —— 失败板块对用户没有可操作性，
显示出来只是噪音，而且大多可自愈。」

但**降噪不能等于丢失**。交付形状必须是**「前端静音 + 后端留台账」**：

```python
# refresh.py
_FULL_WEEK_KEY   = "full_refresh_week"      # 本周是否已全量刷过
_FULL_FAILED_KEY = "full_refresh_failed"    # 本周失败名单（逗号分隔）

# 效果：同周再点"一键刷新" → 只补上次失败的板块，不再全量重跑
```

| 层 | 行为 |
|---|---|
| 前端 | 不显示失败数（纯噪音） |
| 日志 | `logs/sector_crowding.log` 记明细 |
| 数据库 | 失败名单进台账 → **下一轮自动补齐** |
| 任务对象 | `task.failed_sectors` 仍保留（程序可读，人不看） |

> **铁律**：删掉的是**呈现**，不是**记录**。任何"不显示了"的改动，
> 必须同时指出"记录还在哪"。

## §6 · G5 交付闸门 —— commit / push 前必扫

### 6.1 提交前扫描（**必做，不是可选**）

```bash
git status --short                                   # 看全部将提交文件
git diff --cached --stat                             # 看规模是否符合预期
```

**三条检查**：

| 检查 | 命令 / 做法 | 本次实例 |
|---|---|---|
| **个人信息** | 扫 `docs/_*` `scripts/_*` 等**草稿目录** | 31 个未跟踪文件里有手机号、邮箱、薪酬期望 |
| **临时产物** | 排除 `*_backup-*`、`dist-*`、`_tmp*` | `web/dist-pilot-backup-*` |
| **无关改动** | 逐条确认每个文件都属于本次改动 | 避免把别人的工作区扫进来 |

**排除写法**（pathspec）：

```bash
git add -A -- . ':(exclude)docs/_*' ':(exclude)scripts/_*' ':(exclude)web/dist-pilot-backup-*'
```

> **规则**：**以 `_` 开头的目录默认视为草稿**，永不入库。
> 这是最低成本的个人信息防线 —— 草稿文件天然带真实数据（手机号、邮箱、简历原文）。

### 6.2 push 前必须摸清远端性质（**本次踩到的坑**）

```bash
git rev-list --left-right --count origin/main...HEAD
# 本次输出：8   28
#   → origin/main 有 8 个提交不在本地
#   → 本地有 28 个提交不在 origin/main
#   → **双向分叉**，不是"我落后 8 个"
```

`git push` 被拒（`! [rejected] fetch first`）后**正确的下一步是调查，不是合并**：

| 动作 | 判定 |
|---|---|
| `git log --oneline origin/main \| head` 看远端提交长什么样 | ✅ **必做** |
| 发现远端是**独立的、净化过的公共发布历史** | → 停止 |
| `git merge origin/main` | ❌ 会把内部草稿与发布历史搅在一起 |
| `git rebase origin/main` | ❌ 28 个提交全部重写，且公开未净化内容 |
| `git push --force` | ❌❌ **绝不**对独立历史的公共远端使用 |

**规则**：
- **双向分叉 ≠ 需要同步**。分叉可能意味着"两条线本来就该分开"。
- **force-push 永远不会是第一步**。它是"已经确认远端历史该被覆盖"之后的最后手段，
  且必须由人明确授权。
- 拿不准时，**停下来把分叉状态贴给用户**，让他选（本次给了 A/B/C 三个选项）。

## §7 · 本轮 8 个事故的完整复盘（**错法比正解更有信息量**）

### 事故 1 · 口径漂移：262 ↔ 554 翻了 4 次
- **错**：每次都用 E5（读配置/读代码/读勾选框默认值）得出新结论
- **对**：查 `source` 字段分布（E1），发现"默认渲染集合"≠"用户配置集合"
- **规则**：**§2.3 强制切换** —— 第 2 次被纠正就只贴证据

### 事故 2 · 半径溢出：收拥挤度范围，砍了主线池 6 个板块
- **错**：只查了前端消费者
- **对**：先 grep 全部消费者 → 发现 `mainline/datastore.py` 隐式读剔除清单 → 解耦
- **规则**：**§4.1** —— 共享清单必查全部消费者

### 事故 3 · 编辑事故：`NameError: workers`，93 测试全绿
- **错**：一次 `edit` 删代码块时连带删掉相邻定义；测试没覆盖该分支
- **对**：`ruff --select F821` + 为炸过的路径补守护测试
- **规则**：**§5.2①** —— 静态检查是免费的事故探测器

### 事故 4 · 静默失败：`{"restored":1}` 但板块不出现
- **错**：加黑名单没设计撤销通路
- **对**：恢复接口调 `remove_crowding_exclusions()` + **先补算再读列表**
- **规则**：**§3.2** —— 排除机制必须三件套；静默失败比报错危险 10 倍

### 事故 5 · 出口异常：NaN 炸在渲染期，不在 try 里
- **错**：以为 `try/except` 能兜住；5xx 被错误码表折叠成 `SYS_5000`
- **对**：`_SafeJSONResponse` 全局兜底 + 用 `numbers.Real` 抓 `np.float32`
- **规则**：**§5.2②** —— 单元测试测函数，生产炸在序列化；护栏要写测试钉住

### 事故 6 · 归因错误：8 个失败 → 真因是限流
- **错**：先怀疑代码
- **对**：时间戳聚集 + 代码同前缀 → 30 秒定位到 `ths_daily` 500/min
- **规则**：**§5.3** —— 先排除环境，再怀疑代码；限流用退避，不用 `try/except`

### 事故 7 · 方法选择错误：更"高级"的收缩估计被回测证伪
- **背景**：水位 = `当前拥挤度 / 近 6 年最大值`，分母是**样本最大值**，
  `E[M_n]` 随 n 单调上升 → 历史短的板块水位**系统性虚高**
- **错**：选了听起来更高级的 James-Stein 收缩 `denom = exp(w·ln(M_own)+(1-w)·ln(M_peer))`
- **证伪**：`M_peer` 是横截面中位数，向它收缩会把**高于中位**的板块分母**调小**，水位反而更高：

| k | 偏差 |
|---:|---:|
| 0 | +0.047 |
| 250 | **+0.099**（越收越偏） |

- **对**：尺度校正 `denom = M_n · r(n)`，`r(T) = median(M_full / M_T)` 由**截断回测**标定：

| T | `r(T)` | 朴素偏差 | 校正后 | MAE 改善 |
|---:|---:|---:|---:|---:|
| 60 | 2.6207 | +0.3502 | **−0.0612** | **54.3%** |
| 250 | 1.7021 | +0.1801 | −0.0241 | 27.0% |
| 750 | 1.0000 | +0.0470 | +0.0470 | 0% |

- **规则**：**§8 铁律 11** —— **先做截断回测，再选方法**。
  "听起来更高级"的方法在数据面前可能是错的；`r(T≥750)=1` 是**实测结论**不是设的。

### 事故 8 · 交付失守：push 被拒 + 个人信息待提交
- **错**：直接 `git push`
- **对**：先 `rev-list --left-right --count` 看分叉 → 8/28 双向分叉 → 停止并交给用户
- **规则**：**§6** —— 双向分叉 ≠ 需要同步；force-push 不是第一步

## §8 · 铁律 15 条

1. **E5 及以下的证据不得单独支撑结论。** 读代码不算取证。
2. **同一话题被纠正 ≥ 2 次，立刻切换成"只贴原始证据"模式**（§2.3）。
3. **用户报的是观测，不是假设。** 不要拿推断去反驳观测。
4. **一个数字只能有一个权威来源。** 复用清单，禁止重新推导规则（§3.1）。
5. **差集必须双向为 0。** 单向差集等于没验。
6. **加排除必须同时设计撤销通路 + 立即补算 + 先算后读**（§3.2）。
7. **静默失败比报错危险 10 倍。** 问自己："完全没生效时，返回值能看出来吗？"
8. **改共享清单前必列全部消费者。** 隐式耦合靠 grep 发现，不靠记忆（§4.1）。
9. **要"停止变化"用快照，要"持续生效"用规则。** 混用必错（§4.2）。
10. **废弃函数留 raise 墓碑，不要直接删。** 让残留调用立刻炸（§4.3）。
11. **先做截断回测，再选方法。** 高级方法可能方向就是反的（事故 7）。
12. **tests green ≠ done。** 最低交付线 = `ruff F821` + 真实路径 smoke（§5.1）。
13. **删掉的是呈现，不是记录。** 任何"不显示了"必须指出记录还在哪（§5.4）。
14. **`_` 开头的目录永不入库。** 草稿天然带个人信息（§6.1）。
15. **双向分叉 ≠ 需要同步；force-push 不是第一步。** 拿不准就停下来交给用户（§6.2）。

## §11 · 本项目的高频陷阱速查

| 陷阱 | 症状 | 规避 |
|---|---|---|
| `load_config()` `@lru_cache(maxsize=1)` 单例 | 测试间配置互相污染 | 测试里改配置后**必须** `load_config.cache_clear()`（放 `finally`） |
| 5xx 一律折叠成 `SYS_5000` | 根因被吞，只看到"服务器开小差" | 网关层记原始异常 + `trace_id`；`>=500` 之前先看是不是渲染期异常 |
| 读路径触发昂贵生成 | `_latest_report()` 无报告时**同步生成** → 首个请求卡 2m22s | 读路径禁止触发生成；改启动预热或非阻塞生成 |
| 前端 `Promise.all` 连坐 | 慢接口（20s 目录扫描）把快接口拖成 `(0个)` | 面板内多请求**解耦**，各挂各的 `.then`；**loading ≠ empty** |
| 后台进程 stdout 不落文件 | 重启后的日志读不到 → 无法取证 | 启动脚本必须把 stdout/stderr 重定向到 `data/run/*.log` |
| 数据源限流 | 同一秒集中失败 + 代码同前缀 | 退避 + 降并发；失败名单进台账下轮补 |
| 分母是样本最大值 | 短历史样本**系统性虚高** | 尺度校正曲线 `r(n)`，由截断回测标定 |

## §12 · 一句话总结

> **AI 改已有系统时最大的错，不是写错代码，而是"我以为我知道系统现在是什么样"。**
>
> 三句话：
> 1. **结论前先问：这是 E1 还是 E5？** —— 是 E5 就闭嘴去查。
> 2. **改之前先问：这个改动还会打到谁？** —— grep 出来的才算数。
> 3. **改完先问：我怎么知道它真的生效了？** —— 打真实路径，不是跑测试。

## §13 · AI 自己引入的 4 类缺陷（**不记录，下次还会犯**）

> §7 记的是"我没查清"；本节记的是"**我亲手弄坏的**"。
> 这一类最该被写下来，因为它**不依赖知识，只依赖纪律**。

### 13.1 编辑事故：删代码块时连带删掉相邻定义

```python
workers = max(1, min(int(config.performance.worker_threads), 16))   # ← 被连带删掉
```

**为什么没被测出来**：**93 个单元测试全绿**。测试测的是纯函数，
而炸的是"一键刷新的并发编排"那段分支 —— **没有任何测试走到那里**。

**护栏（两条，缺一不可）**：

```bash
ruff check --select F821,F811 src/ scripts/   # 未定义名 / 重复定义，毫秒级
```
- **② 为"刚炸过的那条路径"补守护测试** —— 不是补覆盖率，是补**这一条**。

> **推论**：只要改动涉及"删一段代码"，就该假设**相邻定义可能被一起带走**。
> 结构性文件（注册表、字典、配置段）改完必须跑一条**形状自检**
> （如"注册表的 key 必须等于条目的 name"）。

### 13.2 交互理解错误

**(a) 一句话需求里，可观察行为往往由多处共同决定**

> 用户：「事件告警的信息最多保留三天，超过3天的信息自动溢出删除。」

我直接改了一个字段就说"已完成"。但控制生命周期的有**两个**：
`alert_expire_days`（读路径置 expired，**只是不显示，行还在**）
与 `retention_alert_days`（真正 `DELETE`）。用户说的"**自动溢出删除**"对应第二个。

**两个人都对，但白跑一轮** —— 他说"没生效"，我说"我改了啊"。

**纪律**：需求里有"用户可观察的行为"时，**先列出"要改哪几处才能产生这个行为"**。
超过一处就必须在交付说明里**点名每一处**，或先一句话确认。

**(b) 用户给的是症状，不是病灶**

用户说「行业轮动日报 卡了好久」—— 这是**观测**。真因是
`_latest_report()` 在读路径上**同步生成**整份报告（实测 2m22s）。
回答时要**先答他的问题、再给真病灶、并给出证据（哪个文件、什么数字）**；
不要为了顺着用户而假装他的猜测成立。

**(c) 用户报的是观测（E1），不要拿推断（E5）去反驳**

见 §2.3。这在本轮真实发生了 4 次。

**(d) 上下文继承错误：把"上一轮的结论"当"现在的状态"**

见 §2.1 的 E6。长会话里最容易犯。

### 13.3 把并发协作者的未验证改动当成自己的

**经过**：某测试失败，我去私有树看，发现**文件已经有修复了**（mtime 很新），
于是直接把它复制进发布快照。

**但**：那个文件的工作树版本比私有 `HEAD` **多 112 行** ——
那是**另一个会话正在写的、未提交、未验证的**内容。

**一句话识破**：两个 diff 数字对不上

```bash
git diff --stat origin/main -- <file>       # 108 行   ← 与公开线比
git diff --stat origin/main HEAD -- <file>  #   6 行   ← 与私有 HEAD 比
# 差得多 → 工作树里有【没进 HEAD 的大改动】 → 停下来查是谁的
```

**纪律**：
- 动手前看**文件 mtime**；近期被改过的文件先确认归属
- 新增逻辑优先放进**自己新建的文件**，减少冲突面
- **快照类操作必须从"冻结的修订"取内容，不能从"活动的工作树"取**（§15.4）

### 13.4 检查脚本报错时，**先怀疑检查脚本**

本轮的核对脚本第一次跑出来 `VERDICT: MISMATCH` —— 101 个文件"staged 但不在预期里"。
那 101 个其实是**删除**：我的"预期集合"只算了 `changed`，**没算 `deleted`**。

同一轮里，自写过滤器还因为一个 CR 字符，报出"**174 个文件全部会发布，0 个被忽略**"。

> **两次都表现为"发现了问题"，两次都是假警报。**
> 而更危险的是反向：同一个 bug 在另一个方向上会给出"**一切正常**"。
> 所以：**检查脚本必须先喂"已知答案"的输入自证**（§14.2）。

## §14 · 工具自证：把判定权从"我看"变成"脚本断言"

> 本轮所有"看起来正常"的错误结论，都来自**我肉眼读了一个坏掉的脚本的输出**。

### 14.1 自写过滤器连错 3 次，**三次都让结论偏松**

| # | 编码错误 | 后果 | 危险方向 |
|---|---|---|---|
| 1 | `subprocess(text=True)` 在 Windows 上把写入 stdin 的 `\n` 变成 `\r\n` | 每条路径带尾部 CR → 什么都匹配不上 → 报"**没有任何文件被忽略**" | **偏松 = 会泄漏** |
| 2 | 不加 `-z` 时 `git check-ignore` 按 `core.quotePath` **给非 ASCII 路径加引号** | 中文名文件永远匹配不上自己的输入键 | **偏松** |
| 3 | `-v -z` 每条记录是**四个** NUL 字段（`source\0lineno\0pattern\0pathname\0`），我按两个配对 | 元数据与路径全部错位 | **偏松** |

**规则**：
- 外部工具的调用**一律用 bytes**，不要 `text=True`
- 只用**不带 `-v` 的 `-z`**（它返回的就是忽略集合本身，不需要解析元数据）
- **任何判定"安全/干净"的脚本，都必须假设它默认会给出假绿灯**

### 14.2 固定 sanity + 算术自洽断言（**可复制的模板**）

```python
# 每条都【人工核对过期望值】——不是从脚本输出抄的
SANITY = [
    ("scripts/prune_crowding.py", True),          # 非白名单脚本 → 不发布
    ("scripts/seed_demo_data.py", False),         # '!' 白名单 → 发布
    ("tests/unit/test_ps1_encoding.py", True),    # 硬断言 *.ps1 非空
    (".trae/skills/ai-dev-rules/SKILL.md", True),
    ("docs/OPS_GUIDE.md", True),
    ("web/dist-pilot/index.html", True),
    ("README.md", False),
]

bad = [(p, want) for p, want in SANITY if (p in result) != want]
assert not bad, f"过滤器行为与预期不符，先查清再继续：{bad}"
assert len(publish) + len(ignored & set(candidates)) == len(candidates)   # 算术自洽
```

**算式自洽是最便宜的探测器**：只要 `发布 + 忽略 ≠ 候选总数`，
就一定有一处在骗你。本轮它抓到了两次。

### 14.3 做对照：**在纯净基线上跑同一批检查**

本轮的用法：

```bash
git worktree add --detach /tmp/baseline origin/main
# 在基线跑同一条命令
cd /tmp/baseline && pytest <失败的 7 条> -q
# 结果：1 failed, 4 passed, 2 skipped
```

| 基线结果 | 结论 |
|---|---|
| 基线**也失败** | **环境问题**，不是本次引入（本轮那个 bcrypt/pbkdf2 就是这一类） |
| 基线**通过** | **本次引入的回归**，必须修 |

这一步把"7 个失败"精确切成"**1 个环境 + 6 个我引入的**"，
避免了两种浪费：去修不是自己弄坏的东西，或把回归当成环境问题放过。

### 14.4 交付前必跑的两条"半自动门槛"

```bash
ruff check src tests scripts          # 静态：抓编辑事故
python scripts/verify_cleanup.py      # 项目自己的合规/卫生门禁
```
并且**在纯净基线上也跑一遍** —— 否则你分不清"我弄红的"和"本来就是红的"。

## §15 · 双侧仓库的同步纪律（公开仓 / 私有仓）

> 只要一个项目存在"**私有线**（本地私有历史）"与"**公开线**（对外仓）"两条线，
> 就会出现本节这 4 类问题，而且**全都不报错**。

### 15.1 先把文件分成**三类**（不是两类）

| 类别 | 判定 | 处理 |
|---|---|---|
| **OVERLAY** | 私有工作树有、公开过滤器放行 | 复制覆盖 |
| **PUBLIC-OWNED** | **公开线已发布，但私有 `.gitignore` 把它藏了**，磁盘上还在 | ⚠️ **既不覆盖也不删除** |
| **DELETE** | 公开线有、上面两类都没有 | 从公开树移除 |

**第三类是本轮最贵的发现**。我的候选集用了
`git ls-files --cached --others --exclude-standard` ——
它**受私有 `.gitignore` 影响**，于是"私有藏起来、公开要发布"的文件**根本不进候选集**，
在差集里就表现为"**公开有、私有没有**"，被判成该删的。

**实际后果**：差点删掉 6 个文件共 **3.4 万行** ——
脱敏 stub 路由（`auction_select.py` / `quant_select.py`）、
四个前端面板（`AuctionSelectPanel.tsx` 1548 行、`NiuLineChart.tsx` 983 行、
`QuantSelectPanel.tsx` 940 行、`auctionApi.ts` 493 行）、`qmt/` 的契约文档。

> **怎么发现的**：我生成了"复核包"（逐文件增删 + 变更最大的 30 个文件），
> 在里面看到 `+0/-1548 web/src/components/AuctionSelectPanel.tsx`。
> **交付前生成一份"人可读的差集摘要"，比任何自动断言都更能抓到这一类。**

**PUBLIC-OWNED 的校验方式**（防"没删掉但被私有实现覆盖"这个反向泄漏）：

```bash
test "$(git hash-object <file>)" = "$(git rev-parse origin/main:<file>)"   # 必须完全相等
```

### 15.2 脱敏必须在**上游**做，不能在下游做

**本轮的铁证**：

```
公开线 origin/main： alert_email_to = "your_qq_number@qq.com"   ✅ 已脱敏
私有树（快照源）  ： alert_email_to = "2693888583@qq.com"        ❌ 真邮箱
而且：字符串 "your_qq_number" 在私有树里【一次都不存在】
```

上一版的提交正文写着"PII 清洗"，但**只改在了公开线** →
**下一次快照必然把它覆盖回来** —— 这不是意外，是必然而已。

**规则**：**在快照的上游修**（回写私有树），并 `grep` 归零。
下游做的每一次，都会被下一次同步抹掉。

### 15.3 不要用 `git checkout <私有分支> -- .`（**会绕过 .gitignore**）

`checkout` 会把文件**写进索引**，对**已跟踪**文件**绕过 `.gitignore`** ——
私有资产就是这么漏出去的（历史提交正文原话：
「**撤出 checkout 越过 .gitignore 带入的私有资产**」）。

**正确形状**：先算白名单 → **按名单复制成普通文件** → 再让 `git add -A` 走公开过滤器。

并且：**`.gitignore` 本身绝不参与叠加**（私有版会删掉全部过滤规则，
一旦覆盖，`git add -A` 会放进 **571 个私有文件**）。

### 15.4 快照是**移动靶**：从冻结修订取内容

本轮实测：干活期间**另一个会话提交了 3 个 commit**，
并且工作树里还有 **70 个已跟踪改动待提交**。我构建的快照因此落后
**5 个会发布的前端文件**，还曾把一个并发会话**未提交的 112 行**改动复制了进去（§13.3）。

**规则**：
- 快照必须**从冻结的修订**（一个 commit）取内容，不能从活动工作树取
- 或者：先让私有线静默 → 再快照 → 再发布
- 复制任何文件前看 **mtime**；mtime 很近的文件停下来查归属

### 15.5 交付前的四道核对

| # | 核对 | 本轮做法 |
|---|---|---|
| 1 | **算白名单**（三类模型） | 816 OVERLAY / 9 PUBLIC-OWNED / 93 DELETE |
| 2 | **敏感信息扫描** | 0 邮箱 / 0 手机号 / 0 Token / 0 私钥（其余命中逐条确认为假阳性） |
| 3 | **双向差集** | `该变的都进索引了` **且** `索引里没有不该有的`，两侧都要 0 |
| 4 | **在纯净基线上跑同一批测试** | 把"7 个失败"切成"1 环境 + 6 我引入的" |

> ⚠️ 第 3 条**必须双向**。单向差集等于没验 —— 本轮我自己在 §13.4 上就踩了。
