# 数据源配置

> 供 multi-source-event-collection 技能引用，定义采集源、频率、标准化字段与抓取约束。

## 数据源配置表

| 类别 | 来源 | 采集频率 | 采集方式 |
|------|------|----------|----------|
| 政策网站 | 国务院、发改委、工信部、地方政府官网 | 每小时 | 网页抓取 |
| 新闻API | 东方财富、新浪财经、财联社 | 每5分钟 | API/网页 |
| 投资日历 | 东方财富投资日历、同花顺投资日历 | 每日08:00 | API/网页 |
| 公告 | 巨潮资讯网、交易所官网 | 每10分钟 | API/网页 |

## 事件标准化字段要求

| 字段 | 必填 | 说明 |
|------|------|------|
| title | 是 | 事件标题，保留原文 |
| content | 是 | 正文内容，保留原文 |
| source_name | 是 | 来源名称（如"国务院"、"巨潮资讯网"） |
| source_url | 是 | 原文链接，用于数据溯源 |
| publish_time | 是 | 发布时间，ISO8601带时区（+08:00） |

## 礼貌抓取约束

- 限频：遵守各站点频率上限，同一站点请求间隔不小于1秒，避开对方业务高峰时段
- 超时：单请求超时上限10秒，连续失败3次进入指数退避等待
- 失败降级：单源失败仅记录告警并跳过本轮，不得阻断其他数据源的正常采集
- UA与协议：使用可识别User-Agent，尊重robots协议；重复抓取优先使用缓存

## 幂等要求

- 每轮采集结果先经 event-deduplication 技能去重，再写入events表
- 同一事件重放采集不得产生重复记录（指纹=规范化标题+发布日期+来源）
- 每批采集须携带message_id与批次号，支撑失败重放与审计追溯
