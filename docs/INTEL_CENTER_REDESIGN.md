## 0. 合规基线：平台只做三件事

> **背景**：开发者是个人，**没有证券投资咨询业务资格**。
> 因此平台能力必须收敛到"信息与工具"，而不是"意见"。

### 0.1 为什么不能靠"换个说法"

证监会公告〔2012〕40号《关于加强对利用"荐股软件"从事证券投资咨询业务监管的暂行规定》
对"荐股软件"的认定是**按功能**，不是按措辞：

| 认定要素 | 说明 |
|---|---|
| ① 提供具体证券的投资分析意见 | 按**功能**认定 |
| ② 推荐具体证券 | 同上 |
| ③ 提供买卖时机建议 | 同上 |
| ④ **以不同措辞表达上述内容** | **明确禁止变相表达** |

并且"以直接或间接经济利益销售或提供"即构成从事证券投资咨询业务，需持牌。
（[国务院公报原文](https://www.gov.cn/gongbao/content/2013/content_2371606.htm)）

> ⚠️ **结论：「换种说法绕开买卖建议」是法律上最危险的做法** ——
> 因为条文本身就禁止"以不同措辞表达"，
> 把"建议买入"改写成"值得留意"，等于**自证主观规避意图**，
> 功能上仍是买卖建议，但主观上多了"明知故犯"。

### 0.2 正确做法：换**交付物**，不是换措辞

| ❌ 原表述（越线） | ✅ 替代交付物（合规） | 为什么 |
|---|---|---|
| 「**今日关注清单**：半导体设备 多」 | 「该板块今日被提及 **27 篇**，20 日均值 **9 篇**（环比 +200%），可信度 90.2」 | 换成**可验证计数**；是否关注由使用者判断 |
| 「半导体设备：**维持看多**」 | 「新增可归因信息 **3 条**（费半 +2.1% / 公告 ×1 / 研报 ×2）」 | 只陈述"新增了什么"，不陈述"该怎么做" |
| 「煤炭转空，**需关注持仓敞口**」 | 「25 篇提及（其中 19 篇原文语气偏空）+ ETF 份额 5 日 **−12.4%**，两组数据同向」 | 陈述统计事实，不给操作暗示 |
| 「AI 算力…**提示追高风险**」 | 「提及方向偏多，同时拥挤度指标处于 **87 分位**；两指标取值不一致，故不计入共振」 | 把"风险判断"还原为"两个指标取值" |
| 「**风险告警 / 机会告警**」 | 「**信息事件** / **指标不一致** / **低可信**」 | 告警名字本身就在下判断 |
| 弹窗按钮「查看**详情**」 | 「查看**来源**」 | 能给的只有来源 |

**核心洞察**：换成数据后，**信息量不减反增** ——
"提及 27 篇 / 均值 9 篇"比"值得关注"信息更多，因为**阈值由使用者自己定**。
这不是妥协，是把主观判断交还给有判断权的人。

### 0.3 四条硬约束（不可用开关关闭）

| # | 约束 | 落地位置 |
|---|---|---|
| 1 | 全部指标为**描述性统计**（多少条、比平时多多少），不做**预测性**表述（会不会涨） | 计算层：只产出计数/分位/环比 |
| 2 | 契约中**不存在** `target_price` / `rating` / `buy_sell` 字段 | 数据结构层面堵死 |
| 3 | 所有第三方倾向一律标注为**「原文倾向」**，不是平台判断 | UI 标签固定为"原文倾向" |
| 4 | 公式与参数**公开可复算**（公式版本号 + 参数文件名进审计链） | 见 §4.5 |

效果图渲染脚本里内置**违禁措辞扫描**（`docs/_compliance_check.txt`），
覆盖词表：`建议买入/建议卖出/建议关注/值得关注/目标价/评级/看多/看空/追高/抄底/止损位/止盈位/持有/加仓/减仓/建仓`。

## 2. 盘前预测：口径定义（关键）

> **v2 曾把「复盘预测」拆成两段（15:40 基准 + 08:15 增量），理由是"复盘需要当日收盘"。
> v3 按你的决定改为单一任务：改名为「盘前预测」，输入明确为「上一交易日收盘 + 隔夜信息」。**
> 改名之后口径自洽了 —— 它本来就是**盘前预测**，用昨日收盘做基准是正常做法，
> 不再是"拿旧数据冒充当日复盘"。

### 2.1 输入定义（界面固定显示，不藏在文档里）

| 输入 | 取数区间 |
|---|---|
| **收盘数据** | **2026-09-24（上一交易日）收盘** —— 情绪周期 / 涨停结构 / 资金流 / 板块拥挤度 / ETF 份额 |
| **隔夜信息** | **2026-09-24 15:00 → 本日 08:10** —— 美股 / 外盘商品 / 盘后公告 / 新增研报 |

> **不含本日盘中数据**（生成时本日尚未开盘）。本日盘中的变化由
> **「事件告警」**实时跟踪补上 —— 两者分工明确，不重叠。

### 2.2 界面必须做的两件事

1. **固定显示基准日期**：卡片副标题写明"基于上一交易日收盘 + 隔夜信息"，
   正文再写一次具体日期（效果图页 2 的"数据基准"块）。
2. **"关键判断变化"标注参照物**：写「相对昨收基准」，让读者知道"变化"是相对什么而言。

### 2.3 单一任务（08:10）

| 时间 | 动作 |
|---|---|
| **08:10** | `intel_premarket_forecast` 启动；读昨日收盘产物 + 拉隔夜增量 → 一次出结论 |
| **08:28** | 硬超时；超时则降级并标「输入不完整」，列出缺失项 |

排在 08:10 是为了**早于**盘前新闻（08:15）与简报汇总（08:25），
让汇总时能直接引用它的结论，不必等。

## 3. 交易日定时任务设计（8 个新 JobSpec）

全部 cron 声明进 `src/scheduler/registry.py`（既有单一事实源），交易日判定复用
`src/core/trading_session.py`（`session_state()` / `POST_CLOSE=15:05`）。

| 任务名 | cron | 周期 | 说明 |
|---|---|---|---|
| `intel_zsxq_collect` | `5 8,10,12,14 * * 1-5` | **2 小时** | 盘中研报采集（Token 直采，静默） |
| `intel_zsxq_collect_close` | `15 15 * * 1-5` | 日 | **收盘后收尾采集**（补齐当日全部内容） |
| **`intel_premarket_forecast`** | **`10 8 * * 1-5`** | 日 | **盘前预测** —— 上一交易日收盘 + 隔夜信息 |
| `intel_premarket_news` | `15 8 * * 1-5` | 日 | **盘前新闻**（外盘 + 公告 + 要闻） |
| `intel_premarket_brief` | `25 8 * * 1-5` | 日 | **盘前简报汇总**（合并其余项出一个结论） |
| `intel_premarket_heat` | `28 8 * * 1-5` | 日 | **盘前研报热度**（研报 + 小作文聚合打分） |
| `intel_event_scan` | `*/5 9-11,13-14 * * 1-5` | 5 分钟 | **事件告警扫描**（风险 / 机会） |
| `intel_resonance_check` | `*/15 * * * 1-5` | 15 分钟 | **多源共振判定**（含平台信号交叉验证） |

### 3.1 盘前窗口（08:05 → 08:30，四项任务全部落在窗口内）

```
08:05  采集第1次（覆盖隔夜与早间研报）
08:10  盘前预测        ┐
08:15  盘前新闻        ├ 三项并行，互不依赖
08:25  盘前简报汇总    ┘ 依赖前三项产物
08:28  盘前研报热度    ← 08:30 前最后一项
08:30  ── 全部产出完毕
```

### 3.2 采集为什么是 08:05 / 10:05 / 12:05 / 14:05 / 15:15

```
08:05  覆盖隔夜与早间研报（早于盘前任务，保证 8:25 汇总时有料）
10:05  ┐
12:05  ├ 盘中每 2 小时一次
14:05  ┘  14:05 是当日情报峰值（研报集中发布）→ 该时段告警扫描加密到 3 分钟
15:15  收盘收尾 —— 补齐当日全部内容
```

**15:15 这一次不能省。** 收盘后的研报与小作文是**次日盘前简报的主要输入**。
不采它，次日 08:05 那一次就要在 20 分钟内交出全天内容，压力集中且极易超时。

### 3.3 盘前任务的成功判据

| 任务 | 硬超时 | 超时行为 |
|---|---|---|
| 盘前新闻（08:15 启动） | **08:28** | 降级 + 标记「数据不完整」 |
| 盘前简报汇总（08:25 启动） | **08:28** | 用已有产物出一份，缺项列明 |
| 盘前研报热度（08:28 启动） | **08:30** | 用缓存热度 + 标记「未刷新」 |

**纪律**：超时就报缺口，**绝不用估算值补齐** —— 对齐项目既有规则
"数据缺失时置 `None` 并记 `degraded`，绝不用 0 或中性值冒充"。

### 3.4 非交易日 / 非交易时段

| 场景 | 行为 |
|---|---|
| 周末 / 法定节假日 | 全部跳过，运行记录写 `skipped`（不是失败） |
| 午休 11:30–13:00 | 采集继续；告警扫描暂停 |
| 盘后 15:00 之后 | 仅 ⭐3 共振告警可弹窗 |
| 交易日日历缺失 | 按工作日兜底并记 `degraded` |

## 4. 可信度打分（每条信息都显示）

**双轴模型** —— 关键设计是**来源分即上限**，防止低质来源靠堆量刷分：

```
可信度 = min(100, 来源分 + 0.35 × 内容分 + 独立佐证数 × 4)

来源分（0–94）  ← 同时是不可突破的上限
内容分（0–100） ← 只能小幅加成
独立佐证 ×4     ← 每个独立来源 +4，封顶 +20
```

### 4.1 来源分（权威性）

| 来源 | 基础分 | 例子 |
|---|---:|---|
| 监管 / 交易所 / 公司公告 | **94** | 证监会、交易所公告、定期报告 |
| 权威财经媒体 / 统计局 | **74** | 官方媒体、统计口径数据 |
| 持牌机构研报 | **84** | 券商研究所深度报告 |
| 财经自媒体 / 星球研报 | **54** | 星球小作文、公众号 |
| 股吧 / 论坛 / 截图 | **38** | 无署名、无出处 |
| 未证实传闻 | **28** | 群内截图、"据说" |
| 已证伪历史记录 | **↓ 自动扣分** | 同一作者历史假消息命中率 |

### 4.2 内容分（可验证程度）

| 内容形态 | 分 | 例 |
|---|---:|---|
| 官方原文 / 可核实数据 | 100 | 附公告编号、附数据出处 |
| 有数据支撑的判断 | 78 | "排产环比 +12%" |
| 转述他人观点 | 52 | "某分析师认为…" |
| 情绪表达 / 无信息 | 26 | "感觉要涨" |
| 纯推测 | 12 | "可能会…" |

### 4.3 置信分层（界面用颜色环表示）

| 分层 | 区间 | 颜色 | 处理 |
|---|---|---:|---|
| 高 | **≥80** | 绿 | 可进入告警 |
| 较高 | 65–79 | 黄绿 | 可进入告警 |
| 中 | 50–64 | 黄 | 仅入情报流 |
| 低 | 35–49 | 橙 | 标记"低可信" |
| 存疑 | **<35** | 红 | **不弹窗**，仅留档 |

### 4.4 举证示例（效果图页 1 表格）

| 条目 | 来源分 | 内容分 | 佐证 | 结果 |
|---|---:|---:|---:|---:|
| 交易所公告（扩产进展） | 94 | 100 | 2 | **min(100, 94+35+8) = 94** |
| 券商研报（行业深度） | 84 | 78 | 0 | **84+27 = 88**（封顶 84 之上小幅加成）|
| 星球小作文（多源印证） | 54 | 52 | 3 | **54+18+12 = 66** |
| 未证实传闻 | 28 | 12 | 0 | **28+4 = 31** |

> 注意第 3 行：**三个来源的小作文也只有 66 分** —— 这就是"来源分即上限"在起作用。
> 若无此约束，三条小作文会互相"佐证"到 90+，等于用传闻伪造可信度。

**界面呈现**：可信度环 + 一行说明为什么是这个分（如"自媒体 · 多源印证：2 个独立来源"）。
**不做黑盒分数** —— 每个数字旁边都要能点开看构成。

## 5. 多源共振（你要求的核心能力）

### 5.1 判定规则

```
1. 按【事件轴】聚类      —— 同事件多帖只算 1 个来源
2. 统计【独立来源数】    —— 重复转载不计
3. 校验方向一致性        —— 方向不一致 → 判为「背离」，不计入共振
4. 加权可信度 ≥65 且 独立来源 ≥2        → ⭐2 中共振
5. ≥3 个不同类型来源（须含平台信号）    → ⭐3 强共振
```

**加权可信度**按来源分加权，而非简单平均（一条官方公告的权重高于三条小作文）。

### 5.2 参与共振的信号源

| 类别 | 信号 |
|---|---|
| 舆情 | 券商研报、财经小作文、官方公告 |
| 平台既有 | 板块主线挖掘预警、板块拥挤度、ETF 份额、资金流、集合竞价、情绪周期 |

### 5.3 界面三态（缺一不可）

| 态 | 展示 | 例 |
|---|---|---|
| ⭐3 强共振 | 紫 | 官方公告 + 券商研报 + 主线挖掘 → 半导体设备（90.2） |
| ⭐2 中共振 | 蓝 | 星球小作文 + ETF 份额流出 → 煤炭（66.0） |
| **⚡ 背离** | **橙** | 舆情偏多 **但** 拥挤度 87 分位 → AI 算力（**不计入共振**） |

> **背离必须单独展示，不能只显示"共振"。** 只报同向信号等于只看一半证据；
> 方向矛盾的信号恰恰是最需要提示的（"舆情热但拥挤"就是典型的追高风险）。

### 5.4 防重复计数

同一份信息被当成 N 份独立证据，共振就是假的 ——
这个问题在本项目主线挖掘模块已经写明过风险（"同一份信息被当成三份独立证据，回测胜率必然虚高"）。
**去重键**：`(标的, 事件指纹, 时间窗)`；同一事件 2 小时内只算一次。

## 6. 告警与弹窗

### 6.1 两类告警

| 类型 | 触发 | 例 |
|---|---|---|
| **风险告警** | 利空 + 可信度 ≥65，或与持仓敞口相关 | 煤炭舆情转空 + ETF 份额流出 |
| **机会告警** | 利多 + 可信度 ≥65，或 ⭐2/⭐3 共振 | 半导体设备三源共振 |

### 6.2 弹窗抑制（防打扰，必须有）

```
· 同一事件 2 小时内不重复弹
· 可信度 < 65 不弹
· 非交易时段（含午休、盘后 15:00 后）仅 ⭐3 可弹
· 每日弹窗上限 10 次，超出仅入中心
```

效果图页 1 的时间轴旁与页 4 都显示实际数据：**今日弹窗 3 次 / 抑制 15 次**。
把抑制次数显式展示，是为了让用户相信"没被漏掉，只是没打扰你"。

### 6.3 告警内容合规（硬约束）

每条告警**必须**是"可归因的信息陈述"，不是投资建议：

| ✅ 可以 | ❌ 不可以 |
|---|---|
| "舆情转空，与 ETF 份额流出同向" | "建议卖出煤炭" |
| "三源共振指向半导体设备" | "目标价 XX 元" |
| "拥挤度 87 分位，提示追高风险" | "评级：买入" |

**从数据结构上堵死**：告警契约里**不存在** `target_price` / `rating` / `buy_sell` 字段。
（对齐 assistant `AGENTS.md` 的失败案例记录，以及本项目 `竞价选股` 的合规口径。）

## 7. 五个页面的信息架构（效果图）

### 页 1 · 情报雷达（主入口）

## 10. 验收标准

1. **静默**：连续 3 个交易日定时采集，**零窗口弹出**，无残留 Chromium 会话
2. **性能**：单群组 100 条 < 10s（现状 259s）
3. **准点**：盘前三项任务 100% 于 **08:30 前**产出，或在超时时**如实标注不完整**
4. **可信度可解释**：任一条目可展开看到「来源分 + 内容分 + 佐证数」三项构成
5. **共振不虚高**：同事件重复转载**不计入**独立来源数（要有单测）
6. **不打扰**：弹窗抑制生效，每日弹窗 ≤10 次，抑制次数可见
7. **合规**：告警契约中**不存在**目标价/评级/买卖字段；风险声明强制出现
8. **不退化**：既有 4,004 个用例全绿；不新增反依赖
