# 前端设计规范

## 一、设计原则

- **信息密度优先**：投研用户需要高信息密度界面，禁止大面积留白。
- **渐进式披露**：默认展示核心信息，详情按需展开。
- **多模态交互**：支持自然语言、触控、笔输入等多种交互方式。

## 二、组件化设计

遵循原子设计（Atomic Design）方法论：

```
src/components/
├── ui/                    # 基础组件（Atoms）
│   ├── Button.tsx
│   ├── Input.tsx
│   ├── Table.tsx
│   ├── Chart.tsx
│   └── Card.tsx
├── features/              # 功能组件（Molecules/Organisms）
│   ├── ResearchPanel.tsx
│   ├── TraceViewer.tsx
│   ├── ReportViewer.tsx
│   └── DataSourceBadge.tsx
└── layout/                # 布局组件（Templates）
    ├── MainLayout.tsx
    ├── Sidebar.tsx
    └── Header.tsx
```

每个功能模块必须有独立的Hook管理状态：`useResearchState`、`useTraceState`、`useReportState`。

## 三、响应式设计

| 设备 | 断点 | 布局 |
|------|------|------|
| 桌面端 | ≥1280px | 三栏布局（侧边栏+主内容+详情面板） |
| 平板端 | 768-1279px | 两栏布局（侧边栏+主内容） |
| 移动端 | <768px | 单栏布局，底部导航 |

## 四、数据可视化

- 所有金融数据必须支持表格和图表双视图切换。
- 表格必须支持排序、筛选、分页、导出。
- 图表配色使用色盲安全调色板。
- 关键指标支持“红涨绿跌”和“绿涨红跌”两种配色方案切换。
- K线图、趋势图、对比图支持交互式缩放和悬停查看明细。

## 五、交互体验

- 所有Agent分析结论必须支持“一键溯源”：点击结论即可查看引用的数据源和推理路径。
- 报告生成支持自定义模板，用户可选择报告结构、模块顺序、可视化形式。
- 所有异步操作（报告生成、数据刷新）必须有进度指示器，支持取消操作。
- 错误状态必须提供明确的错误信息和恢复建议，禁止显示“系统错误”等模糊提示。

## 六、美观性规范

- 采用统一的Design Token系统：颜色、字体、间距、圆角、阴影全部通过Token定义。
- 深色模式支持：所有界面必须支持深色/浅色模式切换。
- 字体规范：数字使用等宽字体，正文使用无衬线字体。
- 动效规范：页面切换≤200ms，数据加载使用骨架屏，禁止使用花哨的过渡动画。

## 七、关键页面设计

### 7.1 投研工作台
- 顶部：搜索框 + 快捷操作
- 左侧：Agent列表 + 任务历史
- 中间：分析结果 + 推理路径
- 右侧：数据源 + 报告预览

### 7.2 推理路径查看器
- 树形结构展示推理步骤
- 每步可展开查看数据引用和公式
- 支持点击数据ID跳转至原始数据源

### 7.3 报告生成器
- 模板选择 + 模块拖拽
- 实时预览
- 导出Markdown/PDF
