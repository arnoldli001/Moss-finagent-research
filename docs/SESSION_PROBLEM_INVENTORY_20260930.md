# 本轮问题清单 · 根因 · 解决方案（2026-09-30）

> 范围：本轮会话（起点＝用户报障「点击日K 为什么卡在『正在取日线并跑量价规则』」）暴露/修复的全部问题。
> 每条都带**可复跑证据**与**状态**；未闭环的如实登记在 §5。
> 关联落账：`docs/PRD.md` §20（日K预热）、§28（V8 并发崩溃）、**PRD-28 子节**；台账 `CHG-0097`~`CHG-0149`。

## 0. 一句话结论

**表层症状是"日K慢"，真正的病灶有三层**：① 没有任何作业预热日K（冷 4.19 s / 热 0.07 s）；
② 预热轮**不被预算约束**（实测一轮 316.4 s，跨 2~3 个 tick，把事件循环占住 ⇒ 前端 4 s 探针超时 ⇒ "后端不可达"横幅）；
③ **日线链在并发下会原生崩溃**（`py_mini_racer`/V8 非线程安全，**3/3 复现**，无 traceback）——这才是 pilot"无痕死亡"与 502 的真凶。

## 2. 根因归类（4 类，可复用）

1. **判据维度缺失**：P3/P4/P5 都是"我量了一个维度，就以为量全了" —— 量了停顿没量**崩溃**；量了提交没量**整轮墙钟**；量了慢没量**会不会死**。
   → 纪律：**判据的维度按"后果"枚举**（慢 / 错 / 崩 / 静默 / 越权），不按"我手上有的那个仪器"枚举。
2. **判据对象错**：P1（"服务器开着＝数据会自动取"，但没有任何作业写那个缓存）、P6（"端口空＝进程死了"，而启动期端口必然是空的）。
   → 纪律：**判据必须指向"产生该结果的因果链"，不是它的代理量**（端口 ≠ 就绪；在线 ≠ 在干活）。
3. **无痕死亡**：P5 的原生崩溃与强杀一样**不留 traceback**，导致"事后追查"整条链上没有证据。
   → 纪律：先补**仪器**（退出码 / 事件日志 / 1 Hz 循环延迟 / 在飞登记），再谈定位；"没记录"不等于"没发生"。
4. **协作面**：P12（共享文件与号的并发写）。
   → 纪律：**幂等号现读**、结构改完跑形状自检、能自动化的检查不要写成提醒。
