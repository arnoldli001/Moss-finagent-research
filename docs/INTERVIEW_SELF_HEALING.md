# 面试话术：自学习数据补充能力

> 目标：60 秒讲清楚核心亮点，3 个追问各 30 秒

---

## 电梯演讲（30 秒）

> 我在投研系统里做了一个**自学习数据补充**能力。用户问的指标如果系统没接入——比如"半导体销售额同比"——系统会自动触发一个 LLM Agent，基于 AkShare 和公开 API 的知识**生成 Python 采集代码**，经过 AST 白名单验证和子进程沙箱冒烟测试后，热加载到路由器并注册定时采集。**成功一次就永久沉淀**——连接器代码保存到文件，调度配置写入 JSON，下次同一个指标直接命中本地数据库，不需要再生成。

---

## 核心亮点（3 句话）

### 亮点 1: 自修复，不是等开发者补数据源

> 传统做法是指标缺失就报数据缺口，等开发者手动写连接器。我的系统在 A01 采集 + 存储降级都返回空时，自动触发 LLM 生成连接器代码——**从发现缺口到拿到数据全自动，不依赖人工介入**。

### 亮点 2: 两层安全验证，LLM 生成的代码不能随便跑

> LLM 生成的代码不直接执行。先过 **AST 静态验证**——白名单导入、禁止 exec/eval/os/subprocess/pickle、禁止文件写入模式；再过**子进程沙箱冒烟**——15 秒超时 kill、导入+实例化+fetch 冒烟。两层都过才注册。**最多重试 2 次**，都过不了就放弃，缺口照样上报给决策 Agent——**自修复是增强不是必需**。

### 亮点 3: 自动沉淀，不是用完就丢

> 自修复成功的连接器有**三层持久化**：代码存到 `dynamic_connectors/` 目录、调度配置写入 `_schedule.json`、采集数据入 SQLite。进程重启后，连接器从文件自动加载、调度从 JSON 自动恢复、数据走三级短路命中 DB。**第一次自修复 30 秒，之后永久 0 秒**。

---

## 常见追问应答

### Q: LLM 生成的代码安全吗？怎么防止恶意代码？

> 两层验证。第一层 AST 遍历：检查所有 Import 节点是否在白名单（只允许 akshare/requests/pandas/numpy 等数据采集库）、检查所有 Call 节点是否调了禁止函数（exec/eval/os.system/pickle 等）、正则补充检查文件写入模式 `open(..., "w")`。第二层子进程沙箱：在独立子进程里导入+实例化+调用 fetch，15 秒超时 kill。两层都过才允许注册到路由器。

### Q: 如果 LLM 生成的代码拿到的是假数据怎么办？

> 自修复流程里有一个**重试 fetch 验证步骤**：新连接器注册后，立刻调用一次 fetch，检查返回的 DataPoint 非空、有 period_date、有 value。如果连接器注册了但 fetch 返回空，不算成功，不注册调度。另外，**真实源失败绝不回退模拟源**——这条规则是全系统的硬约束，LLM 生成的连接器如果 `get_capabilities()` 返回 `simulated=True`，Router 会在真实源失败后跳过它。

### Q: 这个功能实际跑过吗？效果如何？

> （如已跑过）跑过。自修复一个 AkShare 函数缺失的指标，LLM 生成的代码第一版有语法错误（LLM 把模块名拼错了），第二版修正后通过了两层验证，沙箱冒烟 2 秒完成，注册后 fetch 到 12 条数据。后续请求走 DB 命中 0 秒返回。

> （如未跑过）设计完成、单测覆盖了安全验证的正向和反向用例。实际跑需要 LLM API 联调，核心风险在代码质量——LLM 可能生成的 AkShare 函数名不存在，沙箱测试会拦截这种情况。

### Q: 为什么不直接用 LangChain Tool 或 function calling？

> 我用的是 ReAct 框架的自定义工具，不是 LangChain。原因：LangChain 的 Tool 抽象太重，我的 BaseConnector 已经是完整的协议（supports + fetch + get_capabilities），直接作为 Tool 注册到 ReAct 更轻量。另外，function calling 需要模型支持特定格式，我用的 deepseek-flash 的 function calling 能力不如直接 prompt 生成代码可靠——**生成完整 Python 类比生成 JSON 参数更容易让 LLM 理解任务**。

---

## 一句话总结（面试结尾用）

> 这个功能的本质是**把数据接入从"开发任务"变成"运行时自服务"**——LLM 发现缺口、生成代码、验证安全、注册调度、沉淀资产，全链路不需要人介入。安全风险用两层验证兜底，失败不阻断主链路。核心价值不是省了开发时间，而是**系统对未知指标的自适应能力**——用户问什么都能尝试拿到数据，而不是报"指标未接入"。
