# 演示 Demo 建议

> 面试现场时间有限（通常 10–20 分钟），**不要逐个页面点**。
> 本文给三条演示动线，按面试官岗位选一条，其余作为追问弹药。

## 零、演示前 5 分钟准备（照着做）

```powershell
# 1. 起服务（本机 8100）
$env:PYTHONPATH="."; .\.venv\Scripts\python.exe manage.py start --replace --daemon

# 2. 预热演示数据（幂等，可重复执行）
.\.venv\Scripts\python.exe scripts/seed_demo_data.py

# 3. 七步导览：逐项 PASS/FAIL，含风险声明（这是最稳的开场）
.\.venv\Scripts\python.exe scripts/demo_tour.py

# 4. 打开工作台
start http://127.0.0.1:8100
```

**开场前自检三条**（任何一条不过，改用「只讲不演」）：

| 检查 | 命令 | 期望 |
|---|---|---|
| 服务活着 | `curl http://127.0.0.1:8100/healthz` | 200（⚠️ 不是 `/api/v1/metrics/health` —— 那条是旧文档里的死路径，实测 404，见 `CHG-0128`） |
| 数据源状态 | 工作台左上「数据源健康」 | 至少 2 个源绿 |
| 有选股结果 | `curl "http://127.0.0.1:8100/api/v1/auction_select/today?trade_date=20260918"` | 有 `picked` |

> ⚠️ **Ollama 冷启动约 28 秒**。演示前先手动跑一次任意 LLM 功能把它拉起来
> （`scripts/seed_demo_data.py` 会触发），否则第一个 LLM 请求会卡住 28 秒，
> 现场很尴尬。

## 一、三条动线（按岗位选）

### 动线 A · 投 AI 应用开发工程师（12 分钟）

| 分钟 | 做什么 | 讲什么（一句话钩子） |
|---|---|---|
| 0–2 | `python scripts/demo_tour.py` 跑七步导览 | "先看系统自检 —— 它自己会报哪一步 FAIL、为什么"（**第 5 步会印 401**：调度管理自 2026-09-26 起**管理员专属**，脚本不带凭据时断言的正是"匿名必须被拒"—— **这是一条安全性的加分项，不是故障**；要展示真实作业清单用 `--admin-cookie`） |
| 2–5 | 工作台 → 投研 → 输入个股 → 运行 | "注意顶部这条**时间线**：Planner 挑了几个 Agent、每个花多久、哪一步降级了" |
| 5–8 | 展开 Trace 面板 + 审计链 | "每次 LLM 调用的 prompt_hash / token / 延迟 / 降级链都落在这里，不可篡改" |
| 8–10 | 打开 `configs/models.yaml` | "分层路由：规划用本地 1.5B，分析用 8B，决策才上云端；简单任务零 token 成本" |
| 10–12 | 断网演示（拔网线或停 Ollama） | "熔断器打开 → 自动降级备模型 → 全失败则**如实报缺口**，不编数据" |

**最有杀伤力的一步是最后那个"故意弄坏"**：面试官见过太多只演示 happy path 的项目。

### 动线 B · 投量化工程师（12 分钟）

| 分钟 | 做什么 | 讲什么 |
|---|---|---|
| 0–3 | 工作台 → 量化 → 因子分析 | "IC/IR 用 Spearman；预处理三步：MAD 去极值 → z-score → 市值+行业中性化" |
| 3–6 | 分层回测 + 净值曲线 | "5 分位分层，看的是 H-L 价差的单调性 —— **A 股空头腿不可做空，这是因子有效性检验不是可交易策略**" |
| 6–8 | 风控页：VaR / 压力测试 | "历史模拟法不假设分布；压力段覆盖 2015 股灾、2020 新冠" |
| 8–10 | 竞价选股面板（`trade_date=20260918`） | "9:25:00 自动出池，每个维度得分可展开；落选区标了每条否决的语料出处" |
| 10–12 | 终端跑 `rulebook --dump` / `--explain` | "全部规则一张纸；单票能逐条解释为什么入选/为什么被杀" |

### 动线 C · 通用 / 时间紧（6 分钟）

1. **2 分钟**：`demo_tour.py` 七步自检（体现工程纪律；第 5 步的 401 是**管理员门按设计生效**，讲这句比跳过它更有说服力）
2. **2 分钟**：竞价选股面板 + `rulebook --explain 600630`（体现重构与可解释性）
3. **2 分钟**：断网降级演示（体现可靠性设计）

> ⚠️ **本导览必须打 dev(8100)**。打到 8110（对外试点）第 1 步就 401 —— 那是**全站强制登录**，
> 不是服务坏了。起服务：`.\.venv\Scripts\python.exe manage.py start --daemon`；
> 自检：`manage.py status` 应显示「后端 API 8100 本项目运行中」。

## 二、五个"必演"片段（以及为什么）

### 片段 1 · 规则总表（成本最低、印象分最高）

```powershell
.\.venv\Scripts\python.exe -m src.auction_select.rulebook --dump
```

输出一张纸看完前置筛选 9 条 / 打标签 1 条 / 否决 10 条 / 12 维分档 / 加分 / 出池。

> **讲法**："原来这些判定散在 4 个文件、329 处 `if/elif` 里，改一条规则要翻半天。
> 现在规则是**数据**、执行是**解释器**，而且每张表能直接打印。"

### 片段 2 · 单票判定溯源

```powershell
.\.venv\Scripts\python.exe -m src.auction_select.rulebook --explain 600630 --trade-date 20260918
```

输出 Pass1 打标签 → Pass2 否决（含豁免）→ 12 维逐维得分 → 加分 → 总分 → 结论。

> **讲法**："这是 600630 龙头股份：主板高开 6.10% 本该被否决，
> 但 Pass1 给它打了「大量抢筹」，Pass2 里规则 4 就豁免了它 —— 最后 49.93 + 5 = 54.93 入选。
> **打标签与否决是两遍独立纯函数**，所以不存在'哪条规则必须先跑'的问题。"

### 片段 3 · 断网 / 依赖不可用降级

停掉 Ollama（或拔网线），再点一次"运行"。

> **讲法**："断路器打开 → 降级到备模型 → 备模型也失败就**如实报数据缺口**。
> 这条是刻意设计：假数据进了投研建议，比'这次没数据'危险得多。"

### 片段 4 · 500 故障复盘（如果有文档可翻）

打开 `docs/INTERVIEW_事件告警500故障复盘.md`（若存在）。

> **讲法**："这是我真实踩过并修掉的一个线上 500 —— 从现象到根因到修复到防复发。
> 我更想讲这个过程，因为它比'我做了一个系统'更能说明我怎么定位问题。"

### 片段 5 · 黄金回归（工程成熟度的证明）

```powershell
.\.venv\Scripts\python.exe -m pytest tests/unit/test_auction_golden.py -v
```

> **讲法**："这次重构是**纯重构**，行为必须一字不差。所以我用冻结的真实行情建了
> 黄金回归：47 只票 × 12 维逐位比对，还有一条**性能门禁**（决策链路必须 < 200 ms），
> 防止以后有人把全市场读取顺手放回热路径。"

## 三、演示禁忌

| 不要 | 原因 |
|---|---|
| ❌ 现场跑全量回测 | 全历史取数数十秒，冷场 |
| ❌ 现场跑 `pytest` 全量 | 3 分钟，且有一个已知无关失败，解释成本高于收益 |
| ❌ 逐个页面点过去 | 40+ 个组件，10 分钟只够点完一半，且没有重点 |
| ❌ 强调"19 个 Agent"却不解释分层 | 容易被当成堆砌；主动说明是**职责分层**、单进程注册 |
| ❌ 报收益数字 | 没有真实资金验证，一问就穿 |
| ⚠️ 演示 LLM 功能前不预热 | Ollama 冷启动 28 秒 |
