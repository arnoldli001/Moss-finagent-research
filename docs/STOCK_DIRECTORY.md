# 本地股票字典（代码 / 中文名 / 拼音首字母）

> 解决"输入股票只能靠记代码""界面上只显示冷冰冰的 6 位数"这两件事。

## 1. 起因：一个真实事故

做T自选股里出现了这样的条目：

```yaml
- code: "603083"
  name: "603083"        # ← 名称就是代码
- code: "600150"
  name: "600150"
```

原因是前端加自选时把"当前已加载快照里的名称"发过去，而用户**没先加载这只票**
时名称就是空的，后端只能退化成写代码本身。界面上一排 `603083 / 600150`，
认不出是什么公司 —— 而且它**看起来像正常数据**，不会报错、不会有人反馈。

同一个问题还有第二副面孔：项目里所有股票输入框都是裸 `<input maxLength={6}>`，
只收 6 位数字。想加"剑桥科技"必须先自己查出代码是 603083。

## 2. 数据来源与分工

| 来源 | 覆盖 | 离线 | 用途 |
|------|------|:----:|------|
| Tushare `stock_basic` | 5562 只 A 股（含行业/市场/上市日） | ✅ | **批量建库主来源** |
| `pypinyin` | 任意中文 | ✅ | 生成首字母与全拼 |
| 东财 suggest | A股/ETF/指数/港股… | ❌ | **按需补录**（ETF、指数不在 stock_basic 里） |

实测（2026-09-16）：东财 `searchapi.eastmoney.com` 在本机**可达**，返回 JSON
（含 `Name`、`PinYin`、`Classify`）；被阻断的是 `push2*` 行情域名，不是搜索域名。

**拼音用本地库而不是外部接口**：5562 个名称生成拼音是毫秒级且结果确定；
换成逐个问搜索接口要 5562 次请求，既慢又不可复现。

## 3. 用法

```bash
# 建库（一次即可，之后增量的 ETF/指数会自动补录）
uv run python scripts/quant_stocks.py rebuild

# 联动联想
uv run python scripts/quant_stocks.py search jqkj     # → 603083 剑桥科技 JQKJ
uv run python scripts/quant_stocks.py search PAYH     # → 000001 平安银行 PAYH
uv run python scripts/quant_stocks.py search 平安      # → 平安银行 / 中国平安
uv run python scripts/quant_stocks.py get 603083      # → 剑桥科技

# 补录 ETF / 指数
uv run python scripts/quant_stocks.py enrich 588170 510300
```

接口：

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/quant/stocks/search?q=&limit=` | 四路联想 |
| GET | `/api/v1/quant/stocks/{code}` | 名称与拼音 |
| POST | `/api/v1/quant/stocks/directory/rebuild` | 重建字典 |

## 4. 联想排序

| 优先级 | 匹配方式 | 例子 |
|:---:|---|---|
| 0 | 代码完全相等 | `603083` |
| 1 | 代码前缀 | `6030` |
| 2 | 首字母完全相等 | `jqkj` |
| 3 | 首字母前缀 | `jq` |
| 4 | 全拼前缀 | `jianqiao` |
| 5 | 中文名包含 | `平安` |
| 6 | 中文名首字 | `平` |

同一个首字母对应多只票时**全部列出**（`JQKJ` → 剑桥科技 + 钜泉科技），
不做猜测式消歧。

## 5. 前端

`web/src/components/StockPicker.tsx` 是统一的选择器组件，已接入三处：
做T辅助（切换标的）、单股票策略回测、宏观择时回测。

行为要点：

- 输入即联想（180ms 防抖，打字过程中不打接口）；
- 输入 6 位数字后**自动在框旁边显示中文名**（手打代码也能确认是哪只票）；
- `↑↓` 选择、`Enter/Tab` 采纳、鼠标点击直接选中；
- 做T页点候选**直接切换标的**（不必再点一次「切换标的」）。

## 6. 名称补全的硬规则：**查不到返回空，绝不退回代码**

`StockDirectory.name_of()` 在查不到时返回**空字符串**，而不是返回代码。
返回代码会让"名称就是代码"的脏数据看起来像正常值 —— 这正是上面那次事故的成因。

同一个规则落在三处：

1. `name_of()` 判定 `name == code` 为"无名称"；
2. `IntradayService.add_watch()` 名称为空或等于代码时，**用字典补齐**；
3. 渲染自选列表时，配置里的名字和字典里的名字都可以用，**实在没有就留空**。

历史脏数据已一次性修复（`603083 → 剑桥科技`、`600150 → 中国船舶`），
而且修复脚本只改那两行、配置文件的 55 行注释原样保留。

## 7. 已知限制

- **不做拼音多音字消歧**：`重庆`→`ZQ`、`长城`→`ZC` 这类依赖 `pypinyin` 的默认读音，
  个别名称的首字母可能与习惯不同（可按全拼或中文名检索，不受影响）；
- **A 股之外的覆盖依赖东财**：ETF/指数首次查询时补录一次；东财不可用时该代码
  查不到名称（不影响代码本身的输入与回测）；
- **字典不落库到 MySQL 也能用**：与量化仓库同一套方言无关实现，
  换成 MySQL 只需改环境变量；
- **不含港股/美股中文名**：东财 suggest 能查到港股，但本项目未用到，未做验证。
