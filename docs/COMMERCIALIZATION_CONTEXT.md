## 0. 一句话结论

**可变现的不是"AI 功能"，而是"一份别人拿不到的信息源 + 把它加工成可复算指标的链路"。**
几乎所有商业化决策都是从两个约束推出来的：

1. **开发者是个人，没有证券投资咨询业务资格** → 只能交付"信息与工具"，不能交付"意见"
2. **来源本身就是可复制的资产** → 数据源一旦暴露，壁垒归零

## 1. 这条线是怎么走过来的

最初的问题是「这套自研量化系统卖给机构或私募大概值多少钱」。讨论之后**重心从"定价"转到了"可售卖化改造"**，
因为定价的前提是"它得先能合法、安全地卖出去"。改造顺序：

```
问值多少钱
  → 公司注册 / 资质门槛（发现个人拿不到短信资质等）
  → 与另一项目（moss-finance-assistant）的整合方案
  → 前端改版（客户看得懂）
  → 权限 / 等级门控（不同客户不同能力 = 才能分层定价）
  → 合规基线（个人无牌照 → 换交付物）
  → 数据源保密（核心资产保护）
  → 运维工具 / 源冗余（能持续供数据才收得到钱）
```

## 2. 能不能卖：合规基线（所有设计的前提）

### 2.1 结论：**换交付物，不换措辞**

依据：证监会公告〔2012〕40号《关于加强对利用"荐股软件"从事证券投资咨询业务监管的暂行规定》。
它对"荐股软件"的认定是**按功能**，不是按措辞，并且**明确禁止"以不同措辞表达"**：

| 认定要素 | |
|---|---|
| ① 提供具体证券的投资分析意见 | 按**功能**认定 |
| ② 推荐具体证券 | 同上 |
| ③ 提供买卖时机建议 | 同上 |
| ④ **以不同措辞表达上述内容** | **明确禁止变相表达** |

> ⚠️ "换种说法绕开买卖建议"是**法律上最危险**的做法：条文本身就禁止变相表达，
> 把"建议买入"改写成"值得留意"等于**自证主观规避意图** —— 功能上仍是建议，主观上多了"明知故犯"。

### 2.2 实际交付物（❌ 越线 ／ ✅ 合规）

| ❌ 原表述 | ✅ 替代交付物 | 为什么 |
|---|---|---|
| 「今日关注清单：半导体设备 多」 | 「该板块今日被提及 **27 篇**，20 日均值 **9 篇**（环比 +200%），可信度 90.2」 | 换成**可验证计数**，阈值由使用者自己定 |
| 「半导体设备：维持看多」 | 「新增可归因信息 **3 条**（费半 +2.1% / 公告 ×1 / 研报 ×2）」 | 只陈述"新增了什么" |
| 「煤炭转空，需关注持仓敞口」 | 「25 篇提及（19 篇原文语气偏空）+ ETF 份额 5 日 **−12.4%**，两组数据同向」 | 陈述统计事实，不给操作暗示 |
| 「AI 算力提示追高风险」 | 「提及方向偏多，同时拥挤度处于 **87 分位**；两指标取值不一致，故不计入共振」 | 把"风险判断"还原为"两个指标取值" |
| 「风险告警 / 机会告警」 | 「**信息事件** / **指标不一致** / **低可信**」 | 告警名字本身就在下判断 |
| 弹窗按钮「查看详情」 | 「查看**来源**」/「查看**依据**」 | 能给的只有来源 |

> **核心洞察：换成数据后信息量不减反增** —— "提及 27 篇 / 均值 9 篇"比"值得关注"信息更多。
> 这不是妥协，是把主观判断交还给有判断权的人。

### 2.3 四条硬约束（不可用开关关闭）

| # | 约束 | 落地位置 |
|---|---|---|
| 1 | 全部指标为**描述性统计**，不做**预测性**表述 | 计算层只产出计数/分位/环比 |
| 2 | 契约中**不存在** `target_price` / `rating` / `buy_sell` 字段 | 数据结构层面堵死 |
| 3 | 第三方倾向一律标注为**「原文倾向」**，不是平台判断 | UI 标签固定 |
| 4 | 公式与参数**公开可复算**（公式版本号 + 参数文件名进审计链） | 界面直接给出公式 |

### 2.4 自动化防线

效果图渲染脚本内置**违禁措辞扫描**（`docs/_compliance_check.txt`）：
覆盖 `建议买入/建议卖出/建议关注/值得关注/目标价/评级/看多/看空/追高/抄底/止损位/止盈位/持有/加仓/减仓/建仓`。
**当前命中 0**。建议做成 CI 门禁（与既有 `test_compliance_gate.py` 同思路）。

### 2.5 合规红线（任何套餐都不开放）

| # | 红线 | 落地 |
|---|---|---|
| 1 | **未证实传闻不对试用开放**：来源为"未证实"的条目，trial **直接不返回** | 路由层按 tier 过滤，**不是前端隐藏** |
| 2 | **风险声明强制**：所有情报输出附免责声明，任何套餐不可关闭 | 契约必填 + 前端固定渲染 |
| 3 | **不出现目标价/评级/买卖字段** | 契约里根本不存在 |

> 第 1 条的理由：**试用账号是最容易外流的账号**（临时开给客户、随手分享给同事）。
> 把最不可靠的内容放在最不可控的账号上，风险与收益不成比例。

## 3. 卖什么：可售卖项与套餐

### 3.1 可售卖项（`platform/config.py` 的 `FEATURES`，当前 9 项）

```
research 投研分析          backtest 策略回测        mainline 主线挖掘
fundflow 资金流监控        quant.auction 竞价选股   quant.select 量化选股
quant.intraday 辅助做T     intel.hot 热点&研报小作文  intel.alerts 事件告警中心
```

**刻意不在表里的**：`scheduler`（调度管理）、`metrics`（运行指标）——
它们是**运维面能力**（调度管理能手动触发作业，一次点击 = 4 次完整研究图），
按用户口径**写死管理员专属、不可勾选**（`my_features.ADMIN_ONLY_VIEWS`）。
`configs/platform_tiers.json` 里仍留着这两个键（用户明确说"可以不删除"），但已不被任何判据读取。

### 3.2 三档套餐与资源上限

| 档 | 自选总数 | 池数 | 单池 | 板块数 | 板块成员 | 参数上限 | 打分间隔 | WS | tokens/月 | 回测 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| admin 管理员 | 100 | 5 | 100 | 20 | 200 | 100 | 60s | 4 | 200,000 | 50 |
| vip VIP客户 | 100 | 5 | 100 | 20 | 200 | 100 | 60s | 2 | 50,000 | 10 |
| trial 试用用户 | 25 | 5 | 5 | 3 | 20 | 25 | 180s | 1 | 5,000 | 2 |

> **报价（行情快照）三档统一 5s，这是刻意的**：报价是批量公共数据（一次 300~500 只、
> 耗时几乎不随数量增长），全宇宙 5s 全量刷新成本只有 ≈2 请求/s / 1.6 Mbps / 1% 单核。
> **没有理由让试用用户的涨跌幅比 VIP 慢** —— 那只造成无谓的体验落差。
> 需要节流的是**逐只接口**（分时/5mK），它按"是否有人正在看"分档，不按付费层级。

### 3.3 定价

- 单价写在 `configs/platform_tiers.json` 的 `pricing`：唯一非零项是 **`quant.auction`（竞价选股）¥199**，其余为 `0.0`（含在套餐内）
- **套餐月费字段已下线**（用户口径 2026-09-23："定价不由本系统维护"）
- `platform_tiers.json` 可进 Git：套餐改动应当可评审、可回滚、可 diff —— 它是**部署配置**不是用户数据

### 3.4 ★ 关键商业化决策：**不卖转发能力**（取消 `intel.export`）

原方案把导出做成"VIP 加购 99 元/月"，**已删除**。理由：

> 那等于**把情报卖给了转发能力** —— 客户导出一张长图发到群里，
> 你的信息差壁垒就变成他的了，而你的订阅收入只有一份。

连带清理（"半留半去最危险"）：`FEATURES` 条目、`pricing` 项、`EXPORT_INTEL` 动作码、
前端「导出长图」按钮**全部删除**；界面只保留**浏览器本地另存**，**不做服务端批量导出接口**
（服务端导出是泄漏主通道，本地保存不是）。

> 顺带收益：原方案里"导出入不入四眼原则"那个两难（要审批会导致用户去截图、不要又怕泄漏）
> **因为功能不存在而自动消解**。少一个功能，少一个风险面。

### 3.5 分级原则

| 原则 | 例子 |
|---|---|
| 核心卖点让试用**能体验** | `intel.hot`（热点&研报小作文 + 投资日历）trial ✅ |
| 执行抓手让试用**只读** | `intel.alerts` trial ❌（"告警是执行抓手，不是展示品"） |
| 重资源功能试用**不开** | `backtest`（吃 CPU）、`quant.auction`（最贵，单独加购） |
| **功能开关 ≠ 页签** | `FEATURES`（可售卖项）与 `VIEW_FEATURE`（前端页签）**刻意分开**：一个售卖项可以对应多个页签（`intel.hot` → 两个一级页签），一个页签也可以由多个售卖项任一开启（`intraday` ← 三个 `quant.*`） |

## 4. 最大的资产：情报来源保密

> **用户原话**：不能暴露我自己的情报数据源来源，会被盗用，失去情报信息差壁垒。

**这不是权限问题，是架构问题** —— 不是"谁可以看"，而是"**任何人都不能看到数据源长什么样**"。

### 4.1 为什么来源本身就是资产

| 泄漏了什么 | 对手能做什么 |
|---|---|
| 具体数据源（哪个星球 / 哪个号 / 哪个接口） | **自己去订阅**，成本可能只有几百块 |
| API 端点与参数 | 直接爬，**零成本复制**采集层 |
| Token 获取方式 | 复用你的账号体系 |
| 采集频率与调度 | 复刻你的时序优势 |
| 作者 / 群组 ID | 精准定位到人，**绕开平台直接联系** |

### 4.2 三层防护（缺一不可）

```
第 1 层｜契约层（最关键）
    API 返回体中【根本不存在】以下字段：
      source_url / group_id / author / author_id / topic_id
      token 前缀 / 采集器名称 / 接口路径 / 原始 HTML
    ★ 意义：前端的 XSS、抓包、爬接口，一律拿不到东西。
    ★ 做法：白名单构造（新字段默认不出），而不是"字典推导剔除"

第 2 层｜展示层
    只暴露【来源大类】枚举 + 可信度构成（来源分/内容分/佐证数），三者都不泄漏来源：
      OFFICIAL / BROKER（不写哪家券商）/ MEDIA（不写哪家媒体）
      SELF_MEDIA（不写哪个号/星球）/ UNVERIFIED

第 3 层｜运维层
    · 日志与异常文案的来源标识脱敏（sanitize_error 走白名单，只保留"哪一类失败"）
    · 采集器异常不得把 URL/Token 带进 HTTP 响应
    · .env 凭证不进日志、不进审计链、不进错误上报
```

> **一个必须守住的边界**：`content_hash` 可以留（用于去重与审计），
> 但**不能和 `source_url` 一起给出去** —— 有了 hash 就能在公开渠道反查同一篇内容。

### 4.3 实施中的关键判断：公开平台 vs 私域

用户口径：**公开数据平台可以暴露**（AkShare/腾讯/新浪/东财/QMT），**平台与群身份必须藏**（知识星球调研、群 id）。

这不矛盾 —— **"我从哪个公开网站抓的"不是壁垒**（谁都能抓），**"我有一份付费/私域的信息源"才是壁垒**。
落地是 `PUBLIC_PLATFORMS` **白名单映射**：6 个公开源 → 平台名；表外来源（`research-note-zsxq` / `broker-*`）一律**空串**。

### 4.4 附带收益（两个问题一起解决）

1. **盗用壁垒**：客户拿不到来源，就**离不开你**（他无法自己去订阅）
2. **合规减负**：原文不出平台，就不存在"二次分发第三方内容"的版权风险

> 这也解释了为什么**取消导出是对的**：导出只是把"来源可复制"从接口层挪到了截图层。
> **一起关掉才闭环。**

## 5. 交付形态与准入门槛

### 5.1 交付形态：多租户 SaaS

- 设计文档 `docs/PLATFORM_MULTI_TENANCY_DESIGN.md`（**315KB / 4440 行**），含 `dim_tier` 三档表、
  资源配额、并发与限流、会话与凭证、审计与不可篡改
- 注册 → 邮箱验证 → 落 `pending` → **管理员审批**才能登录
- 审计日志保留期**≥6 个月**（法律依据见下）

### 5.2 准入：个人开发者的真实门槛

| 门槛 | 事实 | 结论 |
|---|---|---|
| **短信** | 阿里云官方："**仅企业资质才可以进行报备和发送短信**"；个人认证只能用"他用资质"（需企业证照 + 委托授权书）；签名实名报备 **5~10 个工作日**（上线阻塞） | **本轮只做邮箱**（SMTP 免费且无准入），短信后置（决策 D32） |
| 企业资质 | 需营业执照；短信签名要企业资质 | 后续若要短信/发票/对公，得注册主体 |

### 5.3 法条引用纪律（尽调时会直接问"哪一条"）

| ❌ 常见误引 | ✅ 正确 |
|---|---|
| "等保 2.0 要求日志留存 6 个月" | 6 个月出自《**网络安全法**》**第二十一条第（三）项**；等保 2.0（GB/T 22239-2019）是**付费标准**，未取得可公开引用正文，**不引用** |
| 《**证券期货**经营机构信息技术管理办法》 | 《**证券基金**经营机构信息技术管理办法》（证监会令第 **152** 号，2021 经第 179 号修订） |
| "审计日志留存 20 年" | 第十六条是"**审计报告**保存 ≥ 20 年"；**原始日志**下限是《网络安全法》的 6 个月 —— 两者不是一回事 |
| "规章要求双人复核" | 证券期货规章**没有"双人复核"措辞**；强制依据是第三十二条"**岗位相互制衡 / 开发测试运维分离**"，通用定义引 NIST SP 800-53 AC-5 |

## 6. 「值多少钱」该怎么答（价值锚点与折价因素）

> ⚠️ 本文**不给具体报价** —— 那需要可比交易与买方类型，不是从代码里能推出来的。
> 但下面这张表是**任何报价都绕不开的**：左边决定能报多少，右边决定要折多少。

### 6.1 值钱的部分（买方实际买什么）

| 锚点 | 内容 | 为什么值钱 |
|---|---|---|
| **私域信息源** | 知识星球调研 + 券商研报 + 8 个公开快讯源的聚合 | 买方自己拿不到；且按设计**他永远看不到来源**，形成锁定 |
| **加工链** | 可信度分层（来源分/内容分/佐证数）、倾向抽取（规则×模型交叉验证）、相似新闻聚合、平台热议 | 把"一堆文本"变成"可复算指标"，这才是可交付物 |
| **合规姿态** | 数据+公式、四条硬约束、契约层无 target_price/rating、违禁措辞扫描 0 命中 | 买方最怕的是买来一个**不能上线**的东西 |
| **工程完成度** | 三层门权限矩阵、多租户、LLM 网关（分层路由/语义缓存/熔断/审计）、多源降级链、告警三闸门 | 这些是通用能力，可迁移到买方自己别的产品 |
| **可复算性** | 公式与参数公开、因子/IC 序列可导出、每个数字点开能看构成 | 买方风控/合规会查这一条 |

### 6.2 必须折价的部分（买方尽调一定会挖）

| 折价项 | 现状 | 影响 |
|---|---|---|
| **单点依赖** | 私域源 token 会过期（有到期提醒，剩余 11 天那种） | 最脆的一环：断供即产品失效 |
| **单机架构** | SQLite 单写者；零停机需 Postgres + Redis（**前置条件不能往后排**） | 买方若要 SLA，需先做存储外置 |
| **个人主体** | 无牌照、无企业资质 | 买方要么自己持牌承接，要么只买技术资产 |
| **数据合规** | 私域源是"付费入群"获取，原文**不出平台** | 若要出原文，版权与授权要重新评估 |
| **未清零的红灯** | 8 条告警阈值配置漂移的测试长期红 | 尽调时会被读成"已知缺陷未处理" |
| **覆盖率** | 平台热榜 4/6（雪球 3 接口全挂、韭研无免费接口） | 宣传口径不能写"六大平台全覆盖" |

### 6.3 三种买方与卖法

| 买方 | 他买什么 | 卖法 |
|---|---|---|
| **私募 / 资管** | 自用的信息与筛选能力 | 订阅制（三档 + 单点加购）；**不卖导出**，客户离不开你的源 |
| **券商 / 持牌机构** | 技术资产（他有牌照，你没有） | 技术授权 / 定制交付；合规基线可放宽到"由持牌方出意见" |
| **同业 / 独立开发者** | 整套系统 | 源码转让；此时"来源保密"变成**要交接的资产**（token 与订阅关系要一并转移） |
