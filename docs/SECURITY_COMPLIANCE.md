# 安全合规设计

## 一、设计原则

- **零信任架构**：不信任任何内部或外部网络，所有访问请求必须经过身份验证和授权决策。
- **数据分级驱动权限**：数据的访问权限由其安全级别决定。
- **审计不可篡改**：所有操作日志独立存储、防篡改、可追溯。

## 二、数据分级（四级制）

| 级别 | 定义 | 示例 | 访问要求 |
|------|------|------|----------|
| 核心数据 | 泄露对国家安全/经济运行造成特别严重危害 | 未公开政策预判、核心策略逻辑 | 双人审批、物理隔离 |
| 重要数据 | 泄露对经济运行/公共利益造成严重危害 | 产业链图谱、内部研报 | 角色管控、加密传输 |
| 敏感一般数据 | 泄露对组织权益造成一般危害 | 个股分析报告、财务数据 | 权限管控 |
| 常规一般数据 | 泄露危害较低 | 公开行情、已发布研报摘要 | 基础访问控制 |

## 三、多租户隔离

- **隔离模型**：共享表 + 行级安全策略（RLS）+ 独立Schema命名空间。
- **权限模型**：RBAC + ABAC 混合。
- **审计日志**：独立存储、防篡改、保留≥3年。

## 四、安全红线

- 禁止硬编码API Key、数据库密码、Token。
- 禁止在日志中输出用户隐私数据、完整Prompt内容、模型原始响应。
- 所有LLM输出必须附带置信度评分和免责声明。
- 核心数据的访问必须触发双人审批流程。

## 五、合规检查清单

- [ ] 所有输出附带免责声明
- [ ] 多租户数据通过RLS自动隔离
- [ ] 审计日志独立存储，不可篡改
- [ ] 敏感数据操作日志保存不低于3年
- [ ] 无硬编码敏感信息
- [ ] 所有数据库查询使用参数化/ORM
- [ ] 所有数据点携带溯源元数据
