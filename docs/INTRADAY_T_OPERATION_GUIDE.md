## 1. 界面结构与数据节奏

### 1.1 界面结构（2026-09-17 自选改左侧滑动窗口 · 2026-09-23 模块页签上移顶部、周期条并入抬头行）

```
┌─ 模块页签：[量化选股] [竞价选股] [做T辅助]  ← 三个同级模块并列（2026-09-23）
├─ 工具栏：☰自选 · 股票做T辅助 · 代码框/切换标的/加减自选/关联板块(带联想)/海外映射 ·
│           强制刷新 · 阈值回测 · 权重编辑 · 实时推送 · 更新时间
├─ 提示条（可关闭，9 秒自动消失）
└─ 两栏工作区
   ┌──────────────┬─────────────────────────────────────────────┐
   │ 自选（滑动窗口）│ 抬头：名称 代码 现价 涨跌·低吸/高抛/止损 周期[分时|日K] │
   │  ☰ 可收起      ├─────────────────────────────────────────────┤
   │  ⟳ 报价5s/打分60s│ ① 估值空间      ② 分时图与提示点（含档位口径/拟合）│
   │ 中国船舶 600150 │                                             │
   │ −0.71% 分+2 观望│ ③ 多指标合成打分                             │
   │ 中际旭创 300308 │                                             │
   │ +0.54% 分+7 观望│                                             │
   │ …（列表内滚动）  │ ④ 消息面与市场情绪                            │
   └──────────────┴─────────────────────────────────────────────┘
```

**为什么模块页签在顶部**：`量化选股` / `竞价选股` 是**组合级**模块（不针对某一只票），
`做T辅助` 是**个股级**模块 —— 三者层级相同。2026-09-23 之前它们分别被塞在
做T面板的「周期」条里和它右边，看起来像做T的两种"周期"，用户反馈层级混乱；
现在统一上移到顶部并列，做T内部的「周期」条只剩 `日内分时 / 日K` 两项
（它们确实只是做T的两种口径）。切页签 = 换模块，页签在三个模块下都在。

**为什么「周期」与抬头同一行**（2026-09-23 用户口径：同排、放抬头右侧）：
它们原本是上下两行，在 1080p 上白吃掉一整行高度、把下面的估值与分时图整体往下推。
现在抬头占满剩余宽度、「周期」贴在它右侧（窄屏放不下时自动回落成两行）。
顺带把日K模式那句长提示收进了 `日K` 按钮的悬浮说明 —— 摆在行内会把这一行挤回两行。

**为什么自选是滑动窗口**：自选原来是一行横向平铺的胶囊，十几只票会占掉 2~3 行高度，
每加一只就再挤一行，把图越挤越矮（用户报障「容不下较多自选股」）。
现在改成**左侧滑动窗口**（参考同花顺持仓栏）：列表在自己的区域内滚动，
无论多少只票都不再影响图的高度；窄屏（<1180px）时它变成浮层，
点选一只票会自动收起。

| 操作 | 位置 | 说明 |
|---|---|---|
| 切换模块 | 页面顶部 **`量化选股` / `竞价选股` / `做T辅助`** | 三个同级模块；切到组合级模块时，个股级控件（代码框/加自选/权重编辑等）会整排收起 —— 它们不作用于选股结果 |
| 展开 / 收起自选 | 工具栏最左 **`☰ 自选 N`** 按钮，或抽屉头部的 `‹` | 状态记在浏览器本地，下次打开保持；窄屏默认收起 |

### 1.2 四个面板

| 面板 | 回答的问题 | 关键字段 |
|---|---|---|
| ① 估值空间 | 这只票还有没有上涨空间（估值是否透支） | PE/PB 三年分位、同业中位、`headroom`（充足/中等/透支/偏贵） |
| ② 分时图与提示点 | **在哪个价位动手**：三角=信号，虚线=低吸/高抛/止损/箱体 | `levels`、`markers`、`score_series`、`level_series` |
| ③ 多指标合成打分 | **够不够格动手**：14 因子加权总分 + 区间 + 触发原因 | `total`、`factors[]`、`available_weight`、`verdict` |
| ④ 消息面与市场情绪 | 板块涨跌家数、相对强度、大盘状态、新闻 NLP | `sentiment`、`news` |

## 2. 分数是怎么算出来的（③ 打分面板）

### 2.1 一条公式

```
总分 = Σ( 因子得分 × 权重 )        ∈ [-100, +100]
因子得分 ∈ [-1, +1]                 权重合计必须 = 100
贡献分 = 得分 × 权重                表格逐行相加**恰好等于**总分
```

打分表每一行显示：`权重`、`得分[-1,1]`、`贡献分`、`计算依据`（人话解释 + 中间量）。
点「查看各因子中间量（可溯源）」可以看到每个因子的原始输入。

### 2.2 十四因子（分时做T）默认权重

| 分组 | 因子 | 默认权重 | 口径一句话 |
|---|---|---|---|
| 价格结构 | 箱体/压力位 `box` | **17** | 现价在近 N 日箱体中的位置（越靠下越偏多） |
| 价格结构 | 布林带 `boll` | 8 | 当日分钟布林 %B 与带宽收口 |
| 价格结构 | 缠论结构 `chan`（技能） | 12 | 相对最后一个笔中枢的位置 + 背驰强度 |
| 量能筹码 | VWAP偏离 `vwap` | 11 | 现价相对当日分时均价的标准偏离 z |
| 量能筹码 | 筹码量能结构 `chip`（技能） | 8 | 量能进度 × 放量位置 × 换手活跃度 |
| 动量指标 | MACD `macd` | 6 | 5 分钟 0.6 + 日线 0.4 |
| 动量指标 | KDJ/RSI `kdj_rsi` | 6 | 30 分钟与日线各半 |
| 市场环境 | 市场情绪 `sentiment` | 6 | 板块涨跌家数占比 + 相对板块强度 |
| 市场环境 | 指数量能 `index_volume` | 6 | 量能只**放大**方向，不单独给方向 |
| 市场环境 | 板块涨幅排行 `board_rank` | 4 | 全 A 板块涨幅排名分位（需绑定关联板块） |
| 市场环境 | 海外映射 `overseas` | 4 | 美股隔夜 0.75 + 韩股盘中 0.25 |
| 市场环境 | 市场情绪周期 `cycle`（技能） | 6 | 涨停家数/炸板率/最高连板 → 温度（**实时**） |
| 个股特性 | 消息面 `news` | 3 | LLM 情绪分 0.6 + 偏多偏空计数 0.4 |
| 个股特性 | 股性适配 `character`（技能） | 3 | 偏离按该股自身日 ATR 归一化 |

> 日K做T 是另一套 7 因子目录（趋势/缠论买卖点/量价/位置/规则信号/情绪周期/股性），
> 在「权重编辑」弹窗里切到「日线做T（7因子）」标签。

### 2.3 阈值与信号（两条腿同时满足才出手）

```
提示线 hint  ±20：|总分| ≥ 20 且价格触及档位 → 空心三角（小仓位试仓）
动手线 action ±30：|总分| ≥ 30 且价格触及档位 → 实心三角（正式动手）
止损位        ：现价 ≤ 止损位 → ⛔强制卖出警告，且**禁止一切低吸信号**
```

「价格触及档位」的判定（与图上三角、与回测同一口径）：

- 低吸：`现价 ≤ 低吸线 × (1 + 贴线带宽0.3%)`，或 `VWAP偏离 z ≤ -1.5`
- 高抛：`现价 ≥ 高抛线 × (1 − 贴线带宽0.3%)`，或 `VWAP偏离 z ≥ 1.5`

**有效权重护栏**：某个因子当天取不到数据（缺口）时，它的贡献分记 0、权重从
`有效权重`中扣除，并在表里标灰。`有效权重 < 70` 时**禁止实心正式信号**
（自动降级为空心），因为"缺了最高权重的那个维度却照样打满分"是最危险的误判。

## 3. 低吸线 / 高抛线 / 止损位是怎么定的（② 面板）

这三条线与**因子权重完全无关**。它们只看行情结构与你设的**档位参数**。

### 3.1 低吸线

```
低吸线 = max( 箱体下沿 , 布林下轨[若在现价下方] )
        ↓ 档位差护栏（min_band_pct / max_band_pct）
        ↓ 若仍落在现价上方 → ATR 兜底：现价 − dip_fallback_atr × ATR
```

三个反直觉点，面板上都会写明：

1. **布林轨是当日分钟口径**：强势股刚突破时 20 根 bar 带宽会窄到 1% 以内，
   下轨会跑到现价**上方**。所以只采纳"确实在现价下方"的下轨，否则那不是支撑。
2. **跳空高开时低吸线必须重新定位**：箱体下沿与布林下轨都在现价上方时，
   不能把线钉在现价附近（贴线判定是 `price ≤ low ×(1+带宽)`，
   `0.997×1.003≈1` 会让低吸信号永远差一线、实际被做死）。正确做法是按
   **波动率**给一个真实可触及的位置（现价下方 `dip_fallback_atr×ATR`）。
3. **档位差护栏**：`min_band_pct`（默认 1.5%）保证一轮做T不被双边成本吃光
   （佣金+印花税+滑点 ≈ 0.2%）；`max_band_pct`（默认 8%）保证箱体过宽时
   线不会远到永不触发。夹过之后面板会写「被最小/最大档位差 …（候选 a~b）」。

### 3.2 高抛线

```
高抛线 = min( 箱体上沿 × (1 + take_profit_buffer_pct%) , 布林上轨[若在现价上方] )
        ↓ 同样的档位差护栏
```

### 3.3 止损位

```
止损距离 = max( 低吸线 × stop_loss_pct% , atr_stop_mult × ATR )   ← 取更宽的那个
止损位  = 低吸线 − 止损距离
```

为什么取 max：高波动股（如 ATR 占价 5.8%）用固定 1% 的止损距离只有几块钱，
任何噪声都能打穿，早盘会反复报"已跌破止损"。
面板上 `止损 889.64` 会附带 `stop_basis`：例如
`低吸线下方 1%；当日最低 866.66` 或 `低吸线下方 0.5×ATR（ATR=52.82，大于 4% 的…）`。

### 3.4 ⚠️ 档位是**时刻量**，不是全天恒定

低吸/高抛/止损随 VWAP、布林、现价**每分钟重算**。实测 300308 当日低吸线
从 862 一路抬到 898。因此：

- 图上那条横线画的是**当前值**，右端标签才是现在的数；
- 与横线并存的还有一条**随时间漂移的曲线**（同一个颜色的虚线）：曲线回答
  "这条线今天怎么走的"，横线回答"此刻它在哪"。**两条一起看**才不会误读；
- 「今天触及低吸线几次」是按**每根 5 分钟 bar 当时的线**判定的（就是那条曲线）；

**别拿当前值去回看早盘。**

### 3.5 图上怎么读数值（十字光标）

鼠标移进图里即出现十字光标（离开即消失）：

| 位置 | 显示什么 |
|---|---|
| 横线 + 左轴小标签 | 鼠标所指价位（带底色的小标签，直接读，不用去右轴对） |
| 横线 + 右轴小标签 | 该价位的涨跌幅（红=涨 / 绿=跌，与面板其余部分同色系） |
| 纵线 + 下轴小标签 | 吸附到的分钟时刻（`09:35` 这类） |
| 图下方读数条 | `时间 · 价 · 涨跌% · 均价(VWAP) · 偏离%`，以及 **`光标 <价> <涨跌%>`**（横线那一点） |
| 读数条右侧 | **光标价距三条档位线的百分比**：`高抛 +2.85% 低吸 −1.72% 止损 −5.19%` |

最后一项是做T时最常问的一句话："现在这个价，离低吸/高抛还有几个点。"
（纵线吸附到最近的分钟数据点，横线跟鼠标自由走 —— 前者为读时间，后者为读价位。）

### 3.5b 日K主图怎么读数值（十字光标 + 浮层读数）

日K（量价体系 + 擒牛线）主图同样"鼠标移进去就出数"，但要读的是**日线**口径
（2026-09-23 按用户口径补全）：

| 位置 | 显示什么 |
|---|---|
| 竖线 + 下轴蓝色标签 | 吸附到的那根日K的**日期**（轴上 `07-15`，浮层里给完整 `2026-07-15`） |
| 横线 + 右轴蓝色标签 | **光标当前高度对应的价格**（横线跟鼠标上下走，不是钉在收盘价上） |
| 跟着鼠标的浮层读数框 | `日期 · 光标价 · 开/收 · 最高 · 最低 · 涨跌幅 · 量 · 换手 · 资金`（红=涨 / 绿=跌，与面板同色系） |
| 图下方读数条 | 同一根bar的完整读数 + 五条擒牛线的数值（SMX / CBX20 / CBX60 / NML / QRL） |

浮层贴着图的右/下边缘时会自动翻到光标另一侧，不会跑出图外；鼠标移出图外即消失。
滚轮缩放、拖拽平移、双击复位与分时图一致。

其中三项的口径要说清楚（2026-09-23 新增）：

| 栏 | 口径 | 缺值时 |
|---|---|---|
| **量** | 该日成交量，单位**手**（>1万手显示为「x.xx万手」） | 不会缺 |
| **换手** | 换手率 % = 成交量 ÷ 流通股本，来自**本地行情仓** `quant_daily_basic.turnover_rate`（日频定稿） | 显示 `—`：当日那根**形成中bar**（T-1 定稿尚未生成）或该标的无数据 |
| **资金** | 主力资金**净流入额**（正=流入 / 负=流出），来自本地行情仓 `quant_moneyflow.net_mf_amount` | 同上 |

### 3.5c 量一段区间（区间测量）

日K主图可以**框选一段日K**来看这区间的统计量（2026-09-23 新增）：

- 打开方式：工具栏点 **`区间测量`**（点亮后拖拽即框选），或**随时按住 Shift 拖拽**；
- 选中后图上出现半透明选区，浮层给出：

| 项 | 口径 |
|---|---|
| 区间交易日 | 选区内的bar数（交易日，不是自然日） |
| 区间涨跌 | **首收 → 末收**的涨跌幅（与行情软件口径一致） |
| 区间最高 / 最低 | 选区内所有bar的最高价 / 最低价 |
| 换手合计 | 选区内**每日换手率之和**（%）；当日形成中bar没有换手率，会标出「n/m 根」 |
| 区间净流入 / 净流出 | 选区内 `net_mf_amount` 之和（亿元）。**正值显示为「区间净流入」、负值为「区间净流出」** |

清除方式：框上的 `×`、按 `Esc`、双击图面，或再点一次 `区间测量` 关掉这个模式。
拖拽平移不受影响 —— 只有开了测量模式（或按住 Shift）时，拖拽才变成框选。

> 这两项（换手率、资金净流入）**只用于读数与区间统计，不参与打分与买卖信号**。
> 原因：`character.py` 与 `daily_signals.py` 里都有"日线没有换手率列就跳过该项"的分支，
> 一旦把它们喂进规则引擎，会**同时改掉股性分与买卖标记** —— 那是需要单独评估、单独回归的另一件事。

### 3.6 三条线没画出来？先看这三处

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 某条线完全不见 | ① **图外**：该档位超出当前 Y 轴范围（止损离现价远时最常见）。这时图的上/下边缘会出现一条贴边虚线 + `止损 860.40（−5.19%）↓在图下方` | 点档位清单里的「图外档位也纳入Y轴」，或放大时间窗让 Y 轴自动重算 |
| 某条线被关掉了 | 档位清单里那一条的复选框被取消（显示为虚线框 + 删除线） | 重新勾选 |
| 早期版本的显示问题 | 档位线只给了 CSS 类名而 SVG `<path>`/`<line>` 没有显式 `stroke`，会按 SVG 默认 `stroke:none` 渲染 —— 数据在、但一个像素都不画 | 已在 2026-09-17 修复（显式内联 stroke + 覆盖 `path` 的选择器），刷新页面即可 |

档位清单里每条都带勾选框：默认全开；关掉后该线变虚线框并打上删除线，
取消即可恢复。**「（图外）」标记与贴边指示线都是为了不把图压扁**——
若强行把 5% 以外的止损纳入定标，全天分时会被压成中间一条细带。

## 3.7 档位是"算出来的"还是"拟合出来的"（神经网络拟合）

图下方那条 `档位口径：…` 就是答案。两种口径：

| 显示 | 含义 |
|---|---|
| **规则口径** | 档位按 §3.1~3.3 的公式算：箱体/布林/VWAP/ATR + 你设的档位参数 |
| **神经网络拟合** | 用这只票自己的历史**拟合**出来的三条线（见下），并叠加了调整项 |

### 3.7.1 拟合用哪些数据、怎么拟合

- **参与拟合的 7 个客观维度**（用户口径的"优先使用"）：
  筹码量能结构 · 箱体/压力位 · 缠论结构 · VWAP偏离 · 布林带 · MACD · KDJ/RSI；
- **拟合产物**：低吸/高抛/止损三条线，记成"相对**当日均价**的偏离百分比"
  （例如 `低吸 −1.40% / 高抛 +1.60% / 止损 −4.0%`），面板会把它们换算成价格显示；
- **其余 7 个维度只做微调**（不参与拟合）：指数量能、股性 → 结构乘数；
  市场情绪、情绪周期、海外映射、板块排行 → 环境乘数；消息面 → 微观乘数。
  每个乘数夹在 0.5~1.5，面板上显示为 `调整项 结构 ×1.07 / 环境 ×1.01 / 微观 ×1.13`。

### 3.7.2 「过去 10 个交易日做T成功率」怎么算

一轮做T的判定（与图上的三角、与阈值回测同一套口径）：

```
触及：某根 5 分钟 bar 的最低价 ≤ 低吸线
成功：触及之后的 24 根 bar（=2 小时）内，先摸到高抛线，且全程没跌破止损位
失败：先跌破止损位；或 2 小时内没到高抛（时间止损，只亏摩擦成本）
成功率 = 成功次数 ÷ 触及次数      ← 只算"触及过"的样本
```

⚠️ **前瞻不跨交易日**：做T当日事当日毕，隔夜跳空不算做T成功。

### 3.7.3 三个数必须一起看（面板上并排显示）

| 数字 | 含义 | 怎么用 |
|---|---|---|
| **样本内** `xx%` | 在**拟合用的那些天**上的成功率 | 这是"过去 N 个交易日成功率"的字面答案 |
| **留一日** `xx%` | 留一天不参与拟合、只用来验证（逐日轮换） | **这个数才决定能不能信它**。只看样本内一定会被过拟合骗 |
| **可达上限** `xx%` | 把搜索放宽到极致、这段行情里能达到的最高成功率 | 回答"是没搜到，还是本来就不行" |

**启用闸门**：只有「留一日 ≥ 80%」且「触及样本 ≥ 20 次」时，才会用拟合线当档位；
否则**自动回退规则口径**，并在面板上写明原因。这条闸门的用意：宁可告诉你
"这只票拟合不出 80%，我用规则口径"，也不拿一个过拟合的 80% 去指导真金白银的下单。

### 3.7.4 实测参考（300308 / 2026-09-17，8~10 个交易日 / 320~435 根 5 分钟 bar）

| 指标 | 实测 |
|---|---|
| 样本内成功率 | 34~39% |
| 留一日成功率 | 30~38% |
| 可达上限 | 71~80%（最优点常是"低吸 1.4% / 高抛 1.6% / 止损 4%"，仅 35 次触及） |
| 闸门 | 未通过 → 档位走规则口径 |
| 单次拟合耗时 | 0.8~4.9 秒（按交易日缓存，盘中不会每 15 秒重训） |

**怎么读这几个数**：80% 是**目标**而不是承诺。当"可达上限"也低于 80% 时，
说明这段行情里**不存在**成功率 80% 的做T结构 —— 硬要凑 80% 只能把止损放到很宽、
样本压到极少（那种 80% 是过拟合）。这时系统的选择是：退回规则口径 + 把真实数字
摆给你看，而不是给你一个漂亮但不可复现的百分比。

### 3.7.5 怎么操作

- 图下方 `档位口径：…` 后面就是两个按钮：
  **「重新拟合」**（用这只票自己的历史重训一次，约 1~5 秒，成功后档位立即按新线显示）
  与 **「查看依据」**（展开：两个成功率、可达上限、拟合线、调整项乘数、
  以及样本窗口/ATR口径/数据来源等全部 notes）；
- 拟合结果按交易日缓存，切换标的会自动用缓存，不必反复重训；
- 每只票各拟合一套 —— A 票的档位参数不会跑到 B 票上（这是"每个个股都要拟合"的落点）。

## 4. 权重编辑面板（重点）

点工具栏「权重编辑」打开。它做四件事：**改权重 / 改阈值与档位 / 看影响 / 存档案**。

```
┌──────────────────────────┬──────────────────────────────┐
│ 左列：因子权重表          │ 右列：权重模板（一键套配方）   │
│  · Σ权重 + 一键归一化     │  · 按股性推荐（用该票历史）    │
│  · 显示公式（每项口径）   │  · 实时价格线影响  ★新增★     │
│  · 阈值与档位折叠区       │  · 预览分数（不落库）          │
│  · 市场情绪周期条 ★新增★  │  · 保存到数据库                │
└──────────────────────────┴──────────────────────────────┘
```

### 4.1 三条不可动摇的口径

| 口径 | 为什么 |
|---|---|
| **权重合计必须 = 100** | 总分刻度 `[-100,100]` 与 ±20/±30 阈值全靠它。合计 120 时阈值全部失效，而你看不出来 |
| **保存只提交差集** | 档案是"这只票相对全局口径的差异"。提交全量会把全局默认值固化进这只票，以后调全局它不跟着变 |
| **预览不落库** | 拖滑杆要的是"立刻看到会变成什么"，不该因此改动任何持久状态 |

### 4.2 左列：权重表

- 每行：因子名（带「技能」角标=来自交易技能库）+ 权重数字框 + 滑杆 + **贡献提示**
  （`6 / 100 分 · 未改动` 或 `8 / 100 分 · 原 6（+2）`）。
- 点「显示公式」展开每项的公式与数据来源（服务端目录提供，前端不写死）。
- `Σ权重` 变成红色时无法保存 —— 点「一键归一化」按比例缩放到恰好 100
  （你刻意置 0 的维度保持 0）。
- 「市场情绪周期」那一行带一个绿色**实时**徽标，鼠标悬停显示本次取到的
  涨停家数/炸板家数/最高连板/温度；其下方还有一条实时周期条。

### 4.3 左列：阈值与档位折叠区

| 参数 | 默认 | 它直接影响什么 |
|---|---|---|
| 动手线 `action` | 30 | 实心正式信号门槛（图上实心三角） |
| 提示线 `hint` | 20 | 空心软提示门槛 |
| `min_band_pct` / `max_band_pct` | 1.5 / 8 | 低吸~高抛的档位差上下限（护栏） |
| `stop_loss_pct` | 1.0 | 止损距离的百分比口径 |
| `atr_stop_mult` | 0.5 | 止损距离的 ATR 口径（与百分比取更宽者；填 0=只用百分比） |
| `dip_fallback_atr` | 0.3 | 低吸线兜底距离（×ATR），跳空高开时用 |
| `take_profit_buffer_pct` | 0.0 | 高抛线整体上移/下移（负值=允许提前减） |
| `touch_band_pct` | 0.3 | 「贴线即算触及」的容差（太小等不到，太大信号失焦） |
| `vwap_extreme_z` | 1.5 | \|z\|≥该值视为等效触及档位（VWAP 极值口径） |
| `blend_boll_bands` | true | 只读展示：布尔开关不能在面板改（后端 `levels` 是数值字段） |

### 4.4 右列：实时价格线影响（本次新增，回答"会变成多少"）

打开面板后**改任何数字都会自动重算**（防抖 0.8 秒；也可点「立即重算」）。
面板显式标出过期状态：「表单已改动，待重算」。

它给出四块内容：

**① 本次口径的概览 chips**：现价 / 总分 / 动手线 / 提示线 / 有效权重。

**② 档位刻度**：一条相对现价的横轴（50% = 现价），三条线按位置打点
（绿=低吸、红=高抛、黄=止损），一眼看出"线离现价多远"。

**③ 价格线对照表**

| 列 | 含义 |
|---|---|
| 价格线 | 高抛线 / 低吸线 / 止损位 / 当日均价 / 布林轨 |
| 改动前 | **打开面板那一刻**这条线的位置（前端把面板上的值回传给服务端算，缺基准时显示 —） |
| 改动后 | 你当前表单参数下的位置 |
| 变动 | 差值 + 百分比：例如 `+6.81（+0.75%）`；显示 `0.00 未变` 表示这条线没被你的改动碰到 |
| 离现价 | `−1.01%` 表示这条线在现价下方 1.01% |
| 触发价（触及） | 低吸线 ×(1+带宽) / 高抛线 ×(1−带宽)，即"价格到多少算触及" |
| 由谁决定 / 说明 | 例如 `布林下轨 902.35（与箱体下沿 898.72 中取高者）` |

> ⚠️ 三条线是**时刻量**（随 VWAP/布林/现价每分钟重算），所以"改动前"是你打开面板
> 那一刻的值，盘中会随时间小幅漂移 —— 那是行情在动，不是你的参数改出来的。

**④ 触发门槛表**

| 列 | 含义 |
|---|---|
| 可否动手 | ✓ 条件已满足 / ✗ 未满足（并给出被谁拦住） |
| 还差分 | 距**提示线**还差多少分（0 = 已过线） |
| 还差价 | 价格还要走多少 %（负=还要往下跌）到触及线 |
| 推导 | 完整人话推导，例如：`总分 +2.6，距提示线 +20 还差 17.4 分，距动手线 +30 还差 27.4 分；价格需再跌 0.71% 到 901.32 才触及低吸线` |

**⑤ 因子影响度表**（回答"每个因子影响多大"）

| 列 | 含义 |
|---|---|
| 权重 | 当前权重 |
| 得分 | 该因子今天的原始分 ∈[-1,1] |
| 贡献分 | 得分×权重（逐行相加 = 总分） |
| **每+1分权重** | **= 该因子得分**：权重每加 1 分，总分被推动多少。**负得分意味着"加权反而拉低总分"** |
| **权重置0** | 把这一项权重设为 0 后总分的变化（"关掉它"的净影响） |
| 占有效权重 | 该权重占**有效权重**的比例（有缺口时合计>100%，这是对的） |

> 影响度按 `|每+1分权重|` 降序，只列前 6 项；完整 14 项在「预览分数」的全量表里。

### 4.5 权重模板（一键套配方）

`均衡（默认）` / `震荡回归型` / `趋势跟随型` / `高换手题材·连板` /
`低波动钝化型` / `原始十因子口径(legacy)`。
模板是整套已归一化到 100 的配方，选中即整体覆盖表单，之后仍可逐项微调。

### 4.6 按股性推荐（用这只票自己的历史）

按该股近 120~250 日的**振幅 / ATR / 涨停基因 / 趋势效率**推荐一套权重与档位，
并给出「做T友好度 / 股性 / 形态（震荡/趋势/混合）/ 日均振幅」等画像 chips。
推荐值只是**起点**：填进表单后仍要自己确认再保存。日线样本不足时按钮禁用并说明原因
（**绝不猜着填**）。

### 4.7 保存与生效

- 「保存到数据库」只写入改动项（面板会列出本次提交的 N 项）；
- 保存后**立即生效**：该票的打分与档位改用这份口径，其他标的仍走全局口径；
- 优先级：**数据库权重档案 > `configs/intraday.yaml` 的 `overrides.<code>` > 全局配置**；
  主面板打分表上方会写明当前用的是哪一份（"本票口径：权重档案（…）"）；
- 「载入档案」下拉可把任意已存档案载进表单（以接口给的**实际生效口径**为准）。

## 5. 完整影响链路图（把两条链路合起来读）

```
                      ┌─────────────── 因子权重（权重编辑 左列）───────────────┐
                      │  合计必须 = 100；权重只影响"分数"，不移动任何价格线     │
                      ▼
   14 个因子今日得分 ──×权重──► 总分 ∈[-100,100] ──┬─ |总分| ≥ 提示线 20 ─► 空心三角（试仓）
   （实时行情算出，改权重不改得分）                └─ |总分| ≥ 动手线 30 ─► 实心三角（正式动手）
                                                        ▲
                                                        │ 两条腿必须同时满足
                                                        ▼
   箱体 / 布林 / VWAP / ATR ──► 低吸线・高抛线・止损位 ──► 价格"触及"档位
        ＋ 档位参数（阈值与档位折叠区）      ▲
                                           └── 档位参数**只**影响这三条线（与止损距离、护栏）
```

**一句话记忆**：
**权重 → 总分 → 够不够格动手；档位参数 → 价格线 → 在哪个价位动手。**

因此：

- 调权重：价格线**纹丝不动**，变的是总分、区间（偏多低吸区/震荡区间/…）、
  触发门槛里的「还差分」、以及图上信号由空心变实心（或反过来）。
- 调档位参数（如 `stop_loss_pct`）：总分**纹丝不动**，变的是止损位/低吸线/高抛线
  与「还差价」、「触发价」。

## 6. 「市场情绪周期」是实时算的，不是写死的

这是**市场级**因子，专门回答"今天这个环境适不适合做T"（做T是顺周期动作，
同一套规则在主升期与退潮期的胜率差一个数量级）。

### 6.1 数据来源与实时性

| 项 | 来源 | 刷新 |
|---|---|---|
| 涨停家数、首板/连板家数、最高连板 | 东财**涨停池**（akshare `stock_zt_pool_em`） | 盘中实时，60 秒 TTL |
| 炸板家数 = 炸板率分子 | 东财**炸板池**（`stock_zt_pool_zbgc_em`） | 同上 |
| 跌停家数、大面家数 | 东财**跌停池** + 炸板股跌幅 ≤ −9% | 同上 |
| 强势力池（参考） | `stock_zt_pool_strong_em` | 同上 |

实测（2026-09-17 08:55）：`涨停 89 家（首板 77 / 连板 12）· 炸板 11 家（炸板率 11%）
· 跌停 4 家 · 大面 4 家 · 最高 6 板 → 阶段「主升期」，做T环境温度 88/100`。

**取不到时如实记缺口并置"不可用"，绝不拿上一次的数据冒充今天** ——
周期阶段错一天，退潮期就会被当成震荡期放开做T，这是会造成实际亏损的那类错误。

### 6.2 阶段判定（风险优先，不是"涨停多就安全"）

```
① 一票否决：大面 ≥ 10 家 / 跌停 > 10 家
② 退潮：炸板率 > 60%  或  涨停 < 15 家  或  存在一票否决
③ 冰点：最高连板 ≤ 2 且 连板家数 < 4
④ 主升期：涨停 ≥ 60 且 最高连板 ≥ 5 且 炸板率 < 30%
⑤ 高位震荡期：最高连板 ≥ 5（或涨停多但炸板率不健康）
⑥ 发酵期：涨停 ≥ 30        ⑦ 试错期：其余
```

判定顺序刻意"先看风险"：退潮期的尾巴常常仍有 50+ 家涨停（补涨股在动），
若按涨停家数先判成"发酵期"，就会把最危险的阶段认成最安全的阶段。

### 6.3 温度 → 得分（因子口径）

```
温度 100 → +1（环境极好，低吸胜率高）
温度  50 →  0（中性）
温度   0 → −1（退潮/冰点，做T大概率 T 反）
分段线性：以 neutral_temperature（默认 50）为原点，上下半程各自满量程
```

温度的构成：涨停广度 35 + 承接质量（炸板率反向）25 + 连板身位 25 +
亏钱效应（跌停反向）15。它**不表示看多还是看空**，只表示"今天的做T环境好不好"。

### 6.4 一票否决（安全关键）

`退潮期` / `冰点`（或触发大面/跌停闸门）时：**禁止正式低吸做T**。
总分再高也不会出实心低吸信号，权重编辑面板的「触发门槛」表里会写明被谁拦住。
高抛不受该否决影响（退潮期更需要减仓）。

### 6.5 在哪里看到它

| 位置 | 显示内容 |
|---|---|
| 主面板工具栏下方周期条 | 阶段、温度、是否允许低吸、涨停/跌停/炸板/最高连板、闸门说明 |
| 权重编辑「市场情绪周期」行 | 绿色**实时**徽标 + 悬停详情 |

| ③ 打分表该行 | 得分、贡献分、以及 `周期阶段「主升期」，做T环境温度 88/100 → 适合动手` |

## 7. 三个可复现的调参演示

> 用 300308（2026-09-17 实测）演示"调什么、哪里变、变多少"。

### 演示 A：调权重 → 只动分数，不动价格线

1. 「权重编辑」打开，记下「实时价格线影响」里的 **低吸线 898.63 / 高抛线 912.24 / 止损 889.64**。
2. 把 `市场情绪周期 cycle` 从 6 改到 12（记得把别的项减 6，或点「一键归一化」）。
3. 观察：
   - **价格线对照表**：三条线**一个数都没变**（`变动 +0.00`）；
   - **触发门槛表**：还差分变了（例如低吸从"还差 17.4 分"变成"还差 15.2 分"）；
   - **因子影响度表**：`市场情绪周期` 的「权重置0」从 −4.56 变成 −9.12，
     占比从 6.5% 变成 12.8%。

### 演示 B：调档位参数 → 只动价格线，不动总分

1. 把折叠区里的 `止损下限 stop_loss_pct` 从 1.0 改成 2.5（同时可把 `最小档位差 min_band_pct` 从 1.5 改到 3.0）。
2. 观察（2026-09-17 盘中实测的一组读数）：
   - **总分不变**（例：+14.2 还是 +14.2）；
   - **价格线对照表**出现非零变动：`止损位 889.64 → 865.41（−24.23）`、
     `低吸线 898.63 → 891.82（−6.81）`、`高抛线 912.24 → 919.05（+6.81）`，
     而 `当日均价(VWAP) 893.99 → 893.99（0.00 未变）`——VWAP 不由你的参数决定，
     它显示 0 恰好证明对照表是干净的；
   - 说明列变成 `止损距离取「低吸线×2.5%」与「0.5×ATR」中更宽的那个：低吸线下方
     0.5×ATR（ATR=52.82，大于 2.5% 的 22.29）；当日最低 866.66` ——
     **这就是"为什么改了数字却没怎么动"的答案**：ATR 口径更宽，百分比那支没被采纳。

### 演示 C：调阈值 → 只动门槛，不动线也不动得分

1. 把 `提示线 hint` 从 20 改成 15。
2. 观察：**触发门槛表**的「还差分」立即变小（例：3.7 → 0，`✓ 条件已满足`），
   而价格线、总分、因子影响度全都不变。

## 8. 阈值回测：先验证，再做T

工具栏「阈值回测（先验证再做T）」：在历史 5 分钟序列上复现同一套打分
（全因果指标、无未来函数），统计阈值信号的命中率与平均前瞻收益，并与"随机时点做T"的
全样基准对比。

| 指标 | 怎么看 |
|---|---|
| 动手线 ±30 信号数 / 命中率 | 样本太少（<20）时结论不可信 |
| 平均前瞻收益 vs 全样基准 | **超额为正**才说明这套阈值有信息量 |
| 机械做T（含成本）总收益 / 胜率 / 回撤 | 已扣双边成本；负收益说明这套阈值不适合这只票 |
| 成交明细 | 每笔的入场总分、退出原因（高抛/止损/收盘平仓） |

### 9.1 重启后的"热加载"是什么、怎么关

**做什么**：每次自选概览算完，会把列表（代码/名称/板块/总分/信号/价格/涨跌幅/
置顶）落盘到 `data/cache/intraday/watchlist_snapshot.json`；服务启动时读回来塞进
缓存，并把时间戳标成"已过期"。于是第一个 `/watchlist` 请求立刻返回这份旧列表，
同时后台自动重算一遍 —— 这就是既有的 stale-while-revalidate 分支，没有为热加载
新写一条返回路径。

**为什么这么做**：进程启动其实只要 3.2 秒，慢的是**首批业务请求**（每只票都要
重新取报价/分钟线/板块）。把 59.8 秒从"首个请求"搬到别处没有意义，关键是
**先给旧值**。

**你能看出数据是旧的吗**：能。列表项里的 `quote_ts` 是那一轮的取数时刻，前端
照常显示新鲜度；后端不会伪造时间戳。旧列表超过 24 小时不会被加载（宁可等一次
重算，也不把昨天的价格当今天的展示）；自选池增删过的代码也会从旧快照里剔除，
不会显示已经删掉的票。

**手动清掉热缓存**：删文件即可，下次启动就会走一次完整重算。

```bash
rm data/cache/intraday/watchlist_snapshot.json     # Windows: del /f 同上路径
```

**相关**：板块快照预热与盘后自动选股都**延后 60~90 秒**才开跑（`src/api/main.py`
的 `_BACKGROUND_WARM_DELAY`、`src/intraday/service.py` 的 `_auto_select_loop`）。
原因是它们会起 akshare 子进程、扫磁盘，与服务首屏、`/health` 抢资源 —— 实测
`/health` 因此从 3.7 秒退化成 111.8 秒。延后对做T信号没有影响（板块是展示项 +
14/100 权重；盘后选股 15:05 之后任意时刻跑一次即可）。

| GET | `/api/v1/intraday/snapshot?code=&refresh=` | 完整快照（四面板唯一数据源） |

| GET | `/api/v1/intraday/market-cycle?force=` | 市场情绪周期（实时涨停池口径） |
| GET | `/api/v1/intraday/level-fit?code=&refresh=` | **档位神经网络拟合**：两个成功率 + 可达上限 + 闸门 + 拟合线与调整项乘数 |
| GET | `/api/v1/intraday/character?code=&mode=&refresh=` | 个股股性画像 + 推荐权重/档位 |
| GET/PUT/DELETE | `/api/v1/intraday/weight-profiles[/{code}]` | 权重档案（稀疏差分保存，立即生效） |
| POST | `/api/v1/intraday/weight-profiles/preview` | **预览**：给权重/阈值/档位 → 返回打分卡 + `level_set`（含来源与触发价）+ `impact`（含 `level_deltas`/`gates`/`factor_impact`） |
| POST | `/api/v1/intraday/backtest` | 阈值回测 |
| GET | `/api/v1/intraday/daily?code=` | 日K级别做T（量价体系） |

预览接口返回的 `impact.level_deltas` 就是面板"改动前/改动后"两列的来源，
`impact.gates` 是"还差分/还差价"的来源，`impact.factor_impact` 是"因子影响度"的来源 ——
**面板上看到的每个结论，都能在这一个响应里找到对应的字段**。
