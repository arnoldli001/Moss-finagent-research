# ADR · 规划层（Supervisor Planner）的模型选型

- **状态**：已采纳
- **日期**：2026-09-28
- **触发**：用户提出问题 ——「规划层直接用一个云端免费的快速又不丢质量的模型，
  不就省去了本地模型各种判断？」
- **相关**：`configs/models.yaml` 的 `routing.planning` ·
  `tests/unit/test_planner_budget.py` · `tests/unit/test_gap_and_unlock.py`

---

## Context（背景与约束）

规划层做的事：**读用户问题，从「Agent 能力目录 + 指标目录」里挑一个子集，
输出结构化 plan**。特点是**低频**（每次请求 1 次）、**在关键路径最前端**
（它不返回，后面 19 个节点一个都动不了）。

它此前挂在 `light` 层 = 本地 `qwen2.5:1.5b`（`local_only: true`）。
本机硬件：**RTX 4060，8GB 显存**（`configs/models.yaml` 顶部注释早已登记
"8GB 显存放不下两个 7~8B 模型"）。

实测出的三个问题（全部可复跑）：

| 问题 | 证据 |
|---|---|
| 显存换入挂死 | `supervisor_planner \| in=0 out=0 \| 120294ms`；端到端 123.45s 里这一个节点占 120.31s |
| 输出失控截断 | 同一 prompt 三次：`out=163`（成功）/ `out=1024`（撞 light 上限）/ `out=2048`（撞调大后的上限），报错却是 `LLM输出非合法JSON` |
| 判断成本高 | 要判"显存够不够 / 模型驻没驻留 / 驱逐会不会卡"，才能决定这一跳能不能用 |

## Options（候选）

| 方案 | 延迟 | 成本 | 可靠性 |
|---|---|---|---|
| A. 维持本地 `qwen2.5:1.5b`（现状） | 1.5s ~ 15s（不稳定） | 0 | 换入即挂死；输出会截断 |
| B. 免费云端 `glm-4.7-flash` | p50 **1106ms** | **¥0**（官方定价） | 实测 17% 429（登记值）；**本次 2/2 次 429** |
| C. 付费云端 `deepseek-flash` | **3.5s**（实测） | 付费 | 稳定 |

## Decision（决定）

**规划层改用既有的 `medium` 层**（`[deepseek-flash → local_medium]`），
**不自造新层**。

- 采纳用户的**核心意图**：规划层**离开本地** → 显存那一整类问题消失。
- 否决用户的**成本假设**：「免费」在当前唯一可用的免费档上不成立（见下）。
- **自我否决**「新增 `planning` 层」：见「被否决方案」第 1 条 ——
  它被两条**既有**护栏挡下，且违反 YAGNI。

## Rationale（理由）

1. **离开本地是净收益。** 规划是低频 + 简单任务，不值得为它维护一套显存判断；
   而它挂死的代价是整条链路 120s。
2. **免费档的账算不过来。** 方案 B 在 2/2 次调用上 429 → 每一次都要落到付费备源。
   此时"免费"换来的只有**一次白等的 250ms**，没有任何成本节省，却多了一次失败往返。
3. **既有护栏已经做过这个判断。** `test_glm_concurrency_cap_in_config` 明确禁止
   `glm-4.7-flash` 进入任何路由，依据是实测 17% 失败率。本次证据**支持**该护栏
   （实测比登记的更差），因此**不应**为落地本方案而放宽它 ——
   那正是「为了通过而改判据」。
4. **`medium` 已经是"云端主 + 跨厂商备源"且经验证。** 见下条。
5. **延迟仍然达标。** 端到端实测 **29.09s**（目标 ≤40s），且这一轮
   分析层 A08/A09/A17 **真的跑了**（此前几轮只有规划层一条调用）。

## 被否决方案及原因

| 被否决 | 原因 |
|---|---|
| **自造 `planning` 层** | 被**两条既有护栏**挡下，且违反 YAGNI：<br>① `test_routing_fallbacks_are_cross_provider` —— 熔断器**按 provider** 生效，我配的 `[deepseek-flash, deepseek-v4-pro]` 同厂商，主备会一起被拒，等于没兜底；<br>② `test_glm_concurrency_cap_in_config` —— 唯一另一个跨厂商云端（zhipu 免费档）被禁止。<br>可选的跨厂商备源只剩 ollama（又回本地）。**既有 `medium` 已满足全部要求**，没有理由新增层。 |
| **B：`glm-4.7-flash` 作主模型** | 本次 2/2 次 429（登记值 17%）。100% 回落备源时零节省、纯增一次往返。**且会违反既有护栏。** 复议条件见下 |
| **继续用 `light`（本地）** | 显存换入挂死 120294ms；输出撞上限截断；判断成本高 |
| **删掉 LLM 规划、只用规则式 `plan_run`** | 规划是 PRD 硬需求（"Supervisor 通过 LLM 动态决策任务执行顺序"）；且规则式在长尾问法上明显更差 |
| **调大 `max_tokens` 治截断** | 治不了。它只决定"截在哪"：本地模型 1024 与 2048 两次都恰好填满。真正的解法是 `reasoning_effort="none"`（`deepseek-flash` 的思维链**计入输出预算**，会把正文吃光成空串） |

## 复议条件（什么时候可以改回免费档）

**当且仅当**满足全部三条：

1. `uv run python scripts/probe_glm_concurrency.py --levels 1 --n 20`
   在**冷却 24h 后**复测，成功率 **≥ 99%**（登记时留的原始存疑：17% 可能源于
   探针紧跟在其他调用之后、配额已被消耗）；
2. `tests/unit/test_gap_and_unlock.py::test_glm_concurrency_cap_in_config`
   **同步**更新（连同它的依据数字），而不是绕过；
3. 复测原始输出留档（`data/probe/`），可复跑。

> ⚠️ 在满足之前，任何"用免费档省钱"的改动都属于**已被否决方案**。

## 影响半径（本次改动连带确认过的）

| 项 | 处置 |
|---|---|
| `TaskTier` 字面量 | 加 `"planning"`（只增不改，`light` 不受影响） |
| `light` 层 | **不动**：它服务清洗/格式化等**高频**任务，本地仍然合算 |
| `vram.py`（显存探测） | **保留**：仍守 `light` 层。规划层不再需要它，不等于它没用 |
| 探针 | `scripts/e2e_timing_probe.py`（可复跑，本次根因就是它找出来的） |
