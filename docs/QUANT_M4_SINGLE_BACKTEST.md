# M4：单股票多因子条件策略回测 + 策略库

> 回答的问题：「我就想交易这一只票，什么时候买、什么时候卖、能赚多少」，
> 以及「这个策略值得留下来吗，留下来之后还能复现吗」。

## 1. 与「多因子」模式的分工

| | 多因子模式（已有） | 单股票模式（本次） |
|---|---|---|
| 视角 | **截面**：同一时点横着比 5000 只票 | **时序**：一只票的历史竖着看 |
| 输出 | IC/ICIR、分组收益、多空组合 | 逐笔成交、净值曲线、买卖点 |
| 回答 | "按因子排序分组，哪一组更好" | "这只票什么时候该买该卖" |
| 因子用法 | 截面排名/中性化 | 时序条件（均线、分位、突破） |

两者不可互相替代：截面回测再漂亮，也回答不了"我只有 10 万块，就买这一只"。

## 2. 条件 DSL 需要新的算子（否则单股票策略写不出来）

原有 DSL 只有**截面函数**（`RANK/PCTL/AVG/STD/MEDIAN/MIN/MAX/COUNT`）与
逐元素函数（`ABS/LOG/SQRT/SIGN`）。单股票场景下：

- 截面函数**极其危险**：它的求值对象是"整条序列"，于是 `RANK(PE)` 会拿今天和
  **未来所有交易日**一起排名 —— 是彻头彻尾的未来函数，而且算出来还很像样、不报错；
- 单股票真正需要的表达（"收盘价在 20 日均线之上"、"波动率处于近 60 日低位"）
  **根本写不出来**。

所以本次新增一族**因果时序算子**（窗口滚动，只用 t 及之前的数据）：

| 算子 | 含义 |
|------|------|
| `MA(x, n)` / `MEAN_TS(x, n)` | 近 n 日均值 |
| `STD_TS(x, n)` / `SUM_TS(x, n)` | 近 n 日标准差 / 求和 |
| `MAX_TS(x, n)` / `MIN_TS(x, n)` | 近 n 日最高 / 最低 |
| `PCTL_TS(x, n)` | 当前值在近 n 日中的百分位（0~100） |
| `ZSCORE_TS(x, n)` | 相对近 n 日均值的标准分 |
| `REF(x, n)` / `DELTA(x, n)` | n 日前取值 / 与 n 日前的差 |
| `COUNT_TS(cond, n)` | 近 n 日中条件成立的天数 |

三条硬约束：

1. **单股票模式拒绝截面算子**，并在**解析期**就报错（不是等面板装配几分钟后才报）；
2. **截面模式拒绝时序算子**（每一行是一只股票，没有"历史窗口"可言）；
3. 窗口必须是 **1~2000 的整数字面量**（写成因子会让窗口随行情变化 → 策略不可复现）。

因果性有专门的单测守着：**把最后 5 行数据改成 9999，前面 25 天的判断必须一字不变**。

## 3. 撮合口径（每一条都按 A 股真实约束，宁可保守）

- **信号时点**：t 日收盘算出的信号，在 **t+1 日开盘**成交。
  用 t 日收盘价成交 = 用了收盘后才知道的信息，是最常见的未来函数。
- **T+1**：当日买入当日不可卖。
- **整手**：买入股数向下取整到 100 股。
- **涨停不买 / 跌停不卖**：开盘触及涨停放弃买入；收盘触及跌停放弃卖出。
- **停牌**：不买不卖。
- **止损/止盈同日触发**：一律按**止损**成交（无法确知盘中顺序，取不利一侧）。
- **止损跳空**：低于止损价时按**开盘价**成交，不是止损价（缺口里只能以更差价格成交）。
- **费用**：佣金万三（最低 5 元）+ 卖出印花税 0.05% + 过户费 0.001%（双边）+ 滑点 5bp。

## 4. 三个真实踩到的坑（都会让回测"漂亮但不真实"）

### 4.1 价格空间混用

面板里的开高低收是**后复权价**（`close × adj_factor`），而 `stk_limit` 的
`up_limit/down_limit` 是**未复权真实报价**。两者直接比大小：

- 复权价恒大于未复权涨停价 → **171/171 天全部被判成"开盘涨停"**，买入全被挡掉，
  回测收益为 0 却看不出原因；
- 反过来，用复权价算整手资金时，茅台一手算出来 **108 万元**（真实约 12.8 万元），
  "资金不足"永远成立。

修法：把整块价格归一到**回测首日的真实报价尺度**
（价格 `÷ (adj_factor[首日])`、涨跌停价 `× (adj_factor/adj_factor[首日])`）。
比例全部不变（收益率、止损止盈、均线关系与尺度无关），但整手/资金/涨跌停判断回到真实量级。
另外在策略帧里额外提供 `close_raw/open_raw/high_raw/low_raw`（真实报价），
让"绝对价格阈值"和"指标口径"不会互相污染。

### 4.2 平仓后没清空持仓

`_close_position` 只记账、不改 `position`。忘了清空的话，下一日会拿**同一笔持仓再卖一次**，
每卖一次都往现金里加钱：

```
171 天 600519 跑出 +12410%、年化 123126%、回撤只有 -4%
同一入场日出现 3 笔不同结束日的成交   ← 唯一的线索
```

净值曲线单调向上、回撤很小，**肉眼看不出任何异常**。所以加了不变量自检：

1. 交易不得重叠（上一笔卖出日 ≤ 下一笔买入日）；
2. 同一买入日不得出现多笔不同结束日的成交；
3. 期末净值 = 初始资金 + 累计已实现盈亏。

任一条不满足 → 结果里出现 `⚠️ 自检失败` 警告，且**自动保存会拒绝入库**。

### 4.3 库里的数据"只有前缀"时不能走库

入库是**按分区键顺序**进行的，所以库在任何时刻都只是缓存的一个**前缀**。
原先用 `has_rows`（区间内有没有一行）决定"走库还是走 CSV"，于是：

> 一个灌到一半的数据集会被判为"走库"，回测**静默丢掉后半段数据** ——
> 净值曲线照样画得出来，只是少了一半样本。

改成 `covers()`（要求库的最大日期 ≥ 请求结束日）。实测验证（入库进行中）：

```
请求区间 20150105~20260915（跨入库边界）
moneyflow   has_rows=True   covers=False   → 走 CSV   ← has_rows 会误判
```

最小日期一侧不需要检查：前缀模型保证不会"中间缺失"；而库的起点晚于请求起点
（moneyflow 天然从 2010 起）时，CSV 里同样没有更早的数据，走库不丢东西。

## 5. 性能：三个数量级是怎么省出来的

全历史（2006-01-04 ~ 2026-09-15，**5030 个交易日**）单股票回测的实测演进：

| 优化 | 效果 |
|------|------|
| 面板装配把股票池**下推到 SQL**（`codes=[code]`） | 171 天全市场 28.5s → 单票 12.8s |
| **只算条件里引用到的因子**（写 `close > MA(close,20)` 就只算 0 个因子） | 全市场 35 因子几分钟 → 按需毫秒级 |
| `slice_panels` 把 PIT 财务面板也裁成单票 | 单次回测 47.6s → 1.0s |
| 停牌集合与指数收益改走 `dataset_long`（原先**永远读 CSV**，即使库完备） | 全历史面板装配 22.9s → 12.9s |
| PIT 财务时序**向量化**（`searchsorted` 一次算完，替代 5030 次逐日 `as_of`） | 回测循环 **12.50s → 0.20s（62×）** |

`slice_panels` 的等价性依据：35 个因子**全部逐列独立**（滚动窗口只在自己这一列上做，
没有 `axis=1` 的截面运算），所以裁到单列再算，结果与全市场算完再取一列完全一致。

**跨存储路径的可复现性验证**：同一策略在三种实现下跑出**逐位相同**的结果 ——

```
CSV 分区路径         收益 30.67%  回撤 -61.21%  437 笔  样本外 -7.39%/122 笔  期末 130,673
数据库路径           收益 30.67%  回撤 -61.21%  437 笔  样本外 -7.39%/122 笔  期末 130,673
数据库 + PIT 向量化   收益 30.67%  回撤 -61.21%  437 笔  样本外 -7.39%/122 笔  期末 130,673
```

这同时验证了行数、去重、价格空间、PIT 对齐四件事在两条存储路径上完全一致
（`tests/unit/test_quant_storage_parity.py` 把这条不变量固化成了测试）。

## 6. 结果里必须有的"诚实信息"

- **全样本 / 训练集 / 样本外** 三段指标（默认让人看**样本外**）；
- **买入持有基准**（同一只票、同区间、同费用）——跑不赢躺着不动就没有价值；
- 交易笔数 < 10：提示"统计噪声极大，换个入场时点就可能翻盘"；
- 样本外交易 < 10：提示"样本外指标基本没有统计意义"；
- 胜率 ≥ 60% 但盈亏比 < 1.2：提示"小赚多次、大亏一次"的典型形态；
- 持仓占比 < 10%：提示"年化由极少数几段贡献"；
- 样本外收益 < 训练集一半：直接标注"典型的过拟合信号"；
- 参数个数提示（可调项越多越容易过拟合）。

## 7. 策略库（一键保存）

存到 `data/quant/strategies/<id>.json`，一条策略一个文件（可直接查看/版本管理）。

**保存时带上三样东西**：

1. 完整参数快照（含费用、撮合口径、训练比例）—— 不存下来就没法复现；
2. 当时的业绩指标 + 数据区间 + 交易笔数 —— 下次重跑不一致时，能立刻判断
   是"数据补了"还是"策略失效了"；
3. 自检与警告 —— 存的是**带证据的快照**，不是一句"这个策略很好"。

**去重**：内容哈希由「标的 + 入场 + 出场 + 全部可调项」算出，重复保存
**更新已有记录**而不是新建文件（否则试参数会攒出几十个只差一个数字的文件）。

**达标自动保存（`auto_save`）的门槛**——刻意**不看全样本收益**：

| 条件 | 默认门槛 | 为什么 |
|------|---------|--------|
| 全样本交易笔数 | ≥ 20 | 少于 20 笔的胜率是噪声 |
| 样本外交易笔数 | ≥ 5 | 样本外没交易就无从检验 |
| **样本外收益** | **> 0** | 只看全样本收益，"试 30 组挑最好"必然通过 |
| 夏普 | ≥ 0.3 | 排除"收益全靠波动" |
| 回测自检 | 通过 | 自检失败（如交易重叠）一律不许入库 |

> ⚠️ 这里曾经有个 bug：`save_from_result` 漏传 `auto_saved` 参数，
> 于是"自动保存"等于无条件保存 —— 而那正是自欺的入口。已修，并有专门用例守着。

## 8. 用法

前端：「策略回测」→「单股票策略回测」页签。

```bash
# 命令行（与 API 同一条子进程路径）
uv run python -m src.quant.screen_runner --mode single \
    --request req.json --response resp.json
```

接口：

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/quant/backtest/single` | 启动单股票回测（异步，返回 job_id） |
| GET | `/api/v1/quant/backtest/single/{job_id}` | 轮询 |
| GET | `/api/v1/quant/strategies` | 策略列表 |
| POST | `/api/v1/quant/strategies` | 一键保存 |
| GET | `/api/v1/quant/strategies/verdict` | 只看达标判定（保存前预览） |
| GET/DELETE | `/api/v1/quant/strategies/{id}` | 读取 / 删除 |

## 9. 已知限制（如实记录）

- **样本量天然很小**：一只票 20 年也只有 5000 个交易日，样本外可能只有几十笔交易。
  单股票回测的结论置信度**系统性低于**全市场截面回测，这不是实现问题而是信息量问题；
- **不含分红再投资的现金流细节**：用后复权价等价于"分红再投资"，与"现金分红取出"
  的实际收益略有差异；
- **止损用日线最低价判断**：无法区分盘中是否真的成交，属于偏乐观一侧的近似；
- **不做参数寻优**：没有网格搜索/遗传算法，避免鼓励"调参调到好看"；
- 策略库**不做版本历史**：同一套参数只保留最新一次指标快照（`saved_count` 记录次数），
  需要历史请用文件版本管理（目录就是普通 JSON 文件）。
