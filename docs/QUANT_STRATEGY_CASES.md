# 开源策略案例库（多因子页「最新开源回测策略」/ 单股票页「开源策略库」）

> 把网络上公开分享的策略案例自动抓下来、增量入库、在面板里按主题浏览。
> **核心定位：这些是线索，不是结论。**

## 1. 为什么必须把"未验证"写在最显眼处

公开分享的"回测成功的策略"普遍存在四类问题：

1. **样本区间不明**：不说测了几年、什么行情段；
2. **成本忽略**：不计佣金/印花税/滑点，换手越高虚高越多；
3. **未来函数**：用当日收盘价成交、用未公布财报、用全样本排序选股；
4. **选择性报告**：亏钱的策略不会发出来。

所以本模块的产物：

- 每条都带 **`verified=0`**（恒为 0，没有任何路径能改成 1）；
- 每条都带**来源链接与发布时间**，供自行核实；
- 前端表格顶部**固定显示免责说明**，不与"我们回测过的策略"混在一起。

数据库层面也刻意分开：本项目的策略在 `quant_strategy` 表（有净值、有自检、可复现），
网络案例在 `quant_strategy_case` 表。**混在一张表里，迟早会有人把"某博客说年化 50%"
当成"我们验证过"。**

## 2. 只接实测能抓到内容的源

"HTTP 200 不等于能抓到东西" —— 这是选源时最重要的判据。2026-09-16 实测：

| 源 | 结果 | 采用 | 备注 |
|----|------|:----:|------|
| GitHub 搜索 API | 200 / 161KB 结构化 JSON | ✅ | 免鉴权，60 次/小时 |
| arXiv q-fin | 200 / 8KB Atom XML | ✅ | 学术源，方法可查证 |
| CSDN 搜索 | 200 / 174KB 结构化 JSON | ✅ | 中文技术博客 |
| 聚宽社区 | 200 但仅 3KB | ❌ | JS 壳，**无正文** |
| 雪球搜索 | 200 但返回 WAF 挑战页 | ❌ | 需 JS 过风控（`_waf_bd8ce2ce37`） |
| 新浪财经 RSS | 404 | ❌ | 已下线 |

被排除的源**保留在配置里并标注原因**，抓取报告也会列出"已跳过 N 个源"——
源悄悄消失会让人以为已覆盖全网。

## 3. 分类：主题 + 类型

**主题**（表格第一列）：动量/趋势、价值/基本面、波动/风险、机器学习、统计套利、
组合优化、因子研究、打板/情绪、**回测方法论**、其它。

> "回测方法论"这一类是实测补上的：抓取时发现"其它"里绝大多数其实是
> 未来函数、过拟合、幸存者偏差类文章 —— 而这个项目整个量化模块的设计重心
> 恰恰就是防这些。归到"其它"等于把最有价值的线索埋掉。
> 补上分类后：**"回测方法论" 9 → 28 条，"其它" 41 → 14 条**。

**类型**（区分"策略"与"工具"）：策略案例、框架/工具、教程/笔记、学术论文。

> GitHub 搜"量化 回测"会返回大量回测**框架**（backtrader、vnpy 这类）。
> 实测前 18 条里真正讲策略的不到三分之一。不区分的话，用户在"策略案例"表里
> 看到一排框架会以为抓取坏了。前端**默认排除"框架/工具"**，可勾选显示。

## 4. 用法

```bash
# 抓取（GitHub / arXiv / CSDN，约 7 秒）
uv run python scripts/quant_cases.py fetch
uv run python scripts/quant_cases.py fetch --source GitHub     # 只抓一个源

# 查看
uv run python scripts/quant_cases.py list --theme 回测方法论 --limit 30
uv run python scripts/quant_cases.py themes      # 主题分布
uv run python scripts/quant_cases.py reclassify  # 改关键词后重分类（不联网）
```

源清单：`configs/strategy_sources.yaml`（支持自定义 RSS 源）。

## 5. 定时任务（已接入项目调度器）

| 作业 | cron | 服务对象 |
|------|------|---------|
| `strategy_cases_weekly` | `10 8 * * 1`（周一 08:10） | 多因子页「最新开源回测策略」 |
| `strategy_cases_daily` | `20 8 * * *`（每天 08:20） | 单股票页「开源策略库」 |

拆成两个作业是因为两页关注的主题不同（前者偏因子/方法论，后者偏择时/套利），
代价只是多几次搜索请求。

## 6. 增量与去重

案例 ID = **来源链接的 SHA-256 前 16 位**。重复抓取只更新摘要与抓取时间，
不新增行 —— 每周抓一次不会把表撑爆。

`reclassify` 是必要补充：抓取只更新"本批返回的条目"，旧记录会保留旧分类。
改了关键词表之后必须重跑一次，否则新旧分类会混在一张表里
（实测踩过：新增"回测方法论"后表里仍有 40 多条停在"其它"）。

## 7. 已知限制

- **不做正文解析**：只取标题/摘要/来源/时间。要判断一个策略值不值得复现，
  必须点进原文看它的样本区间与成交假设 —— 摘要里通常没有这些信息；
- **不自动复现**：把网络案例自动跑一遍听起来很美，但案例里的条件往往
  无法完整还原（不说复权口径、不说股票池、不说参数），跑出来的结果没有意义；
- **GitHub 搜索限流**：免鉴权 60 次/小时，够每日/每周任务用，但不能高频抓；
- **主题分类靠关键词**：会有误判，可以改 `strategy_cases.THEME_KEYWORDS`
  再跑 `reclassify`，不必重抓。
