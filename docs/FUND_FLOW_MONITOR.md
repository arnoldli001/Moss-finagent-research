# 资金流监控（Fund Flow Monitor）设计文档

> 页签位置：顶部「资金流监控」（`web/src/components/FundFlowPanel.tsx`）
> 后端：`src/fundflow/`（models / provider / service）+ `src/api/routes/fundflow.py`
> 持久化：`dim_fund_flow_watch`（SQLite，与 `fact_*` 同库）
> 免责声明：本模块输出为资金流数据的机械汇总，不构成投资建议。

## 一、这个页签回答什么

| 面板 | 回答 | 排序口径 |
|---|---|---|
| **板块资金流排行** | 近 N 日钱在往哪些板块去 / 从哪些板块走 | 近 N 日**净额均值**（净流入前 20 + 净流出前 20） |
| **个股资金流排行** | 昨日涨停（≥25亿）+ 净流入前10 + 净流出前10 | 净额均值 ÷ 流通市值；涨停股优先 |

### 个股榜的三类构成（2026-09-17 用户口径）

1. **昨日涨停股**（流通市值 ≥ 25 亿）：打板资金去向，短线最直接的"钱在哪"；
   低于 25 亿的涨停多是几百万资金推动，放进"机构大资金动向"会淹没真实信号；
2. **净流入前 10**（净额均值 ÷ 流通市值）；
3. **净流出前 10**（同口径取最负）。

左侧三列数据（**取不到就留空，绝不用旧值冒充**）：

| 列 | 来源 | 是否盘中实时 |
|---|---|---|
| 流通市值 | 腾讯 `qt.gtimg.cn` 批量快照 → 回落本地 `daily_basic.circ_mv` | ✅ 盘中 |
| 今日涨幅 | 腾讯快照 `change_pct` | ✅ 盘中 |
| 涨停原因 | 东财涨停池 `stock_zt_pool_em(所属行业)`，含连板数 | 日频（按涨停日取） |

> **为什么"昨日涨停"用本地仓库自算而不是东财涨停池**：实测东财
> `push2ex` 的 `date` 参数**无效**（传 20260915/16/17，`qdate` 一律回当天），
> 用它会把"今天的涨停"当成"昨天的"。仓库 `daily.high >= stk_limit.up_limit`
> 是确定性判定且支持任意历史日。涨停原因则反向用 akshare
> `stock_zt_pool_em(date=...)`（实测支持历史日：20260914→55 只、20260915→32 只）。
| **资金流走势图** | 勾选的板块/个股逐日走势，可叠多条线对比 | 单位统一为亿元，零轴以上=净流入 |

用户口径原文：「展示最近10日净流入或净流出板块的资金额走势图（支持用户手动加入板块，
默认初次使用热门板块前20）」「展示最近5-10日净流入或净流出大资金平均值/流通市值，
排行前20的个股，其资金额走势图」。

### 为什么个股榜用**比值**而不是绝对额

绝对额排行永远是大市值股票的天下（工商银行随便一点波动就超过中小盘全天的量）。
除以流通市值后才能看出"这只票自己的体量里，大资金进了多少" —— 这正是
"监控机构大资金动向"要的东西。实测（2026-09-17）榜首 `688801 C煦原`：
近 10 日主力净额均值 3.27 亿 / 流通市值 79.7 亿 = **4.10%**。

## 二、数据来源（三层，按可靠性排序）

| 层 | 数据 | 来源 | 频率 | 用途 |
|---|---|---|---|---|
| **主** | 板块净额/净占比/大单/超大单/当日排名 | Tushare `moneyflow_ind_dc`（东财板块口径） | 日频（最近已结算交易日） | 板块榜排序 + 板块走势 |
| **盘中覆盖** | 板块当日净额、涨跌幅 | 同花顺 `stock_fund_flow_industry/concept(symbol="即时")`，走子进程隔离 | 盘中实时（60s 缓存） | 把"当日"列刷新成此刻口径 |
| **个股** | 主力/大单/超大单净额（元） | Tushare `moneyflow`（**本地仓库**，零网络） | 日频 | 个股榜排序 + 个股走势 |
| 个股辅助 | 流通市值 | Tushare `daily_basic.circ_mv`（本地仓库） | 日频 | 排序分母 |
| 备用 | 板块历史 | 东财 `stock_concept/sector_fund_flow_hist`（akshare） | 日频 | 主口径取不到时降级 |
| 兜底 | 板块历史 | 成分股 × 个股 moneyflow 求和（本地聚合） | 日频 | 上面两级都不可用时 |

### 实测踩过的三个坑（都写进了代码注释）

1. **Tushare 不传 `trade_date` 会返回多天拼接**：实测 5000 行里含
   `20260914/15/16` 三天 —— 若不按 `ts_code` 去重取最新，界面上"当日净额"
   会随机显示几天前的值（第一次接完就出现"截面日期 20260910"）。
2. **`to_thread(client.call, api, {})` 是错的**：`call(self, api, **params)`
   只接受关键字参数，传空字典会被当成第二个位置参数 →
   `TypeError: takes 2 positional arguments but 3 were given`，而它被
   `except` 捕成"数据源不可用"，整条板块链**静默变空**（排查了一圈才发现）。
3. **同花顺这一版 akshare 没有板块成分股函数**：1.18.94 的 `dir(ak)` 里只有
   `stock_board_concept_index_ths` / `_info_ths` / `_name_ths` / `_summary_ths`，
   没有 `cons_ths`；成分股只能走东财 `stock_board_concept_cons_em`。
   所以"本地聚合"兜底在当前版本下事实上不可用，保留它是为了数据源恢复后自动生效。

### 内网实测的可用性（2026-09-17）

| 接口 | 结果 |
|---|---|
| Tushare `moneyflow_ind_dc`（无日期） | ✅ 1030 个板块，含超大单/大单 |
| Tushare `moneyflow_ind_dc`（按 ts_code） | ✅ 单板块 730 行历史，一次拿满 10 日窗口 |
| Tushare `moneyflow`（本地仓库） | ✅ 全市场日频，毫秒级 |
| 同花顺 `stock_fund_flow_industry/concept(即时)` | ✅ 行业 90 / 概念 387 |
| 东财 `stock_concept_fund_flow_hist` | ❌ 持续 `RemoteDisconnected`（东财侧封了本机） |
| 东财 `stock_board_*_cons_em` | ❌ 同上 |

结论：**东财 akshare 那条线在本机当前不可用**，因此主口径放在 Tushare；
东财路径保留为备用（换网络/恢复后会自己生效），不删。

> 根因已在 2026-09-17 查清并记录：东财 `push2*.eastmoney.com` 被**按 TLS SNI 阻断**
> （URL 写域名断、写 IP 通；DNS/TCP/反爬/限频全部排除）。完整证据链、
> 影响面与两个恢复办法见 [TROUBLESHOOTING.md §七](TROUBLESHOOTING.md)，规避开关
> `MOSS_EM_DIRECT=1`（默认关闭）实现于 `src/core/eastmoney_direct.py`。

## 三、刷新节奏

| 触发 | 行为 |
|---|---|
| 进入页签 | 立即取一次快照 |
| 盘中自动 | **每 60 秒**取一次（服务端同节奏重算，命中 60s 缓存不重复取数） |
| 「立即刷新」 | `refresh=true` 穿透服务端缓存 |
| 切换窗口（5/10/15/20 日） | 立即重取（服务端按新窗口重算榜单与走势） |

页面顶部显示：`时段 · 数据获取时间 · 服务端生成时间 · 交易日`，并逐条列出数据来源说明
（哪个口径、多快更新）。**不写死"实时"二字**：板块历史是日频，只有"当日"列在盘中是实时的。

## 四、选择列表的持久化

- 表 `dim_fund_flow_watch(kind, code, name, source, added_at)`，`kind ∈ {sector, stock}`；
- **默认热门只播种一次**：仅当 `sector` 一条记录都没有时，写入"当日净额绝对值最大的 20 个板块"。
  用户删掉某个之后**不会再被自动塞回来**（`ensure_defaults` 见到非空就跳过）——
  "我删了它又回来了"比"没给默认值"更让人恼火；
- 加入/移除都**幂等**（重复加入只更新名字，不改加入时间）；
- 仓储不可用时：页签仍能看榜单与走势，只是选择不进库（接口返回 503 并说明原因）。

SQLite 连接开了 `WAL + busy_timeout=15s`：实测与做T面板同时刷新时，
`CREATE TABLE` 会撞上 `database is locked`（服务进程里还有采集/告警两条链在写同一个库）。

## 五、前端交互

- 榜单每行左侧名字是**勾选开关**（点一下即叠加到走势图），右侧 `＋/−` 是加入/移除监控；
- 走势图：滚轮缩放、拖拽平移、双击复位、`近5/10/20日` 快捷窗口；
  Y 轴随可见窗口自动重算（放大后能看到小波段）；悬停给出竖线与逐条当日值；
- 图例可**单条隐藏**（`●/○`），另有「全显」「清空选择」；
- 数据不可得的实体**不进图**：只在图例/缺口里说明，绝不画一条 0 值假线
  （那会让人以为"这个板块资金流是 0"）。

## 六、与选股功能的对接（先板块后个股）

`GET /api/v1/fundflow/pick?window=&top=` 输出机器可读的两份清单：

```json
{
  "sectors": [{"code": "BK1036.DC", "name": "半导体", "net_avg": 1.36e10,
               "today_net": ..., "change_pct": 1.34}],
  "stocks":  [{"code": "688801", "name": "C煦原", "net_avg": 3.27e8,
               "net_to_mv": 0.041, "circ_mv": 7.97e9}],
  "gaps": []
}
```

刻意**不做二次打分**：这里只给"钱在往哪去"的原始排序，
阈值/权重怎么用属于选股模块的口径，不在这里替它决定（口径混在一起以后没法归因）。

## 七、接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/fundflow/snapshot?refresh=&window=&top=` | 榜单 + 走势（盘中 60s 缓存） |

## 九、已知局限（不隐瞒）

1. **板块历史是日频**：`moneyflow_ind_dc` 只到最近已结算交易日，盘中看不到"今天的10日线"；
   "当日"列由同花顺实时层补，两者数值口径不同（已在 `source_notes` 逐条标注）。
2. **个股走势是日频**：`moneyflow` 收盘后定稿，盘中不变。
3. **东财 akshare 链路当前离线**（本机网络），相关备用口径与"本地聚合"兜底
   在当前环境下取不到数 —— 代码路径保留，恢复后自动生效。
4. 板块名跨源不一致（同花顺「5G」vs 东财「5G概念」），跨源比对用归一化名，
   取数一律以**该口径自己的官方名**为准（搜索列表给的就是可用的名字）。
