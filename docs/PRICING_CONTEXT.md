## 1. 结论表（当时给的第一手判断）

| 场景 | 合理成交价（人民币） |
|---|---:|
| 急售 / 打包代码 | **5–15 万** |
| 卖给一家私募做研究底座（**最现实**） | **30–80 万** |
| 补齐软著 + 6 个月真实资金实盘后可谈到 | **150–400 万** |
| 卖给中型券商/基金（需公司主体+团队+供应商准入） | **300–800 万/年**（服务模式），**纯卖代码基本不可能** |

> **当时状态（无实盘、无公司主体、无软著）落点大概率 20–50 万。**

一句话总结原话：

> **你的资产不是那三个收益率数字（它们经不起尽调），而是"一个能独立交付机构级 AI 量化平台的工程师
> + 18 万行已验证代码 + 4/8 人年才能重建的基础设施"。**
>
> 按软件卖：**20–50 万**。按人 + 服务卖：**150–500 万**（需补实盘、主体、软著）。
> 按 LICENSE 长期授权卖：**年费 30–80 万起**，可复购。

## 3. 三个致命点（"最好的效果"全都会被尽调打穿）

### ① 没有任何实盘业绩 —— 唯一一次跑出来是亏的

- 回测账户口径 **59 天 −16.33%**
- **没有对接券商下单**，没有滑点/冲击成本模型
- 项目自己的 `docs/DEMO_GUIDE.md` 写着"❌ 报收益数字 —— 没有真实资金验证，一问就穿"

> **没有 track record 的量化系统，定价方式不是"未来能赚多少"，而是"替代开发成本打折"。**
> 这是整个估值的地基。

### ② "最好效果"全部是样本内 + 参数在同一份数据上选出来的

| 模块 | 被指出的问题 |
|---|---|
| **竞价选股** | V3 基准 +13.81% / 夏普 0.528 / **最大回撤 −51.11%**；**8 个熔断参数是在同一样本上选的**（报告自评"仍需 walk-forward"）；开发中修过**前视偏差**；**87% 的卖出是"收盘判定+收盘成交"**（报告自称"当前最大的未验证风险"）；最大 15 笔亏损 = 全部净盈利的 **166.6%** |
| **LightGBM 三档** | 零成本 +19.51% → 含费 +13.28% → **含费+1% 滑点 = −10.58%** → 止损收紧 −26.37%。报告原话："你要的『近一年』正好就是模型的测试区间" |
| **ETF 份额监控** | 引用的 T+34 +9.18% / 胜率 83.3%，实际 **n=66 条信号但只有 3–5 个独立时段**；报告自述 Wilson 95%CI 在 n=3 时"**毫无统计意义**"；样本外那栏 `独立时段 = 1` |
| **主线挖掘** | 因子显著性用非重叠 t 值看**绝大多数 < 2**；已落地权重方案 t=2.02 是唯一勉强及格；**第二层因子全线负 IC**（−0.0275 / −0.0334） |

> 项目自己最狠的一句在 `docs/MAINLINE_MINING.md`：
> **"在它跑出来之前不能拿任何一个数字当实盘预期。"**

### ③ 没有牌照 → 三个模块对外收费就踩线

| 依据 | 关键内容 |
|---|---|
| 证监会公告〔2012〕40号 | 给出**具体证券的投资分析意见 / 推荐具体证券 / 给出买卖时机建议**的软件 = "荐股软件"；**以直接或间接经济利益销售或提供 = 从事证券投资咨询业务，需持牌** |
| 《程序化交易管理规定（试行）》证监会公告〔2024〕8号 | 第 7 条要求报备**交易软件名称、版本号、开发主体**；第 19 条**禁止违规转让、出借自身投资交易系统或为第三方提供系统接入** |

> **结论**：平台 / 回测 / 数据层可以卖（不属荐股软件）；
> 但**竞价选股、AI 投资建议、做 T 择时**这三块对外收费就踩线 —— 买方合规部一票否决。

## 4. 市场锚点：机构真实付了多少钱（已核实中标金额）

| 项目 | 中标方 | 金额 | 时间 |
|---|---|---:|---|
| 中信建投证券「与基金公司联合实验室量化交易执行系统」 | 金证股份 | **220 万** | 2026-06 |
| 财通证券「FICC 综合交易系统升级」 | 恒生电子 | **299 万** | 2025-09 |
| 中加基金「投研管理平台项目」 | 上海携宁 | **119 万** | 2025-08 |
| 财信证券「量化业务优化项目（软件部分）」 | 恒生电子 | **48.8 万** | 2025-07 |
| 财信证券「恒生统一算法策略平台·算法优化」 | 恒生电子 | **35.68 万** | 2026-09 |
| 华龙证券「金证 AI-T0 交易策略系统 V1.0」 | 金证股份 | 预算 **78 万** | 2025-08 |
| 财信证券「量化策略服务采购」 | 4 家入围 | 预算上限 **1000 万** | 2026-03 |

**规律**：单点算法模块 **35–490 万**；完整投研/量化平台 **120–300 万**；策略服务框架可到 **1000 万**。

> ⚠️ 这些价格买的是：**公司主体 + 发票 + 供应商准入 + 实施团队 + SLA + 信创合规 + 落地案例**。
> 当时这六项**一项都没有** —— 所以不能直接对标，只能对标"替代开发成本"。

**替代成本独立估算**：18 万行 × 实测可复现 × 高质量文档 ≈ **3–3.5 人年**工程量。
按国内量化/金融科技外包 2–4 万/人月，替代成本 **72–170 万**；
扣掉 AI 辅助开发与 bug 修复成本 → **公允替代成本 50–90 万**。
这是谈判的**天花板参照，不是成交价**。

## 5. 买方视角：谁会买、出多少、卡在哪

| 买方 | 意愿 | 现实出价 | 卡点 |
|---|---|---|---|
| **私募（<10 亿规模）** | 中 | **20–60 万** | 小私募自研/招人更便宜；买了没法直接接交易 |
| **量化私募（有 IT 团队）** | 低 | 5–20 万（只想看思路） | 他们只买"能接进自己交易系统的信号"，而本系统没法接 |
| **中型券商/基金** | 低 | 需公司主体 | 投顾牌照 + 供应商准入 + 等保 + 二次开发能力 |
| **量化平台厂商**（恒生/金证/同花顺） | 极低 | 通常不买源码 | 他们买的是牌照、客户和渠道，不是代码 |
| **数据/内容平台** | 低 | 10–30 万 | AI 投研部分有溢价，但赛道小 |

> **唯一真正高价值的买方，是"买你这个人"** —— 也就是 acqui-hire。

## 6. 两种变现结构（比一次性卖源码好得多）

**A. 授权 + 服务（推荐）**
> 不卖源码，卖"部署 + 定制 + 数据接入 + 一年运维"，**年费 30–80 万**，源码始终留在手上。
> 可复购、可涨价、风险可控。

**B. 信号订阅 / 收益分成**
> **年费 50–200 万**，或管理规模 5000 万以上分 **20%** 业绩报酬。
> **但必须先有 6 个月以上真实资金实盘业绩**，否则没人签；且分成可能触发投顾资质要求。

### 三种卖法的等价换算（当时特别强调的一点）

| 卖法 | 收费形式 | 你保留什么 | 定价参照 |
|---|---|---|---|
| **买断源码**（转让 IP） | 一次性 **20–50 万**，常见 3–3–4 分期 | **什么都不留**，且不能再卖第二家 | 成本法：替代成本 × 折扣 |
| **永久授权**（源码交付+永久使用权） | 一次性 **80–200 万** | 名义著作权在手，事实已交付 | 成本法 + 少量溢价 |
| **年度授权 + 实施运维**（推荐） | **30–80 万/年**，续费率是生命线 | **源码不交，随时可停** | 收益法：年费 × 倍数 |

> **换算关系：一次买断价 ≈ 年费的 3–5 倍。**
> 所以"20–50 万买断"换成授权制 = **年费 6–12 万**；反过来要收 **40 万/年**，
> 一次买断就该报 **120–200 万**。**两个数字不是同一个东西的两种说法，是两种完全不同的资产。**

## 9. 这段上下文是怎么找回来的（方法，对你也有用）

最早几轮已被上下文压缩掉。我没有凭记忆复述，而是从**本地会话记录**里解出来的：

```
C:\Users\<用户>\AppData\Roaming\dsh-desktop\harness\sessions\
    --D-code--\session-<uuid>\session.v4.jsonl.zstd
```

三个坑，记下来免得再踩：

1. **记录是"拼接 zstd 帧"**：一个文件里 `28 b5 2f fd` 出现 **56840 次**（每条记录一帧）。
   - `zlib.zstdDecompressSync(buf)` **只解第一帧** → 25 MB 文件只出 171 字符（会话表头），
     看起来像"记录是空的"，据此得出的"关键词 0 命中"结论**完全是假的**。
   - `createZstdDecompress()` 流式解在第二帧处报 `Unknown frame descriptor`（Node 不跨帧）。
   - **正确做法**：按魔数切帧、逐帧解（`subarray` 是视图，不产生 O(n²) 拷贝）。
2. **帧是"完整快照 + 增量"混合**：同一份会话里首帧可能是 3000 万字符的整份快照，
   后面是几十到几万字符的增量 → **同一消息出现多次，必须按 message id 去重**，
   再按 `seq` 排序才是对话时间线。
3. **英文小标题会骗人**：记录里助手消息的短标题是英文（"I'll start by exploring..."），
   但正文是中文 —— 只按英文关键词找会漏。

可复用的脚本（本仓库）：

| 脚本 | 作用 |
|---|---|
| `scripts/_extract_frames.mjs` | 按魔数切帧逐帧解压，统计关键词命中（可跨多个会话文件） |
| `scripts/_frames_to_text.mjs` | 把一份记录的所有帧解成纯文本 |
| `scripts/_dialog_timeline.py` | 按 message id 去重 + 按 seq 排序，还原对话时间线 |
| `scripts/_find_valuation_answer.py` | 从时间线里挑长回答、并按价格数字定位 |
