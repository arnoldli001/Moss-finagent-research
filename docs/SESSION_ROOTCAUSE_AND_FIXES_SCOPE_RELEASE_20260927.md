## 一、A 类 · 口径治理

### A1 · 拥挤度清单 262，却算了 554（**四轮才定案**）

**症状**：用户报「拥挤度清单只有 262 个，为什么计算 554 个」。

**我错在哪**：连续四轮给出四个不同结论，每次都自以为"找到了新证据"：

| 轮次 | 我用的"证据" | 结论 | 证据级别 |
|---|---|---|---|
| 1 | 读代码 + 读配置项默认值 | 收到 262 是对的 | E5（读代码推断） |
| 2 | 读看板勾选框默认值 | 该回退 554 | E5 |
| 3 | 读注释里的口径说明 | 又改成 262 | E5 |
| 4 | **查 `source` 字段分布** | **554 = 全部已配置**，定案 | **E1（产线查询）** |

**真根因**：`visible=1` 的 554 个板块里，**系统种子**和**用户手动添加**混在一起：

```
visible = 1 的 554 个拆开：
    source='default' + 概念    257   ← 系统种子
    source='manual'  + 非概念  292   ← 【用户自己加的】
    source='manual'  + 概念      5   ← 用户自己加的
```

按「只看概念板块」收口 = **算了系统塞进来的 257 个，不算用户自己配的 292 个**。
「默认渲染集合」≠「用户配置集合」—— 前者是**视图默认**，后者要看 `source` 这种**来源字段**。

**解决方案**（已交付）：

| 集合 | 处理 | 实现 |
|---|---|---|
| 已配置（`visible=1`） | **预计算** | 全量刷新池 = `list_visible_codes()` |
| 未配置 | **按需算**（新增时触发） | `compute_metrics_for_codes(codes)`，单板块 ~0.37s |

**没做的事（诚实登记）**：`pool_concepts_only` 在本次会话里被翻转了 4 次
（262→554→262→554→262），最终定格 `false`（554 = 全部已配置可见）。
这个字段本身就是这次摇摆的产物，**它的默认值语义应该被删掉**，而不是留着让人再猜。

### A2 · 收窄拥挤度范围，主线池被连带砍掉 6 个板块

**症状**：改完拥挤度范围后，主线（`ml_board`）里的板块数不对了。

**真根因**：**隐式耦合**。一份有语义的清单被两个子系统同时读：

```

   ├─→ sector_crowding/refresh.py     ✅ 预期消费者
   ├─→ sector_crowding/metrics.py     ✅ 预期消费者
   └─→ mainline/datastore.py          ❌ 隐式消费者（改之前不知道）
```

改之前我只查了"前端谁在调这个接口"，没查"还有哪个后端模块读这份清单"。

**解决方案：用快照解耦，而不是调参数**（已交付）：

| 做法 | 结果 |
|---|---|
| 写一条动态规则（"胜率 ≤ 40% 就排除"） | ❌ 新板块也会被这条规则排除掉 |
| **生成冻结快照** | ✅ 新板块仍能加入，老名单不再抖动 |

- `configs/mainline_frozen_pool.yaml` = **122** 条（`base_pool: 138` − `gated_out: 16`）
- `load_frozen_pool()` 返回 `set | None`；**`None` = 无快照 = 退回旧行为**（可回退）
- 快照存在时跳过动态排除，但**仍然尊重 `sector_blacklist`**（安全类排除不因快照失效）
- 验证：`ml_board` = 122 行，与冻结名单**双向差集 0 / 0**

> **口诀**：要"停止变化"用**快照**，要"持续生效"用**规则**。混用必错。

## 二、B 类 · 稳定性与出口

### B1 · 做T快照 500「服务器开了点小差」（**最隐蔽的一个**）

**症状**：用户看到 `ApiError: 服务器开了点小差`，5xx。日志里**没有业务堆栈**。

**排查路径**：

| 步骤 | 动作 | 结果 |
|---|---|---|
| 1 | 查错误码表 | `>=500` 一律折叠成 `SYS_5000`，502 有独立码 `DATA_5020` → 说明是**真 500** |
| 2 | 找业务异常 | 找不到。路由的 `try/except` 里什么都没抓到 |
| 3 | 怀疑出口 | 查 Starlette `JSONResponse.render()` |

**真根因**：

```python
# Starlette 的 JSONResponse.render() 用 allow_nan=False
# → 响应体里只要有一个 NaN/Inf，就在【渲染期】抛异常
# → 这个阶段【在路由的 try/except 之外】
# → 用户看到 SYS_5000，日志里没有任何业务堆栈
```

**解决方案**（`src/api/main.py`）：

```python
class _SafeJSONResponse(JSONResponse):
    @staticmethod
    def _clean(value):
        if isinstance(value, Real) and not isinstance(value, Integral):
            f = float(value)
            if math.isnan(f) or math.isinf(f):
                return None          # 出口统一转 null
        ...
    # 全局兜底：
    app = FastAPI(default_response_class=_SafeJSONResponse)
```

**两个值得抄的细节**：
1. 用 `numbers.Real` 而不是 `isinstance(value, float)` —— 否则 `np.float32` **漏网**。
2. 测试必须**钉住框架默认行为**（本次 6 条测试里有一条专门断言
   "Starlette 默认实现确实会拒绝 NaN"）—— 否则将来换框架，这层护栏会**静默失效**。

**没做到的事**：**原始故障没能复现**。修复依据是"机制上唯一能产生
'渲染期异常 + 无业务堆栈 + 真 500'的组合"，不是"我看到了那一条 traceback"。
这一点在面试里要如实说。

### B6 · 接口回 `{"restored":1}`，但板块不出现（**静默失败**）

**症状**：用户新增/恢复一个板块，接口返回成功，界面里没有。

**根因**：加黑名单时**没有设计"怎么加回来"**：

```python

→ 接口回 {"restored": 1}
→ 板块不出现（还在剔除清单里）
→ 【不抛任何异常，不报任何错】
```

**解决方案：排除机制必须三件套**（已交付）：

1. **撤销通路** —— 恢复接口调 `remove_crowding_exclusions(codes)`
2. **立即补算** —— 恢复后立刻 `_warm_metrics(codes)`，否则用户看到的是 `—`
3. **顺序正确** —— **先补算，再读列表**（两个接口里都是 warm-before-read）

> 自检问法：「**如果这个操作完全没生效，我能从返回值里看出来吗？**」

## 三、C 类 · 统计方法（**最容易在面试里被深挖**）

### C1 · 水位分母的样本最大值偏差

**背景**：水位 = `当前平滑拥挤度 / 该板块近 6 年最大值`。

**问题**：分母是**样本最大值**，而 `E[M_n]` **随样本量 n 单调上升** →
**历史短的板块水位系统性虚高**（曾有 218 个板块误报 ≥80%）。

**我试过的三个方案，前两个都错**：

| 方案 | 做法 | 结果 |
|---|---|---|
| v1 · 二值门槛 | `min_bars ≥ 750` 才出水位 | ❌ **只把悬崖挪了个位置**（750~1460 根仍有 1033 个板块，仍不等价） |
| v2 · 向同类中位数**收缩**（James-Stein） | `denom = exp(w·ln(M_own) + (1-w)·ln(M_peer))` | ❌ **被自己的截断回测证伪** |
| v3 · **尺度校正** | `denom = M_n · r(n)`，`r(T) = median(M_full / M_T)` | ✅ 有效 |

**v2 为什么错（这是最有信息量的一段）**：

`M_peer` 是**横截面中位数**。向它收缩，会把**高于中位**的板块分母**调小**，
水位反而**更高** —— 修正方向是反的：

| 收缩强度 k | 偏差 |
|---:|---:|
| 0 | +0.047 |
| 250 | **+0.099**（越收越偏） |

**v3 的标定结果（由截断回测给出，不是我设的）**：

| T（样本根数） | `r(T)` | 朴素偏差 | 校正后偏差 | MAE 改善 |
|---:|---:|---:|---:|---:|
| 60 | 2.6207 | +0.3502 | **−0.0612** | **54.3%** |
| 250 | 1.7021 | +0.1801 | −0.0241 | 27.0% |
| 750 | 1.0000 | +0.0470 | +0.0470 | 0% |

**验收（四个数字，单看一个都能骗人）**：
- **33** 个短历史概念板块 → **32 个出水位**（剩 1 个 38 根 < 60 根下限）
- **告警率 0%**（对照满窗组 6.1%）→ 不是普遍抬高，是消除虚高
- 中位数对齐 **0.372 vs 0.351** → 分布整体对齐，不是只动尾部
- 有水位的数据行数 **740,182 → 2,029,906（2.7×）** → 覆盖度净增

重算 2437 个板块 / 2,178,721 行 / 91.1s / 失败 0。
标定总体：**满窗板块（n ≥ 1460）**，`r(T) = median(M_full / M_T)`。

> ⚠️ **`r(T ≥ 750) = 1` 是实测结论，不是我设的参数**（多数满窗板块的极值就在最近 750 天内）。
> 而"收缩"这个听起来更高级的方法，在数据面前是**错的**。
> **先做截断回测，再选方法。**

## 五、E 类 · **AI 自己引入的问题**（诚实登记）

### E1 · 自写过滤器三次给出**假绿灯**（全是编码层错误）

| # | 错误 | 后果 | 方向 |
|---|---|---|---|
| 1 | `subprocess(text=True)` 在 Windows 上把写入 stdin 的 `\n` 变成 `\r\n` | 每条路径带尾部 CR → **什么都匹配不上** → 报"没有任何文件被忽略" | **偏松（会泄漏）** |
| 2 | 不加 `-z` 时 `check-ignore` 按 `core.quotePath` **给非 ASCII 路径加引号** | 中文名文件永远匹配不上自己的输入键 | **偏松** |
| 3 | `-v -z` 每条记录是**四个** NUL 字段（`source\0lineno\0pattern\0pathname\0`），我按两个配对 | 元数据与路径错位，全部判错 | **偏松** |

**三次都让过滤器看起来比实际更松** —— 也就是**都会导致泄漏**，而且都会
"安静地通过"。第一次跑出来的结果是"**174 个文件全部会发布，0 个被忽略**"，
我差点据此继续。

**修法与纪律**：
- git 调用**一律用 bytes**，不用 `text=True`
- 只用**不带 `-v` 的 `-z`**（它返回的就是忽略集合本身）
- **固定 12 条 sanity 断言 + 算术自洽断言**，每条都人工核对过期望值：

```python
SANITY = [
    ("scripts/prune_crowding.py", True),          # 非白名单脚本 → 不发布
    ("scripts/seed_demo_data.py", False),         # '!' 白名单 → 发布
    ("tests/unit/test_ps1_encoding.py", True),    # 硬断言 *.ps1 非空
    (".trae/skills/ai-dev-rules/SKILL.md", True),
    ("docs/OPS_GUIDE.md", True),
    ("web/dist-pilot/index.html", True),
    ("README.md", False),
    ...
]
assert len(publish) + len(ignored & set(candidates)) == len(candidates)   # 算术
```

> **元教训**：**工具自己会错，而且错得偏向"看起来没问题"。**
> 任何用来做安全判定的脚本，都必须先喂"已知答案"的输入自证。

### E2 · 把并发会话的未验证改动复制进了快照

**经过**：我发现某个测试失败，去私有树看，发现文件**已经有修复了**（mtime 22:06:26），
于是直接 `Copy-Item` 进快照。

**但**：`tests/integration/test_alert_api.py` 的**工作树版本比私有 HEAD 多 112 行**
（323 vs 182）—— 那是**另一个会话正在写的、未提交、未验证的**内容。
我把它整份复制进了发布快照。

**发现方式**：`git diff --stat origin/main -- <file>` 显示 108 行差异，
而 `git diff --stat origin/main HEAD -- <file>` 只有 6 行 —— **两个数字对不上**。

**修法**：`git checkout <pre-amend-commit> -- <file>` 回到已验证版本，
然后**只补那一处 skip**（4 行），重新 amend。

> **纪律**：**快照必须从"冻结的修订"取内容，不能从"活动的工作树"取。**
> 动手前看文件 mtime；与私有 HEAD 差得多的文件要停下来查。

### E3 · 双向差集核对脚本自己写漏一半

**经过**：我写了"双向差集"核对（这正是我在 A3 里总结的纪律），
第一次跑出来 **`VERDICT: MISMATCH`** —— 101 个文件"staged 但不在预期里"。

**差点误判**：那 101 个其实是**删除**（公开线有、白名单没有）。我的
"预期集合"只算了 `changed`，**没算 `deleted`**。

**修法**：预期集合 = `changed ∪ deleted`，并加算术自洽断言
（`published + ignored == candidates`、`expected == staged`）。
修正后：**0 / 0 CONSISTENT**。

> **教训**：**检查脚本报错时，先怀疑检查脚本。** 本次它自己错了两次
> （E1 的 CR 问题、E3 的漏算删除），两次都表现为"发现了问题"，而实际是假警报。
