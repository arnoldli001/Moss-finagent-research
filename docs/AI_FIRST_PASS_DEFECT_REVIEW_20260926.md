## 一、六类根本原因（跨条目归纳）

### 1.1 「同一个判断有两份实现」→ 必然分叉（#7、#5、#8）

- 「在线」列手写 SQL、`is_valid()` 写 Python，两条判据只对了一半；
- 成本有两套潜在口径（内存账本 vs 事后统计）；
- ── 分叉的那一侧就是"漏网之门"。项目自己的文档
  （`src/api/login_gate.py`、`src/api/routes/my_features.py`）早就写过这条警告，
  **但警告拦不住新代码**。

**通则**：判据必须收敛成**一个常量/一个函数**，并配一条"两条路径结果必须相等"的测试。

### 1.2 护栏写在使用方，而不是配置层（#11、#12、#13）

- 成本护栏写在文档里（"脚本该自己查 remaining"）→ 等于没有；
- `local_only` 靠每个调用点自觉 → 新调用点默认**不安全**；
- 探针脚本没人记得它是探针。

**通则**：**默认值即护栏**。要么把约束放进配置/基类（新调用方自动继承），
要么在入口 fail-closed；绝不依赖"记得传参数"。

### 1.3 资源约束被忽略（#8、#9、#12）

- 本地只有**一个计算槽位**、8GB 显存只能常驻一个 7~8B 模型（实测 5 次 evict）；
- 输出预算 4096 token，而思考型模型先吃掉 ~560；
- 并发请求会在 Ollama 内部排队，最终以"调用失败"的形式暴露。

**通则**：把算力当**有明确上限的资源**建模：槽位数、显存、tokens/s、单次输出预算
都要有实测数字，然后**按预算分批/限流**，而不是"发出去再说"。

### 1.4 身份/归属缺失 → 统计全是假值（#6、#5）

访问审计 100% 是 dev-bypass 假身份，"按租户"这一栏在生产上只有一个 `local` 行；
LLM 审计里 44,145 次调用只有 621 次带租户。

**通则**：**先证明归属链是通的**，再做任何按维度聚合的报表。
否则面板越漂亮，误导越强。

### 1.5 假绿 / 静默降级（#2、#6、#9、#7）

- 采集为空被当成"已追平"；
- 读不到审计时显示"0 元/0 用量"；
- LLM 失败退回关键词兜底（情感恒 neutral）；
- "在线 3"把过期会话算成在线。

**通则**：**"没量到"与"量到 0"必须分开显示**；降级要留下用户可见的痕迹
（数据缺口文案、`data_gaps`、`未量到`），并把口径与局限随数据一起下发。

### 1.6 评估方法本身有漏洞（#14）

"换模型前后对比"如果带缓存，就等于拿旧模型的答案冒充新模型的结果
（第一次三模型输出逐字节相同、本地耗时 0.0s）。

**通则**：**任何"优化前后对比"必须先确认测量路径干净**（禁缓存、隔离环境、
同一输入、记录原始输出），否则优化结论不可信 —— 这比优化本身更容易出错。

## 二、逐条：现象 → 证据 → 根因 → 解决

> 只列"上线即故障/亏损"与"静默降级"这两档；口径失真类见第一节归纳。

### 2.1 「查看原文」2248 个请求（#1）

- **证据**：Network 面板 3 秒内 2248 次请求，页面始终空白。
- **根因**：`useEffect(..., [details])` 且 effect 内部 `setDetails(...)`：
  依赖 → 请求 → setState → 依赖变化 → 再请求；同时 effect 的 cleanup 把
  已发出的响应当作"过期"丢弃，于是**永远渲染不出内容**。
- **修法**：依赖换成不可变键（`detailHash/detailTick`），去重靠 `requested` ref，
  去掉 cleanup；正文读取一次性缓存。
- **验证**：手测 1 个请求、2145 字符；回归断言"给 onClose 才有关闭按钮"等 34 条前端渲染检查。

### 2.2 事件告警中心花 token（#8）

- **证据**（`data/audit/llm_audit.jsonl` 逐次聚合）：`alert_analyzer` 53 次调用 / 0.32 元，
  其中阶段二 28 次是 deepseek（0.0666 + 0.2348 元）、阶段一 1 次 0.0196 元。
- **根因**：阶段二 `tier="reasoning"`，而 `configs/models.yaml` 里 `reasoning` 的
  **primary 是付费 deepseek-flash**、本地 `local_medium` 只是 fallback →
  "先花钱，本地模型闲着"。
- **修法**：阶段二改 `medium`（本地 qwen3:8b），两阶段都 `local_only`（本地不可用**明确失败**，
  不偷偷降级付费），云端要 `MOSS_ALERT_ALLOW_CLOUD=1` 显式打开。
- **验证**：本地 10 条真实事件 → 10/10 有效评估、0 付费调用、130 秒；
  分数有区分度（业绩暴雷风险 85/把握 0.95、海外花絮双低分 15/把握 0.35）。

### 2.3 阶段一被截断、整批退回关键词兜底（#9）

- **证据**（生产日志）：`阶段一分类失败，使用本地兜底: LLM输出非合法JSON:
  Unterminated string starting at: line 76 column 5 (char 1487)`。
- **根因**：阶段一一条调用要输出全部事件的分类结果；本地思考型模型
  (~560 token 思考) + 真实事件 ~350-400 token/条 → 超过 `max_tokens=4096`
  被**从字符串中间截断**。`json_schema` 只保证结构合法，**不保证生成跑得完**。
- **修法**：① 按实测开销分批（`STAGE1_BATCH=6`，留 ~40% 余量，单批 ≈55 秒 < 120 秒超时）；
  ② 截断抢救 `salvage_events()`（逐项 `raw_decode` 救完整前缀）；③ 单批失败只影响那批。
- **验证**：18 条长正文真实形态事件 → 3 批、71 秒、**18/18 走模型、0 兜底**。
- **方法论价值**：这条把"schema = 万无一失"的错觉纠正为
  **"schema 管结构，预算靠分批，抖动靠重试，兜底是最后一道"**。

### 2.4 调度管理无门槛 + 一次点击 4 次完整研究图（#10）

- **证据**：`/api/v1/scheduler/*` 只有登录门槛；`snapshot_industry_watchlist`
  是 `graph_snapshot` + `targets=[半导体,煤炭,创新药,白酒]` → 一次点击 4 次
  `runtime.graph.ainvoke`（全 Agent 链 + 全部 LLM 调用），且**同步执行**。
- **根因**：把"管理员专属"实现成了**套餐矩阵里的一个默认值**（可勾选），
  而接口层没有任何授权判断 —— "隐藏页签 ≠ 禁止访问"是项目文档里写过的结论，
  但新接口仍然只继承了登录门槛。
- **修法**：路由级 `dependencies=[Depends(require_admin)]`（4 个端点全覆盖，
  新端点默认管理员专属）+ 服务端 `ADMIN_ONLY_VIEWS` 规则（矩阵勾了也不下发）+
  权限矩阵锁格 + 前端代价确认弹窗。
- **验证**：未登录 401 / vip·trial 403 / admin 200 / 未知作业 404；
  另有"管理员把 `scheduler` 勾给试用后，试用仍看不到也调不动"的断言。

### 2.5 成本护栏只是约定（#11）

- **证据**：`budget.py` 的文档写着"批量作业该在自己的入口判断 `remaining()`"，
  而两个脚本从没实现 → 单日 487.57 元（日预算 20 元的 24 倍）。
- **修法**：`ScriptCostGuard` 两个口径 —— 入口按**预计**花费拒绝启动、
  中途按**实际**花费中止；预计花费 = 调用数 × 实测单次成本（0.02 元，取实测上限）；
  基线取"本进程增量"以免把别人花的钱算自己头上。
- **验证**：`mainline_relevance --stage score` → `预计花费约 98.88 元，超过单次上限
  1.00 元 —— 已拒绝启动（一次调用都不发）`，退出码 3；`--limit 40`（≈0.8 元）仍放行。

### 2.6 「在线 3」（#7）

- **证据**（pilot DB 实查）：管理员名下 4 条未撤销会话中 **3 条 `idle_expires_at` 已过期**
  （最后活动分别在 2.8/1.5/0.5 小时前），而列表列只判"未撤销 + 绝对未过期" → 显示 3；
  按全站判据 `is_valid()` 只有 1 条有效。
- **修法**：抽 `ACTIVE_SESSION_WHERE` 作为 `is_valid()` 的 **SQL 孪生**，批量统计与
  详情接口都用它；前端把列名改为「在线设备」并说明"统计的是有效会话数，不是人数"。
- **验证**：4 种会话形态（有效/滑动过期/绝对过期/已撤销）下
  "批量口径 == 逐用户口径 == 1"，且过期会话仍在明细里标「已失效」。

## 三、AI 首轮编码的"性格"：为什么会这样

| AI 首轮代码的典型倾向 | 后果 | 对策（写进 skill） |
|---|---|---|
| 让代码**跑起来**（happy path 绿）就算完 | 边界/资源/并发/归属全没建模 | 交付前必须回答"上限是多少/超了会怎样/谁在花钱" |
| 复制粘贴既有模式，但**只看被复制的那一处** | 同一判断出现第二份实现（在线数、成本口径） | 改判据时先全局搜同类实现，能抽常量就抽 |
| 注释写得很像"已经解决" | 文档与实现脱节（护栏只是约定） | 注释里出现"应该/必须"的约束，就要有对应测试或配置 |
| 默认值取"最方便"（付费兜底、全量、同步） | 静默花钱、静默降级、阻塞 | 默认值必须取**最安全**的一侧（本地/限流/异步/fail-closed） |
| 报表先做漂亮，归属链没验 | 面板全是假值 | 先证明"0 与未量到能分开"，再谈聚合 |
| 优化做完就宣布收益 | 测量路径不干净（缓存/并发/环境） | 对比必须禁缓存、记录原始输出、给出可复现命令 |
