## B 版：面试展开（按"问题—判断—动作—结果"讲）

### B0 · 30 秒电梯陈述

> "这是一个**面向二级市场的 AI 投研系统**：19 个 Agent 分 5 层，数据层做多源
> 容灾、分析层做宏观/中观/微观推理、决策层出建议、审计层做哈希链留痕。
> 我自己搭了三块基础设施：**LLM 网关**（分层路由 + 语义缓存 + 熔断 + token 预算）、
> **数据连接器路由**（三级故障转移 + 分档缓存）、**自学习数据补充**（LLM 生成采集码 +
> 双重安全校验）。
> 量化侧我从零写了因子库、分层回测、VaR/压力测试和集合竞价选股，后者最近做了一次
> 大重构：把 329 处 `if/elif` 收敛成四张规则表，**34 倍提速**，并用冻结行情做了
> 逐位黄金回归保证行为不变。"

### B1 · 三个可以深挖的技术点

| 点 | 一句话钩子 | 展开方向 |
|---|---|---|
| **LLM 网关** | "所有 Agent 禁止直连模型 API，必须过网关" | 分层路由省 token、语义缓存命中率、断路器状态机、token 预算与审计链 |
| **竞价选股重构** | "把规则变成数据，把执行变成解释器" | 位掩码消除顺序耦合、黄金回归逐位校验、性能瓶颈其实在生态序列不在规则 |
| **自学习数据补充** | "系统自己给自己补数据源" | LLM 生成代码的安全边界：AST 静态校验 + 子进程沙箱 + 15s 超时 |

### B2 · 量化侧的展开

- **因子链路**：`Factor` 基类 + `@register_factor` 装饰器 → 预处理三步
  （MAD 去极值 → z-score → 市值+行业中性化，OLS 带截距）→ IC/IR（Spearman
  秩相关）→ 5 分位分层回测（H-L 多空年化/夏普/最大回撤）→ Jaccard 换手率。
- **风控**：VaR/CVaR 用历史模拟法（不用参数法，因为参数法假设正态太乐观），
  压力测试覆盖 2015 股灾 / 2020 新冠 / UBS 瑞信 / 美联储加息四段；
  Brinson 归因拆行业配置 + 个股选择 + 交互。
- **工程纪律**：回测引擎里**没有 LLM、没有未来函数**，用 `--synthetic`
  确定性合成数据验证机制本身。朴素 PPI 动量规则在 601088 上实测跑输买入持有
  —— 我把它写进 README，因为**回测子系统验证的是框架而不是收益承诺**。

### B3 · 数据层的展开（可靠性设计）

```
请求 → 分档 TTL 缓存（月频宏观 24h / 估值 12h / 行情 4h / 实时流动性 5min）
         │ 未命中
         ↓
      per-key lock（防缓存击穿：同一 key 并发只放一个请求到远端）
         ↓
      QMT → CSV → AkShare   任一级 DataFetchError 自动降级
         ↓ 全失败
      宁可报"数据缺口"，绝不回退 simulated
```

> 这条"**不回退模拟数据**"是刻意的取舍：假数据进了最终投研建议，
> 比"这次没数据"危险得多。代价是偶尔需要人工补数据源。

## C · 常见追问与应答（备好，不要临场编）

| 追问 | 应答要点 |
|---|---|
| 为什么用 LangGraph 不用 AutoGen？ | 需要**可控的 fan-out/fan-in**（A09→A13 并行再汇总到 A17）。AutoGen 的 group chat 是黑盒，我控不了并发度与失败边界。 |
| 19 个 Agent 是不是过度设计？ | 是**分层职责**不是 19 个独立微服务：demo 阶段单进程内注册，接口无状态，保留拆成 FastAPI 微服务的路径。真实跑一次不会全唤醒（Planner 按指标目录+Agent 目录挑子集）。 |
| 怎么控制 LLM 成本？ | 四层：① Planner 用 1.5B 本地模型（规划是分类任务，3-5s vs 云端 18s）；② 语义缓存；③ 单任务 token 预算超限直接拒绝；④ 输入硬截断 + max_tokens 硬上限。 |
| 怎么防 LLM 幻觉？ | 时效红线（拒绝引用过期数据）+ 审计链留 prompt_hash/response_hash + A18 审计 Agent 做完整性校验。**不声称完全解决**，只做"可发现、可追溯"。 |
| 回测收益多少？ | 不吹收益。三档模型近一年回测年化 19.51% 有**样本内声明**与滑点敏感性分析；朴素规则在 601088 上跑输买入持有 —— 框架正确性优先于收益数字。 |
| 最大的性能瓶颈在哪？ | 竞价选股模块实测：决策链路 1231 ms 里 **99.3% 是生态序列每轮读三张全市场表**（约 208 万次 pandas 元素操作），规则判定只占 8 ms。所以优化对象是"把一天一变的结果挪出热路径"，不是优化规则。 |

## D · 写简历时的注意事项

> **先分清两个平面（纪律不同，别互相污染）**：
>
> | | **简历 / 自我介绍** | **架构设计 / 面试展开** |

> | 回答的问题 | 我**做到了**什么 | 我**判断**该怎么做 |

> | 上限 | 只能写到已验证的边界 | **可以放开写**，越深越好 |
>
> 下面「不要写」**只约束简历**。**设计文档不受此限**——
> 设计里写高并发、分布式、多副本、分片都不违规，违规的只有
> "把设计说成已实现"。
> 平台级设计与并发容量推演见
> [`PLATFORM_MULTI_TENANCY_DESIGN.md`](PLATFORM_MULTI_TENANCY_DESIGN.md)（§7 共享计算层、§8 分布式扩展、附录 C 面试防御包）。

**可以写**（有代码/测试支撑）：
- 19 Agent 分层编排、LLM 分层路由与网关、数据三级容灾、因子回测/风控链路
- 2500+ 单测；竞价选股 34× 提速 + 黄金回归逐位校验

**简历里不要写**（没有证据或容易被打穿）：
- ❌ 任何"实盘收益 / 超额收益 / 胜率"数字 —— 没有真实资金验证
- ❌ "高并发 / 分布式"**当成绩写** —— demo 阶段是单进程 SQLite，写成已完成会被追问到崩
  - ✅ **可以改成"判断"来写**（这是加分项，不是减分项）：
    "定位到单实例吞吐饱和 5~6 req/s 的根因是重复计算而非核数（实测整机 CPU 仅 6~13%），
    据此否掉加实例方案，设计共享因子层 + 口径指纹缓存，目标计算次数降 13×"
  - 引用数字必须是 `实测`（可复跑：`.\.venv\Scripts\python.exe scripts/_probe_concurrency.py`），
    `目标` 值可以写但必须标明是设计目标
  - ❌ 不能写："已支撑 100 人并发"、"生产 QPS 30+"、"完成分布式改造" —— 要等 P2/P3 落地并有实测
- ❌ "自研向量数据库 / 语义检索" —— 语义缓存是字符 3-gram 余弦，属轻量实现
- ⚠️ "19 个 Agent"要主动说明是**职责分层**，否则容易被当成堆砌

**量化岗额外准备**：
- IC 为什么用 Spearman 不用 Pearson（对异常值稳健、捕捉单调关系）
- 中性化为什么必须带截距项（否则常数项被吃进 beta）
- 为什么用历史模拟法算 VaR（不假设分布，但需要 ≥50 天样本）
- 分层回测的空头腿 A 股不可做空，怎么处理（用 H-L 价差做因子有效性检验，
  **不是**可交易策略）
