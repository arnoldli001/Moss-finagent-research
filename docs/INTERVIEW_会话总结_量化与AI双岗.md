## 1. 30 秒版项目画像

**Moss-FinAgent-Research**：基于多 Agent 协作的 AI 辅助投研系统，服务二级市场。
- **技术栈**：FastAPI + Pydantic v2 + SQLite（可切 Postgres/Redis）+ 本地 Ollama（qwen3:8b / qwen2.5:1.5b）+ DeepSeek-V4-Flash 云侧 + React/TS 单页工作台。
- **Agent 架构**：LangGraph StateGraph 的 Supervisor 调度，18 个 Agent 分 5 层（数据/信息/分析/行业/决策/审计）。
- **业务模块**：做T辅助（自选池分时打分/关键价位/信号推送）、量化选股、集合竞价选股、事件告警（快讯+日历 → LLM 风险/机会评估 → 阈值告警 → WS/邮件）、资金流监控、板块拥挤度、主线挖掘、策略回测。
- **本会话主线**：把"单机演示"推进到**可对外（多租户 / 权限 / 配额 / 试点上线）**，并修掉一批**只在真实使用下才暴露**的问题（性能、告警恒 0、鉴权边界、配置静默失效）。

一句话卖点（面试开场可用）：
> "我做的是一个多 Agent 的 A 股投研系统：模型侧是本地+云双通道的 LLM 网关，业务侧是量化因子与事件驱动告警，工程侧把单机 demo 做成了带环境隔离、多租户权限、幂等写接口和边缘网关的对外试点。这次我重点讲三个我自己挖出来的问题：**告警为什么恒为 0、首屏为什么 6~7 秒、WebSocket 为什么会绕过登录**。"

### 2.2 量化业务改造
- **事件告警盘中化**：扫描班次从"只有工作日 17:30 一班"改成 **09:30 / 10:30 / 12:00 / 13:30 / 14:30 / 17:30** 六班（三个作业共用同一把扫描锁）+ **服务启动后 90 秒自动补扫一次**；时刻表由注册表 cron **现算**（`alert_scan_schedule()`），前端与 `/alerts/settings` 共用，避免"改了 cron 忘了改文案"。
- **做T辅助首屏两段式**：先推**轻量快照**（行情/分时/关键价位/总分/信号）把图打出来，1 秒后补**完整快照**（消息面 LLM/估值/板块分时/大盘/海外映射）。
- **轻量快照缓存**：自选整表刷新循环本来每轮就给 46 只票各算一份轻量快照、算完就丢；现在按代码留档（TTL 10 min），**交互首帧直接内存命中**。
- **分时图可视化**：价格由蜡烛改**折线**、量能红绿、Y 轴按**涨跌停带**（10/20/30%）收敛、档位标签纵向防重叠、缩放锚点改为**数据中点**、空窗口给诚实提示。
- **URL 子状态路由**：`code/mode` 等状态写进 hash，可分享/刷新保持（无路由库，自己写的 `route.ts`）。
- **板块拥挤度刷新口径**：一键刷新从"全量 1850 个板块"改成"**关注板块池**（清单里可见的 554 个，主线挖掘复用的同一份池子）"，全量降级成一个次要按钮。

### 2.3 合规整改（量化岗常被问"合规"）
- 三批文案整改：**125 处**投资建议式表述、**388 处**「低吸/高抛」→「回踩/冲高」（含 `configs/intraday.yaml`）、新增统一 `Disclaimer` 组件挂到五个面板；**排除了**营销文案与因子标签；全项目检索确认无「必涨/稳赚/评级」类语言。
- 结论口径要自己拿准：**我不是合规意见的出具方**，做的是"降低措辞风险 + 全量可检索"。

### 2.4 稳定性 / 可观测性
- 前端连接状态横幅 + 网络错误归因（区分"服务没起"与"连接被中断"）。
- 调度运行记录（runs.jsonl）+ LLM 审计（prompt hash / token / 租户 / 用户 / 缓存命中 / 降级链）。
- 长连接竞态修复：uvicorn `--timeout-keep-alive 65`（坑 #1）。

### 2.5 部署 / 上线（架构师岗加分）
- **自有域名上线**：`wujiaitool.cn` 托管到 Cloudflare → 命名隧道 `moss-pilot` → 本地 ingress `http://127.0.0.1:8110` → **登录自启计划任务**常驻；实测 `/` 200、`/health/live` 200、`/health` 401（门槛在隧道后照样生效）。
- **Access 与应用鉴权的取舍**（被问"你为什么不直接上 Cloudflare Access"）：Access 是**边缘邀请制**，会把注册页一起挡掉 → 与自助注册冲突；正解是"边缘只挡机器人（Bot Fight Mode / Turnstile），业务边界交给应用层（登录 + 注册审批 + 分级配额）"。

## 3. 踩过的坑（现象 → 根因 → 修法 → 可复用教训）

### A. 协议 / 浏览器 / 网络层
| # | 现象 | 根因 | 修法 | 教训 |
|---|---|---|---|---|
| 1 | 管理台点"创建用户"报 **Failed to fetch**（后端无错日志） | uvicorn 默认 **keep-alive 5 s**，浏览器复用连接时服务端已关闭 → 前端拿到网络层错误 | `--timeout-keep-alive 65` + 安全重试 + 幂等键 + 状态横幅 | "Failed to fetch"**先怀疑连接复用/网络层**，别先怀疑业务代码 |
| 2 | 公网匿名连 `/ws/intraday` 能收到整套快照 | `LoginGateMiddleware` 基于 `BaseHTTPMiddleware`，**只处理 http scope**，WS 完全不经过 | `ws_allow()` 单独校验会话，拒绝用 4401 | **鉴权边界要按"协议/入口"清点**，写一个中间件不等于全覆盖 |
| 3 | 手机访问偶发 502 | 隧道在、origin 在重启 → cloudflared 连不上后端 | 区分"隧道坏"与"origin 短暂不可达"（看 cloudflared 日志的 `dial tcp ... refused`） | 502 的归因顺序：先看 origin 端口 → 再看隧道 |
| 4 | 域名建好、权威 NS 有 A 记录，本机 `Resolve-DnsName` 却报"域名不存在" | 解析器把之前的 **NXDOMAIN 负缓存**住了（SOA minimum TTL，最长 30 min）；`ipconfig /flushdns` 只清本机 | 用 `curl --resolve host:443:IP` 绕开 DNS 验证链路 | **验证"通不通"要绕开缓存层**；别把缓存当故障 |
| 5 | `cloudflared tunnel login` 浏览器授权成功，CLI 一直 `Waiting for login...` / `Failed to fetch resource` | OAuth 回调取证书在本机失败 | 让浏览器**下载** `cert.pem`（内容是 `BEGIN ARGO TUNNEL TOKEN`），手工放到 `~/.cloudflared/cert.pem` | 交互式授权流程要准备**非交互兜底**；凭证文件长得不像 PEM 也要认 |
| 6 | 隧道随终端/会话消失，客户访问中断 | 前台进程的宿命 | 注册**登录自启计划任务**（失败自动重启 3 次） | "能跑"≠"能一直在跑"，交付要考虑**存活** |

### B. 配置 / 依赖解析层（本会话最狠的一类坑）
| # | 现象 | 根因 | 修法 | 教训 |
|---|---|---|---|---|
| 7 | 事件告警**永远是 0 条**、判分被压到 0~55 | `.env` 里 `DEEPSEEK_API_KEY=...` **被粘在一行注释的末尾**，dotenv 逐行解析 → 整行当注释丢弃 → reasoning 档**静默降级**到本地 qwen3:8b，作业状态还是 success | 拆分粘行脚本（写回前后各解析一次 dotenv，断言"键集合不缩水"）；同一条链上还救回 `QMT_ENABLED=0`、`MOSS_EM_DIRECT=1`、`LOCAL_QUOTE_DIR` | **"配置存在、格式合法、却被解析器吃掉"是最贵的一类 bug**；失败表现是"功能降级但状态成功"→ 必须把"降级发生了"做成可观测指标（生效模型/降级计数） |
| 8 | 启动横幅写着"定时任务：已关闭"，实际调度器在跑 | `MOSS_SCHEDULER_ENABLED=0` 全仓库**没有任何一处读取它** | 本轮**故意不改行为**（用户当下要的就是让告警跑起来），记录为待修 | **开关只写了"设置"没写"读取"**；`grep 变量名` 零命中就是证据 |
| 9 | 一条测试日期一过就 4 条用例集体转红，被测代码没动 | 夹具把 `expire_time` 写死 `2026-09-21`，读路径**懒过期**把告警标 expired、默认列表过滤掉 | 夹具改成 `now + 7d`；另用显式构造过去时间的用例覆盖"已过期"语义 | **绝对时间进夹具＝把测试租给日历**；"未来/过去"语义一律用相对时间 |
| 10 | 模型打分分布被压到 0~45，阈值永远够不着 | 叠加因素：**模型被降级**（坑 7）+ stage-2 提示词只有一句"评分须克制"、没定义分档 | 给提示词写死 **0-100 分档锚点**（按"影响能否落到具体标的与可量化方向"定档），再**按实测分布**标定阈值 | 标定顺序：**先生效模型 → 再提示词 → 最后阈值**；先调阈值只会掩盖前两层 |

### C. 数据 / 排序 / 算法层
| # | 现象 | 根因 | 修法 | 教训 |
|---|---|---|---|---|
| 11 | 事件告警扫描天天 success，但 87 条已分析事件**来源 100% 是"财报披露日程"**，当天 184 条快讯一条没轮到 | 日程型事件把 `publish_time` 写成**未来披露日**（09-28~10-01），按它倒序取候选 → 候选窗口被"未来时间"永久占满 | 引入 `dedup.event_recency_key`：**未来时间收敛到抓取时间**，同刻真新闻优先；积压出队改为"取一窗 + Python 排序" | **排序键的语义错误会造成"系统性饥饿"**，而它在监控上表现为"任务成功" |
| 12 | 阈值（risk 中 60 / opp 中 65 / conf 0.70）一条告警都出不来 | 实测分布 max(risk)=58、max(opp)=55、max(conf)=0.72 —— **门槛高于模型实际分布的最大值**，数学上不可能出告警 | 写探针脚本打印每条事件的三个分数 + 分位数分布，按 p75~p90 标定（conf 0.60 / risk 70-50-35 / opp 65-50-35），实测同一批 20 条有 5 条成告警 | **阈值不是拍出来的，是按分布标定的**；同时要能说出"宁漏勿滥"和"标定缺失"的区别 |
| 13 | 时间比较在混格式下不可靠 | 时间字段同时存在 `YYYY-MM-DD HH:MM:SS`（裸本地）与 `YYYY-MM-DDTHH:MM:SS+08:00`（ISO），**字符串比较会把 ISO 写法恒判为大**（'T' > ' '），naive 与 aware 直接比还会抛异常 | SQL 里不做过时间比较（取窗口），排序与比较统一在 Python 层用同一个 `_aware()`/`_parse_dt()` | 时间**永远统一时区与格式再比**；能用 `datetime` 就别用字符串 |

### D. 性能层（量化+架构双岗都能讲）
| # | 现象 | 定位方法 | 根因 | 修法 |
|---|---|---|---|---|

### F. 协作/流程层（体现工程素养，面试官很吃这套）
- **先测量再改**：三次性能问题都不是先改代码，而是先写探针（`scripts/_probe_*.py`）把耗时拆到子链路 / 把分布打出来。
- **改动必须可验证**：每个修复都给出可复现的验证（帧序日志、DB 计数、`curl --resolve`、pytest 计数）。
- **回归测试与"反向验证"**：新坑都补了测试（时刻表展开、周末不触发、启动补扫三条路径、未来日程不抢候选、401 全局信号）。
- **文档即交付**：设计文档按"已完成 / 部分完成 / 实测发现并修掉的真问题"分区，每个坑写清现象-根因-证据-修法。

## 4. 面试官大概率会问什么（按岗位分组，含答题要点）

### 4.1 量化开发岗
1. **"你的做T信号怎么定阈值？"**
   → 讲**分布标定**：先跑探针拿全样本打分分布（p50/p75/p90/max），门槛压到 p75~p90；再讲标定的三层依赖（生效模型 → 提示词 → 阈值），能举例"门槛 60 而实测 max 58，注定 0 信号"。
2. **"板块拥挤度怎么算？为什么用 6 年水位？"**
   → 原始拥挤度 = 板块成交额 / 全市场成交额；MA5 平滑；水位 = 当前平滑值 / **近 6 年平滑最高值**（用历史最大值做分母，跨板块可比）。可扩展：分位数替代最大值、行业内相对拥挤。
3. **"数据源怎么保证不挂？"** → 多源链 + 健康度排名（样本 <3 时按配置顺序当先验）+ 明确降级语义（竞价链无免费替代源就**如实登记"无备源"**，不留一个永远失败的源）。
4. **"未来数据/前视偏差怎么防？"** → 顺势讲本会话那个绝佳案例：**日程型事件 publish_time 在未来，把候选窗口占满**（未来信息挤掉当下信号）——这是"未发生的数据污染排序"的真实版本。
5. **"回测的坑？"** → 复权、停牌、涨跌停不可成交、手续费/印花税、幸存者偏差、样本外验证；说清你项目里回测模块的边界。
6. **"实盘/模拟盘差异？"** → 盘中数据缺口、限频（东财 3573 s 冷却）、单实例写库、开盘 5 分钟数据抖动。

### 4.2 AI 应用开发 / 架构师岗
1. **"多 Agent 怎么编排？"** → Supervisor + StateGraph，Agent 间标准 JSON 消息；说清**什么时候不该用多 Agent**（单链路能线性解决就别上编排，成本与可观测性都会变差）。
2. **"LLM 网关怎么设计？"** → 多 provider 链 + 按 tier 路由（medium=本地 qwen3:8b / reasoning=DeepSeek）+ **prompt hash 缓存** + 熔断/降级 + 审计（token、租户、用户、缓存命中、降级链）。**关键反思**：降级必须可观测，否则"模型降级"会伪装成"业务逻辑不灵"（坑 7）。
3. **"结构化输出不稳定怎么办？"** → JSON mode + **截断抢救**（逐项 `raw_decode`，遇到不完整对象即停，其余下一轮重试）+ 分档锚点提示词 + 缓存（同一 batch 逐字节相同则命中）。
4. **"成本怎么控？"** → 候选上限（单次扫描 ≤30 条）+ 两级流水线（分类用便宜档、打分录 reasoning 档）+ 缓存 + 按租户 token 聚合与配额。
5. **"怎么评测？"** → 承认现状：**没有系统离线评测集**（这是要补的），现有的只是"参数契约断言 + 金标准测试 + 人工看分布"；能说出下一步：构造标注集 → 用 AUC/命中率替代"阈值是否出告警"。
6. **"多租户怎么做？"** → 权限码 × 角色矩阵 + 分级配额（调用频次/token/自选上限）+ 审计（租户/用户维度）+ **数据隔离级别**（单库带 tenant_id vs 分库）；诚实说明 RLS 只在 Postgres 路径上。
7. **"安全边界在哪里？"** → 边缘（Tunnel/Access/Bot Fight）vs 应用（登录门槛 + Session + 注册审批 + 限流）；并主动讲 **WS 绕过中间件**、**CSRF cookie 已发但未强制**这两处现状。

### 4.3 通用系统设计 / 工程
1. **"为什么 dev 和 pilot 要分库？"** → 调试不能影响客户；"不搞独立生产库，那每次调 bug 都要影响客户吗"就是这个问题的问题陈述。
2. **"幂等怎么设计？"** → `X-Idempotency-Key` + 在途声明（in-flight claim）+ 轮询结果 + 失败释放；为什么要配"安全重试"（只重试幂等读/写）。
3. **"单实例 SQLite 的边界？"** → 单写者、WAL、`busy_timeout`、写锁竞争；何时必须上 Postgres（多实例/长事务/RLS）。
4. **"怎么做性能定位？"** → 先复现 → 分层计时 → 找到"谁在等谁" → 再改；本会话三次都是这个套路（附探针脚本）。
5. **"上线要考虑什么？"** → 存活探针（0 I/O）、边缘鉴权、DNS 缓存、进程存活（服务/计划任务）、回滚（前端 dist 版本 + `ship-frontend`）。

## 6. 三个可以讲成 STAR 的"故事"（每个 60~90 秒）

### 故事一：**事件告警为什么永远是 0 条**（推荐主讲，最能体现分层排查）
- **S**：客户反馈告警页一条都没有，而调度面板显示扫描"成功"。
- **A**：层层排除——① 班次只有一班 17:30（盘中根本不扫）；② 已分析事件 **100% 是"财报披露日程"**（未来披露日占满候选窗口）；③ 阈值高于模型实测分布最大值（注定 0）；④ 审计日志发现 reasoning 档**静默降级**到本地小模型，根因是 `.env` 里 API key 被粘进注释行。
- **R**：四层全修；实测同一批 20 条事件从 0 条 → 5 条告警，dev/pilot 都真实出告警；补了 6+ 条回归测试。
- **反思**：**"任务成功"≠"业务正确"**；降级、饥饿、标定这三类问题都不会让作业失败，只会让结果永远为空。

### 故事二：**分时图 6~7 秒 → 0.7 秒**
- **S**：点开一只自选股，分时图要六七秒。
- **A**：不猜，先量：单接口冷 4.5 s / 热 0.2 s；写分层探针发现 `board_series` 16.7 s（已后台化）、基础取数 2.3 s；真正的根因是"首屏在等完整快照"+"自选整表刷新与交互抢 CPU"。
- **R**：两段式首帧（轻量先出图）+ 轻量快照缓存 → 帧序实测 **0.67 s 出图 / 2.40 s 完整**；同一只票第二次点击 **3 ms**。
- **反思**：优化前先回答"**用户第一眼要看的是什么**"，把与它无关的重活挪出关键路径。

### 故事三：**WebSocket 绕过了登录门槛**
- **S**：自查时发现公网匿名连 `/ws/intraday` 能拿到整套快照。
- **A**：中间件是 `BaseHTTPMiddleware`，只处理 http scope；WS 走的是 websocket scope，完全没经过。
- **R**：加 `ws_allow()` 独立校验，匿名拒绝（4401），补 TestClient 与真实隧道的双向验证。
- **反思**：**安全是"清点入口"的活**，不是"写了个中间件"就完事；之后我把这条写进了设计文档的接入点清单。

## 7. 诚实边界（主动说，比被问出来强）
- **CSRF**：`moss_csrf` cookie 已下发，但**中间件未强制校验**（写接口目前靠 SameSite + 同源）。
- **prod 未打通**：prod 要求 Postgres，而事件/档案/池子的实现仍以 SQLite 为主 → 目前对外只能跑 pilot。
- **环境隔离不完整**：板块拥挤度模块的库（`data/moss_finagent.db`）未跟随 dev 隔离。
- **评测缺失**：LLM 打分没有离线评测集，阈值靠分布标定而非指标优化（AUC/命中率）。
- **Access 未配置**：当前公网入口靠应用自身登录门槛；"客户能进、全网扫不到"的邀请制是**可选项**，与自助注册冲突（已把取舍讲清楚）。
- **既有测试基线**：仍有历史失败（如集合竞价相关的 12 条），我修掉了其中一批（时间炸弹 4 条），但没全清。
- **AI 参与度**：这个项目的很多代码是在 AI 辅助下完成的 —— **面试的诚实做法**是：把每个模块的"为什么这么设计"讲清楚（本文件第 4、5 章就是为此准备的），而不是声称每个字符都手写。面试官真正在意的从来是**判断力**：为什么这么选、怎么验证、错了怎么发现。
