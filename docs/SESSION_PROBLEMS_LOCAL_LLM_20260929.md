## 1. P1 —— 本地模型"掷硬币"（最贵的一个）

### 症状

本地模型**随机**返回空内容：同样的 prompt，一次正常、一次一个字都没有。
表现为"这批抽取怎么漏了一半"，看起来像显存或并发问题。

### 根因

`qwen3` / `qwen3.5` 是**思考型**模型，**思考 token 计入 `num_predict`**。
真实 prompt（`tone.build_prompt` + `tone.extraction_schema()`，`num_predict=2048`）
各 3 次实测：

| 模型 | 默认（开思考） | `think=false` |
|---|---|---|
| `qwen3:8b` | p50 **18.3s** · 输出 729 tok · 键齐全 100% | p50 **9.1s** · 321 tok · 键齐全 **100%** |
| `qwen3.5:4b` | p50 31.4s · **空正文 100%**（2048 全被思考吃掉） | p50 **4.8s** · 184 tok · 键齐全 **100%** |

**判决性对照**：4B 权重比 8B 小一半（显存宽裕得多），却**比 8B 更容易空返回**
⇒ **"显存不足"解释不了它**。病在输出预算。

### 怎么修的

`src/infrastructure/llm/providers.py::_resolve_local_think`：

- 本地（Ollama）调用**默认关思考**（默认值即护栏）；
- `MOSS_LOCAL_THINK=1` 可开回；非法值**打 warning 并按默认处理**（不静默）；
- 个别任务可用 `ModelSpec.think` 覆盖（`None` = 跟随默认）；
- **云端不受影响**（`think` 是 Ollama 顶层参数，灌给 OpenAI 兼容端点会静默失效）。

### 护栏（14 条，含**接线判据**）

`tests/unit/test_local_think_switch.py` 里最关键的一条是
`test_think_reaches_the_http_payload`：它拦一次**真实出站请求**，断言 `think`
真的进了 payload。为什么必须这样：**"我改了 `_resolve_local_think`" ≠
"它生效了"** —— 单测全绿而 `chat()` 忘了塞进 payload 的形态，
在测试上看起来与成功一模一样。

### 效果（审计 `latency_ms` 现算）

| 调用点 | 8B p50 / p95 | **4B p50 / p95** |
|---|---|---|
| `intel_extract`（券商作文多空抽取） | 13.22 / 55.72s（dev）· 17.37 / 45.30s（pilot） | **3.88 / 10.76s** · **7.09 / 11.71s** |
| `alert_analyzer`（事件告警打分） | 45.39 / 73.36s | **8.38 / 18.14s（−82%）** |

> ⚠️ 8B 的 max 实测 **141.28s / 110.67s 已超过** `llm_timeout_seconds = 120s`
> —— 那就是"掷硬币"在时延上的形态。

## 2. P2 —— 8GB 卡上的模型共存（为什么必须换 4B）

### 症状

两个项目（本仓库 + `medscholar-agent`）共用同一个 Ollama。
用 8B 时互相把对方挤出显存：实测**换出+重载 12.95s**，
而且会把对方推到"本地不可用 → 静默改走云端付费"的分支。

### 根因（实测驻留）

| 模型 | 实测驻留 |
|---|---|
| `qwen3:8b-q4_K_M` | **5578 ~ 5900 MB** |
| `qwen3.5:4b` | **2983 ~ 3187 MB** |
| `qwen2.5:1.5b` | 1112 MB |
| 卡总显存 | 8188 MB |

`8B + 1.5B = 6.69GB` 只剩 ~1.2GB；`4B + 1.5B = 4.10GB` 剩 ~2.0GB。
**后者的意义是"不再有谁进来就把谁挤出去的连锁"** —— 那条连锁正是历史事故里
`120294ms` 挂死的成因。

### 怎么修的

`configs/models.yaml` 的 `local_medium` 从 `qwen3:8b-q4_K_M` 换成 `qwen3.5:4b`
（**键名不变** —— 键的语义是"中等层本地地板"，不是"8B"；改名会漏改 16 处引用）。

**准入判据**是**带标注**的字段级测评（9 条真实形态语料 × 2 轮，每条带人工期望值）：

| 指标 | `qwen3.5:4b` | `qwen3:8b` |
|---|---|---|
| 完全正确率 | **89%** | 89% |
| p50 / p95 | **4.44 / 5.58s** | 5.40 / **22.49s** |
| codes/brokers/analysts/bull_stocks | 100% | 100% |
| `tone` | 86% | **100%** |
| 显存驻留 | **2983 MB** | 5578 MB |

**真实语料补测**（24 条券商作文，走真实 gateway、缓存关闭）：

| 指标 | 4B | 8B |
|---|---|---|
| **方向产出率** | **75%** | 66.7% |
| 券商命中 | 12.5% | 16.7% |
| 分析师命中 | 8.3% | 8.3% |
| 摘要可落库率 | 91.7% | 95.8% |
| p50 | **2.05s** | 2.31s |
| 方向结论分歧 | **仅 2/24 条**（「4B 未定而 8B 给方向」= **0 条**） | — |

**诚实边界**：那条 `tone` 劣势出现在**歧义样本**（"减持+问询"与"分析师维持增持"
同时出现）上；**真实语料 24 条里 4B 的方向产出率反而更高**，且没有一条是
"4B 判不出而 8B 判得出"。1 轮 × 24 条，分歧条目未做人工裁定。

### 护栏

`test_intel_vocab.py::_assert_capable_local_floor` —— 判据**与模型名无关**：
① 不得是 light 层那个 1.5B；② 显存档位 ≥ 3000MB。
并配**自证**（喂 1.5B 必须报错），否则它是"看起来在守"的恒真断言。

## 3. P3 ~ P5 —— 限流护栏（免费档的可观测性）

### 背景

`light` 层（占 **82%** 调用量）首位是**免费档** `qwen-siliconflow-7b`，
而它**有限流机制**。没有护栏的后果：

```
siliconflow 静默限流 → 每次调用先白撞一次 429 → 再落到 dashscope
```

**这个过程没有任何可见面**：延迟上升、下一跳配额被额外消耗。

### 三个问题

**P3 没有"锁回"机制。** 阈值 3 次连续 429 → 锁 10 分钟 → 期间直接跳过该跳；
任意一次成功则清零（"连续"的语义）；锁定期满自动解锁（半开重试，**不永久弃用**）。

**P4 判据依赖文案。** 原实现只在异常消息里找 `"429"`，而那句话来自
`httpx.HTTPStatusError` 的默认文案（`Client error '429 Too Many Requests' for url ...`）
—— **用 httpx 的实现细节当判据**，它一改写法就静默失效（`total_429` 永远 0，
而没有任何报错）。

修法：判据**优先用结构化 HTTP 状态码**（新增 `LLMGatewayError.http_status`，
由 `providers._gateway_error` 从 `exc.response.status_code` 提取），
文案只作兜底。状态码是协议层的，不会因为文案改版而变。

**P5 状态文件跨实例污染。** 路径写死 `data/run/free_tier_429.json`，
而 `data/run/` 是 **dev / pilot / 生产共用**目录 ⇒
**dev 里调试出的 3 次 429 会把线上同一跳锁 10 分钟**，且不报错。

修法：`resolve_state_path()` 三级优先
—— `MOSS_RATE_GUARD_PATH` > `LLM_AUDIT_DIR` 同级 > 兜底。
选 `LLM_AUDIT_DIR` 是因为 dev/pilot 的隔离**本来就在设它**（少一个 key 就少一处漏改）。

### 可观测面（运维要能看见）

- `GET /api/v1/health` → `model_gateway.rate_limit_guard`
  （含每模型的 `locked` / `remaining_s` / `total_429`）；
- 运行指标面板「免费档限流」一行，**四态可分**：
  `未上报` / `未量到` / `无记录` / `已锁定，还剩 9 分 12 秒`。

**为什么"未量到"必须单独一档**：读不到状态文件时若显示"0 次限流"，
那是**假绿** —— 运维会以为没限流。判据区分「没量到」与「量到 0」。

### 护栏

- 后端：`test_health_rate_limit_guard_contract.py` 打**真实响应体**钉字段名与类型
  （字段改名 / `available` 丢失 / `models` 被拍平**都不报错，只会显示错**）；
- 前端：`web/src/rateGuardView.ts` 纯函数 + `npm run check:rateguard` 穷举 17 条断言
  （组件在浏览器里、还要登录，它的文案口径**没人能断言**）。

## 4. P6 —— 语义缓存串答案（**最重要的未修项**）

### 症状

`tone_job` 落库后 **4/5 条摘要为空**，而模型每次都吐了合法 JSON。

### 定位过程（逐层二分，每步都是可复跑判据）

| 层 | 判据 | 结果 |
|---|---|---|
| 模型本身 | 直连 Ollama `/api/chat`，两条不同正文 | ✅ 输出各不相同 |
| 网关关缓存 | `gw.complete(..., use_cache=False)` | ✅ 输出各不相同 |
| 网关开缓存 | 同一对正文再跑一次 | ❌ **`cache_hit=True kind=semantic`，第 2 条起拿到第 1 条的答案** |
| `_ask_segment` 层 | 置 `gw._cache = None` 后同跑 5 条 | ✅ **5/5 摘要可落库、各条针对自己正文** |

### 根因（数字可复算）

语义相似度是拿**整个 prompt** 算的，而抽取 prompt 的固定骨架
（JSON schema + 指令 ≈ 700 字）占绝大部分：

| 两条**完全不同**的资讯 | 整 prompt 相似度 | **仅正文**相似度 | 阈值 0.85 |
|---|---|---|---|
| 光模块 vs 减持 | **0.9328** | 0.0393 | ★ 命中 |
| 光模块 vs 降准 | **0.9348** | 0.0535 | ★ 命中 |
| 减持 vs 降准 | **0.9371** | 0.0280 | ★ 命中 |

**即任意两条不同资讯的 prompt 都 ≈0.93 相似 → 必然复用第一条的答案。**

### 影响面（**与模型无关**）

同一模型、同一批文本：**关缓存三条各不相同，开缓存三条全同**。
⇒ **8B 时代同样存在，是长期潜伏，不是换 4B 引入的。**

`tone_job._ask_segment` 走的是默认缓存路径（未传 `use_cache=False`），
所以**任何两条不同资讯的抽取结果都可能互相串**（`codes`/`brokers`/`tone` 全体）。

### 为什么没修（诚实登记）

这是**缓存键口径**的缺陷，三条候选各有代价，需要单独裁定 + A/B：

1. 语义复用只在**正文**相近时发生（骨架不进相似度）→ 要改缓存接口；
2. 命中必须同时满足"整 prompt 相似"与"正文相似"→ 降低命中率；
3. 抽取类调用显式 `use_cache=False` → 降低命中率、成本上升。

## 5. P7 —— 一个被我自己搞错的归因（值得单独讲）

发现 P6 之前，我把"4 条空摘要"归因成 **"4B 惜字 → 摘要太短 → 撞
`summarize.validate_summary` 的 `no_number` 判据"**，并把它写进了 PRD。

**那个归因是错的。** 是用户追问"测试过质量吗"逼我去独立复核，
才发现：关掉缓存后 4B 的摘要 **5/5 全部可落库、中位 27 字（比 8B 的 20 字还长）**。

**教训**：

- 归因错一次就会**改错一个地方** —— 当时差点去改摘要 prompt（那会白改一遍）；
- **复核要用独立路径**：我当时的"证据"是同一批被缓存污染的调用，
  它当然会支持任何归因。

PRD 里保留了更正痕迹（`> 本条第 1 版把这件事归因成…已作废`）——
**变更史本身就是需求**，删掉它，下一个人会把错归因再提一遍。

## 6. P8 ~ P13 —— 工程与流程类问题

### P8 白名单是"空头支票"（假绿）

**症状**：`scripts/prd_sync_check.py` 写在 `.gitignore` 白名单里
（台账声称"加入发布白名单，这样换开发工具也生效"），**却从未 `git add`**。

**后果两层，第二层更贵**：

1. 克隆/CI 里文件不存在 → `AGENTS.md` 教的那条对账命令跑不了；
2. **CI 的对账门禁因此每次都静默跳过**（只打一行 `::warning::`）——
   门禁看起来接上了，**实际一次都没跑**。

**为什么原有三条判据全漏掉它**：它们报错的**前提**是
`_tracked(path) is False`（= "这个脚本不发布"）。而白名单里的文件恰恰是
"**打算发布但目前没入库**" —— 三条判据都把它当合法的未发布脚本放过。
**"政策上要发布"与"技术上已发布"之间的缝，就是这个假绿的来源。**

**修法**：新增**判据 4**（白名单 = 承诺，`git ls-files` = 事实，不一致就报红，
带非空自证），并**兑现三条承诺**（`prd_sync_check` / `preflight_check` / `affected_tests`
—— 三者都是 `AGENTS.md` 当**命令**教的）。

> 自证故事：正则漏了 `re.MULTILINE` → `findall` 返回空集 → 判据恒绿。
> 被我写在同一文件里的"解析出 0 条就报错"自证断言两分钟内抓住。

### P9 过期路标（死常量）

`llm_policy.py` 里 `LOCAL_MODEL = "qwen3:8b"` / `LOCAL_MODEL_SMALL = "qwen2.5:1.5b"`。
三个条件叠在一起才叫"过期路标"：

1. **死的**：AST 精确判定生产代码引用 **0** 次（只有测试函数名与文档提过）
   ⇒ 删除**不改任何行为**（这一点必须先查清才动手）；
2. **值也过期**：配置里真实登记的是带量化后缀的名字；
3. **地板已换代**：8B → 4B。

留着它的代价是**排障被带偏**：下一个人会去找一个不在路由链上的模型。

**护栏**：`test_local_model_single_source.py`（5 条），含
"`llm_policy` 不许再定义模型名常量"（用 **AST** 判 —— 注释里的历史记录不算违规）
与它的非空自证。

### P10 改了配置但对外实例没生效

**症状**：配置里 `local_medium = qwen3.5:4b`，而对外实例**仍在跑 8B**。

**根因**：`LLMGateway` 在**构造时**把 `configs/models.yaml` 读进内存，
之后**再也不重读**。而 pilot 是 22:06 启动、配置是 23:19 才改的。

**唯一证据**是审计里 `agent_id=intel_extract` 那几行的 `model=` 字段 ——
**配置解析显示 4B、进程实跑 8B，两边都不报错。**

**修法**：按 PID 重启（**绝不用 `manage.py stop`**），
并把纪律写进 `docs/OPS_GUIDE.md` §2.3b：判据是**审计里那一行 `model=`**，
不是"配置里写着什么"。

### P11 值守长期失效

**症状**：`pilot-watchdog.log` 每轮记「端口被其他程序占用（值守拒绝启动）」并 `exit 2`。

**根因**：`data/run/backend.pid` 指向**已不存在**的进程（12108），
而真实在跑的是另一个 PID ⇒ 值守按 pid 文件认领，认不到就**拒绝启动**
⇒ **对外实例长期处于无人值守状态**。

**修法**：重启后 pid 文件复位，值守恢复认领。
**这条对"20~30 秒消失"那类现象有直接价值：先查 pid 文件指向谁** ——
它比"进程真的被杀了"常见得多。

### P12 600 字会不会超上下文（用户提问，实测）

| 输入 | prompt 长度 | 实测 `prompt_eval_count` |
|---|---|---|
| 纯骨架（schema + 指令） | 779 字符 | **404 token** |
| 300 字正文 | 1082 字符 | **603 token** |
| **600 字正文（生产单段上限）** | 1379 字符 | **795 token**（3 次一致） |

⇒ 600 字只占 `num_ctx=4096` 的 **19%**。而且**生产路径根本到不了上限**：
`segment_text` 的 `MAX_TEXT_CHARS=600` 切段 + `build_prompt` 的 `[:600]` 兜底
是两道硬闸。

**但顺着这个问题查出了一个真缺陷**：把正文一路加长（绕过兜底）后，

| 提交的正文 | prompt | 实际处理 | done_reason |
|---|---|---|---|
| 6000 字 | 6761 字符 | 3027 | `length` |
| **12000 字** | 12761 字符 | **2050 ← 封顶** | `length` |
| **20000 字** | 20761 字符 | **2050 ← 封顶** | `length` |

**Ollama 不报错**，只处理"装得下的那部分"，把实际处理的 token 数放进
`prompt_eval_count` —— 而**生产链路上原先没有任何地方读这个字段**。

**修法（只加观测，不改行为）**：`_warn_if_prompt_truncated` ——
`prompt_eval_count < 0.3 × 字符数` 时打 WARNING。取 0.3 因为实测中文密度 0.64。
**只告警不重试**（这一层不替调用方决定"截断了要不要重试"）；
当前 600 字上限**永不触发**它 —— 它是给"将来有人放宽上限"准备的安全网。

> ⚠️ 封顶值**不是常量**：换 `num_ctx=16384` 的临时模型后是 **8194~9152**
> ⇒ 不能当成固定数字写死判据。

### P13 一条长期红灯的老测试

`test_medium_force_local_env_restores_old_behavior` 一直是红的
（用 HEAD 版 `providers.py` 复跑确认：**改之前就是红的**）。两个原因叠加：

1. 它只注册 `{ollama, deepseek}`，而 `medium` 链现在有 4 跳
   （dashscope/siliconflow 未注册）→ 报 `提供商未注册` → 与断言的消息对不上；
2. 更要紧的：`pin_local` 里现在有**显存可行性检查**，
   本地拉不起来时会**故意**摘掉本地、改走云端备源 —— 于是
   "强制本地 ⇒ 零云端"这条不变量**已不再成立**（这是刻意行为）。

**修法**：按真实语义**拆成两条**，而不是放宽断言 ——
① 钉住显存可用 → 验"强制本地"这条回退路；② 钉住显存不可用 →
验"改道云端 + 出声（`vram_reroute` 审计）"。

## 8. 跨仓库改动：`medscholar-agent` 换模型的三层验证

改的不是本仓库，但**证据**必须留（详见那个仓库的
`docs/MODEL_SWAP_TEST_20260929.md`）。

| 层 | 判据 | `qwen3.5:4b` | `qwen3:8b` |
|---|---|---|---|
| ① 写作基准（3 轮） | 稳态 tok/s · 引用问题 | **70.5~71.1** · 0 | 47.0~47.2 · 0 |
| ② 端到端（1 轮） | 墙钟 / 产物 / 引用校验 | **199s** / **12,141 字** / 19 篇合法 | 311.8s / 9,512 字 / 11 篇合法 |
| ③ claim-level 忠实度（1 轮） | 覆盖率 / `unverifiable` | **53%** / **7** | 36% / **0** |

**读法（关键，否则会被当成"谁更好"）**：

- `unverifiable` = 「跨语言引用且**连数字/缩写都对不上**」= **格式可核查性**的代理指标
  ⇒ 8B=0、4B=7，是 4B **唯一可观测的劣势**（它写进的缩写与数字更少）；
- 两边都有 `contradicted`（6/5），落在该评测 Tier 0 的**已知盲区**上
  （中文综述引英文文献），**不能归因于模型**；
- **裁判就是被评模型本身** ⇒ **这一层分不出胜负**。

**结论**：4B 在工程与写作层面未掉质量；若以"引用可自动核验"为硬指标，
优先级应是**换嵌入模型 `bge-m3` + 换更强的 Tier 1 裁判**，而不是回退 8B。
