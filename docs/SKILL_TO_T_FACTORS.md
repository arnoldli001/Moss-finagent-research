# 交易技能库 → 做T决策因子 映射表

> 本文回答一个问题：**「今天产出的那批交易 skill，到底哪一条变成了代码里的哪一项打分？」**
>
> 结论先行：12 个 skill 里，**4 个技能落成了分时做T的新加权因子**（缠论结构 / 筹码量能结构 /
> 市场情绪周期 / 股性适配，合计 29 分权重），**1 个技能落成了日线做T的七因子加权总分**，
> 其余技能要么并入已有因子、要么只作为**纪律清单**展示而**刻意不进打分**。
>
> 最后一条是刻意的：心态、盘感、目视盘口这些无法用日线/分时数据验证的东西，
> 硬塞进权重只会让总分看起来更"丰富"、实际更不可靠。它们在面板上以文字纪律出现，
> 不参与任何乘加。

代码位置：`src/intraday/{chan,character,market_cycle,daily_score,factors,features}.py` +
`src/intraday/weight_profiles.py`（因子目录与权重模板的唯一事实来源）。

## 二、新增四因子（分时做T）的完整口径

分时权重配平（合计 100，硬校验）：

```
原十因子 × 0.71 → box17 / vwap11 / boll8 / macd6 / kdj_rsi6 / sentiment6 / news3
                  / index_volume6 / board_rank4 / overseas4      = 71
技能库四因子                                              = 29
  chan 12 | chip 8 | cycle 6 | character 3
```

> 想完全回到改动前的口径：前端权重编辑器一键切 **`legacy`** 模板
> （四因子置 0，其余恢复 24/16/12/8/8/8/4/8/6/6）。这是刻意留的回退路径。

### 1. `chan` 缠论结构（权重 12）

**出处**：`chanlun-trading` skill（缠中说禅《教你炒股票108课》）+
`D:\code\chanlun-quant` 那套已验证过的实现。

**公式**（`factors.chan_score_from`）：

```
位置分：p = (现价 − zd) / (zg − zd)         zd/zg = 最后一个「笔中枢」的下沿/上沿
  p ≤ 0（中枢下方）→  +clip(−p / overshoot)      超跌，等一买
  p ≥ 1（中枢上方）→  −clip((p−1) / overshoot)   透支，防卖飞
  0<p<1（中枢内） →  −clip((p−0.5)×2) × 0.6     轻微均值回归
背驰分：底背驰 +strength / 顶背驰 −strength
总分 = (1−w)×位置分 + w×背驰分                w = divergence_weight = 0.5
```

**关键设计**：

- `overshoot=0.5` 让**离开中枢足够远后位置分饱和**。没有这个上限，一只连续拉升的强势股
  会被算成 p=8、"极端超买"，但那不是超买、是趋势 —— 饱和后由背驰项决定要不要反手。
- 位置与背驰方向冲突时（顶背驰却在中枢下方）**两项互相抵消**，
  面板会显式标注「位置与背驰方向矛盾，把握度下降」。这是"信号矛盾时降低把握"的期望行为，
  比强行裁决成某一侧更诚实。
- **中枢用日线算，不用分时**：日线中枢才是"这只票当前的结构位置"，一天只生长 0~1 个；
  分时中枢一天要长好几个，拿它当支撑压力会到处报警。

**实现与已知妥协**（见 `src/intraday/chan.py` 的诚实标注）：

- 保留"**严格包含**"（仅 `h1>h2 且 l1<l2`、或高低点完全重合才算包含；`h1==h2 但 l1≠l2`
  不算）与"分型**向前扫描取第一个**"两条修正 —— 这两处是参考实现里踩过坑改出来的。
- **不做线段**（未移植特征序列算法）：中枢由笔构造，没有级别递归、九段升级、
  三类买卖点分类。
- 平顶/平底不产生分型（严格包含的直接后果），比宽松实现保守。

### 2. `chip` 筹码量能结构（权重 8）

**出处**：`盘口与筹码` + `低吸买入技巧`（承接力/量能确认）+ `集合竞价选股`（量比口径）。

**公式**（`factors.chip_score_from`）：

```
方向 = clip((0.5 − position) × 2)           position = 现价在**当日分时区间**中的位置
强度 = clip((量比 − 1) / scale)             量比 = 今日预测量能 / 近5日均量
score = 方向 × (0.5 + 0.5×强度)
换手率 < 1% → score × 0.7（只打折，不反转）
```

**关键设计**：**量能只放大方向，不单独给方向**。
放量本身既可能是吸筹也可能是派发，位置才决定它是哪一种：

| 情形 | 方向 | 幅度 | 得分 | 语义 |
|------|-----:|-----:|-----:|------|
| 低位倍量 | +0.8 | ×1.00 | +0.80 | 吸筹/承接，低吸最有利 |
| 高位倍量 | −0.8 | ×1.00 | −0.80 | 派发/出货，该高抛 |
| 低位平量 | +0.8 | ×0.50 | +0.40 | 位置偏多但缺量能确认 |
| 高位缩量 | −0.8 | ×0.25 | −0.20 | 无量滞涨，方向保留、强度衰减 |
| 任意极度缩量 | — | ×0 | 0 | 没有量能信息 → 中性 |

**未量化（诚实标注）**：**委比、内外盘、买五/卖五承接**在当前数据链路里**取不到** ——
`Quote` 模型没有档位字段，QMT 与腾讯两处解析都在解析层把五档丢掉了
（`fetch_quote` 的 detail 写着"QMT快照（五档盘口）"，但 `Quote` 里没有这一项）。
所以本因子只用**从数据里真能算出来的**量价筹码，不用"看起来更专业"的编造字段。

### 3. `cycle` 市场情绪周期（权重 6）

**出处**：`市场情绪周期` skill（含全部阈值）+ `短线交易体系`（四阶段）。

**数据**：东方财富涨停池 / 炸板池 / 跌停池 / 强势股池，经 akshare 取（实测单次 0.1~0.2 秒，
四池合计 < 1 秒），按 `date` + TTL(60s) 缓存。

**算出来的量**：涨停家数、首板/连板家数、最高连板高度、炸板家数与**炸板率**、
跌停家数、**大面家数**（跌停 + 炸板中跌幅 ≤ −9%）、晋级占比。

**阶段判定**（`market_cycle.classify_stage`，阈值全部来自 skill 原文）：

| 阈值 | 值 | 出处口径 |
|------|---:|---------|
| 活跃 | 涨停 ≥ 30 家 | 「涨停家数 ≥30 → 市场活跃」 |
| 高潮 | 涨停 ≥ 60 家 | 主升/高潮特征 |
| 冰点特征 | 涨停 < 15 家 | 「涨停 <15」 |
| 退潮特征 | 炸板率 > 60% | 「炸板率 >60%」 |
| 承接健康 | 炸板率 < 30% | 主升期必要条件 |
| 有身位 | 最高连板 ≥ 5 | 主升/高位震荡 |
| 冰点 | 高度 ≤ 2 板 **且** 连板家数 < 4 | 「高度≤2板 & 连板<4家」 |
| 一票否决 | 大面 ≥ 10 家 / 跌停 > 10 家 | 「大面≥10家 / 跌停>10家」 |

**判定顺序刻意是「风险优先」**：先看一票否决与退潮，再看冰点，最后才认主升。
退潮期的尾巴常常仍有 50+ 家涨停（补涨股在动），若按涨停家数先判成"发酵期"，
会把最危险的阶段认成最安全的阶段。

**温度 → 分数的映射是分段线性**（以中性温度 50 为原点）：

```
温度 100 → +1      温度 50 → 0      温度 0 → −1
[50,100] 与 [0,50] 各自满量程
```

分段而不是单条 `(T−50)/50`：后者会让高温区间永远够不到 +1，主升期的机会被系统性低估。

**闸门与打分的关系（刻意分离）**：

- `cycle` **因子分**只表达"今天做T环境好不好"；
- **退潮/冰点/一票否决**另走 `t_allowed` 闸门，面板红字提示并禁止低吸做T。

**一处刻意的非对称解读**（必须说清）：skill 原文是「退潮期禁止做T降本」，
本实现的闸门**只禁低吸方向（先买后卖），不禁高抛减仓方向**。
理由：退潮期的正确动作就是减仓，"禁止做T"不应被读成"禁止卖出"。
这条是**实现者的解读而非原文直述**，若要一律禁止可改 `factors.cycle.veto_signals` 的语义。

### 4. `character` 股性适配（权重 3，分时）

**出处**：多份资料反复出现的"个股脾气"，也是项目原本用 `CodeOverride` 手工填参数想解决的问题。

**公式**（`character.character_score_from`）：

```
ratio = dev_pct / (atr_pct × scale)     dev_pct = 现价相对 VWAP 偏离%
                                         atr_pct = 该股日 ATR20 占价%
score = −clip(ratio) × (0.5 + 0.5 × 震荡性)
震荡性 = 1 − trend_efficiency
```

**关键设计**：与 `vwap` 因子**互补而非重复**。
`vwap` 问"今天偏了几个**当日**标准差"（早盘样本少会失真），
`character` 问"偏了几个**这只票的日常波动**"（跨日跨票稳定）。

**这一支同时驱动权重推荐**（见 `/api/v1/intraday/character`）：股性画像产出
`atr_pct / 平均振幅 / 量能活跃度 / 趋势效率 / 涨停基因 / 跳空频率`，
据此选模板（`swing` / `trend` / `dragon` / `low_vol` / `balanced`）并按股性做乘数微调
（如震荡票 `box×1.15`、趋势票 `chan×1.25`），最后归一化到 100。

**股性也决定档位**（`levels`）：

```
min_band_pct  = clamp(atr_pct × 0.45, 1.0, 6.0)     必须大于双边成本约 0.2%，且跟着真实波动走
stop_loss_pct = clamp(atr_pct × 0.55, 0.8, 5.0)
max_band_pct  = clamp(atr_pct × 3.0, 3.0, 20.0)
atr_stop_mult = 0.4（钝化）/ 0.6（其余）
```

理由（实测踩过的）：300308 日线 ATR 占价 5.8%，默认 1% 止损只有 9 元，任何噪声都能打穿；
600036 招行 ATR 只占 1.7%，档位差给到 3% 则一年也等不到一次。

**做T友好度 `t_friendly`（0~100）的构成**：空间 35 + 回归性 30 + 活跃度 20 + 涨停基因 15。
权重来源是"做T这件事本身要什么"，不是拟合出来的。

## 三、日线做T 七因子加权总分

**与规则信号（B1-B15 / S1-S6）是并列关系，不是替代**：

- 规则信号回答"**满不满足某套战法的形态**"，可解释到每一条条件（布尔）；
- 加权总分回答"**综合来看现在偏向低吸还是高抛**"，能容纳"条件只满足一半"。

**刻意不把加权总分接回 `_finish` 的 `triggered` 判定** —— 那会让"三条里满足两条"
也发正式信号，而项目里已有回归测试专门钉住"缺 required 条件不得静默触发"这条底线。

| 因子 | 权重 | 计算 | 技能出处 |
|------|-----:|------|---------|
| `trend` 趋势结构 | 20 | 四条均线相对位置（price/MA5、MA5/MA10、MA10/MA60、price/MA120）四个分量等权 | `短线交易体系`、趋势战法 |
| `chan_daily` 缠论买卖点 | 18 | 日线笔中枢位置 + 背驰（与分时同一支 `chan_score_from`） | `chanlun-trading` |
| `volume` 量价结构 | 16 | 活动量柱状态（有效支撑/待观察/已破位）+ 量价形态方向 + 缩量/大阴扣分 | `盘口与筹码`、量柱体系 |
| `position` 位置与身位 | 14 | 近120日分位（越低越偏多）+ **连板高度惩罚** + 贴近高点折价 | `打板技巧`、`连板股选龙头` |
| `signal_rule` 规则信号质量 | 12 | 已触发的 B/S 条数与满足度（只算 `triggered=True`，3 条满仓） | `daily_signals.py` 规则体系 |
| `cycle` 市场情绪周期 | 10 | 与分时同一个温度函数 | `市场情绪周期` |
| `character` 股性适配 | 10 | `clip((t_friendly−50)/50)`，趋势票再 −0.2 | 股性资料 |

**阈值比比时更粗**：日线 ±15/±25（分时是 ±20/±30）。一天只有一根bar，
过度敏感会让用户天天改主意。

`position` 里的**连板惩罚是非线性的**：`streak≥3 → 0.15×min(4, streak−2)`。
原因：分位本身在连板股上会一直贴着 1.0，区分不出"3板"与"7板"，
而连板越多做T的赔率越差（一次 T 反就是 −10% 量级）。

## 四、只做清单、不进打分的部分（诚实标注）

以下内容来自技能库，但**没有任何一条进入权重**，只作为面板纪律/缺口提示：

| 内容 | 出处 | 为什么不进打分 |
|------|------|--------------|
| 心态、纪律、"为了做T而做T" | `短线交易体系`、`盘口与筹码` | 无法从行情数据验证；写进权重等于把主观感受伪装成量化 |
| 目视盘口（大压单/托单/撤单） | `盘口与筹码` | 需要逐笔委托与撤单数据，当前链路只有成交价量 |
| 委比 / 内外盘 / 五档承接 | `盘口与筹码`、`低吸买入技巧` | `Quote` 没有档位字段，解析层已丢弃（见上文） |
| 生态定位、周期参悟 | `短线交易体系` | 依赖对市场整体的主观判断，不同人标注结果不一致 |
| 复盘模板、问句清单 | `复盘方法` | 作用是"提醒你别漏看"，不是"给个分数" |
| 龙头卡位（谁是龙头） | `热点龙头捕捉`、`连板股选龙头` | 需要全市场连板梯队与题材归属，当前只有单票与关联板块数据 |
| 一字板 / 20CM 首板等特殊形态 | `打板技巧` | 需要更细的盘口与封单数据；已在日线 `volume` 因子中部分体现 |

## 五、技能原文与实现的冲突（不隐瞒）

| 冲突点 | 技能原文 | 本实现 | 处理方式 |
|--------|---------|--------|---------|
| 退潮期做T | 「禁止做T降本」 | 禁止**低吸**方向，保留高抛减仓 | 见上文 §二.3 的解读说明 |
| 参与板数 | 「最起码做三板的」 vs 另一处「首板/2板可参与」 | 未在因子中体现具体板数门槛，只用连板高度做身位惩罚 | 阈值互斥，不硬编码 |
| 龙回头幅度 | 35% vs 40% | 未量化 | 两处原文冲突 |
| 竞价量 | 2 倍 vs 2/3 | 未量化 | 同上 |
| 量比形态 | 「>10 见顶」（倒U型） | `chip` 用线性放大 | 线性近似，倒U型无法用单因子表达 |
| 流通市值 | 60亿 vs 100亿 | 未量化 | 日线链路无市值列（`DailyParams.limit_cap_yi` 目前空转） |

## 七、已知局限（不隐瞒）

1. **中枢用笔不用线段**，级别递归与三类买卖点未实现（见 `chan.py` 的诚实标注）。
2. **股性画像依赖日线样本 ≥ 60 根**，次新股会直接记缺口、不给推荐权重。
3. **情绪周期依赖 akshare 的东财池接口**，接口变动/网络不可用时该维度按"不可用"扣除有效权重，
   **不会用上一次的旧值** —— 周期阶段错一天会导致"退潮期被当成震荡期"这种会造成实际亏损的误判。
