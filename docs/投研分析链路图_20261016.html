二、LLM 网关（唯一出口）：六个机制

① 取消检查

调前拦断，避免浪费
取消令牌逐跳检查

② 保头保尾截断

7:3 保头尾（防切断 schema）
超长 prompt 不丢尾部契约

③ 三级缓存 + 判定 本版重写

精确哈希 → 语义召回 → 判定
详见下一节

④ token 预算

按 trace 累计，超额拒绝
超限是"拒绝"不是"截断"

⑤ 降级链

熔断按 provider × 租户分别记
同 provider 的"备"不算备

⑥ 哈希审计

prompt/response 哈希
每次调用可回放、可比对

三、③ 的展开：三级缓存 —— 拦截发生在哪一层，决定它有多便宜

L1 精确命中

SHA256(system+prompt+scope)，进程内索引（≤20000 条）

命中 p50 19.7 µs、0 次网络
贵的一跳（embedding/rerank）一次都不发

L2 语义召回

BAAI/bge-m3 余弦 top-K（K=12）
判定阈值 0.85（默认）/ 0.80（embedding 侧）

桶内没有向量时退化 3-gram（同形不同义的安全网）
"换个说法该复用"由这一层负责

L3 判定（重排）

BAAI/bge-reranker-v2-m3 对 K 条原文打分
阈值 0.95，top-k 12

★ 只在 anchor 模式跑；prompt 模式 0 网络
逐字引用类输出（引文/证据）禁语义复用

L4 回源（LLM）

真调模型，然后按 (agent_id, scope, anchor|prompt) 入桶

scope 带数据指纹 d=<16hex> ⇒ 数据一变，L1/L2/L3 整条路径一起失效

护栏 / 观测量实测值（2026-10）它防的是什么
判定侧熔断（embed / rerank 各自一份） 3 次失败 → OPEN，窗口 600 s，冷却 60 s 判定服务挂了却"每次都等满超时"：实测黑洞单次查找 4.5 s（embed 1.5 + rerank 3.0）→ 熔断后第 4 次查找 1 ms
L1 miss 的代价（K=12）约 376 ms（含 embed + rerank） "两级缓存"到"三级"不是白拿的：贵是有价的，所以必须能被看见
复用率 / 命中年龄分桶 桶：<1min · 1-10min · 10min-1h · 1-6h · 6-24h · 1-3d · 3-7d · >7d 只报"命中率"会把"召回多少"与"真拦下多少"混成一个数； 独立拦复用的判定次数：2 → 3 才是这一版的意义
no_traffic 与"L1 全命中"分开报 prompt 模式只有语义层查找、无判定 ⇒ 如实报"无判定流量" 把"没量到"报成"命中率 100%"是本项目最反对的假绿

四、模型池：唯一出口的另一端（configs/models.yaml 为唯一事实源）

本地小模型（Ollama）

qwen2.5:1.5b · qwen3.5:4b · deepseek-r1:7b

零配额、唯一可持续的底板；8 GB 单槽
实测 44.1 tok/s · 只常驻 4B + 1.5B

免费云 A（总量额度）

qwen-flash（阿里云百炼）

额度有限 ⇒ 必须监控跑道
实测跑道 6.4 天 → 23.9 天（限走高频层后）

免费云 B（速率限制）

Qwen/Qwen2.5-7B-Instruct（硅基流动） · glm-4.7-flash

可再生 ⇒ 会 429 ⇒ 需限流熔断
连续 3 次 429 → 锁该跳 10 分钟

付费云（兜底）

deepseek-flash · deepseek-v4-*

按 token 计 ⇒ 要能被钱验证
日成本上限 + 预扣结算

降级方向：本地 → 免费云 → 付费云；"成功但极慢"也会前进到下一跳（单跳墙钟预算）， 但链上最后一跳不设墙钟——给它设预算只会把"慢但正确"变成"必然失败"。
